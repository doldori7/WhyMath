# /review — 다각도 리뷰

## 임무
*기술·교수학·비용·안전*의 4개 축에서 변경사항을 검증한다.

## 실행 절차

### 1. 리뷰 대상 식별
- `$ARGUMENTS` 있으면: 해당 파일·디렉터리·PR
- 없으면: `git diff HEAD~1` 또는 마지막 커밋 이후 변경

### 2. 4축 리뷰

#### 축 1: 기술적 정확성
- [ ] 컴파일·실행 가능
- [ ] 테스트 통과·커버리지 충족
- [ ] 타입 안전성
- [ ] 에러 처리
- [ ] 동시성·경쟁 조건
- [ ] 성능 (N+1 쿼리·메모리 누수)
- [ ] 의존성 추가 정당화

#### 축 2: 교수학적 정확성 (LLM·콘텐츠 변경 시)
- [ ] Polya 4단계 원칙 준수
- [ ] 답 미루기 메커니즘 작동
- [ ] 소크라테스 질문 품질
- [ ] 오개념 진단 정확성
- [ ] 학습자 수준 적응성
- [ ] 메타인지 코칭 요소 포함
- [ ] *답을 너무 빨리 주지 않는가?* (가장 자주 위반되는 항목)

#### 축 3: 비용·효율
- [ ] LLM 호출이 로컬로 가능한가? (Phaiakes9 우선)
- [ ] 캐싱 적용 가능한가?
- [ ] 배치 처리 가능한가?
- [ ] 응답 지연 (p50 < 2s) 추정
- [ ] 학생당 월 LLM 비용 추정 (목표: < 1,000원)

#### 축 4: 안전·윤리
- [ ] CLAUDE.md 금기 위반 없는가?
- [ ] 미성년자 데이터 보호 (암호화·익명화)
- [ ] 저작권 안전선 준수 (검정교과서 본문 X, 학원 콘텐츠 X)
- [ ] 동의 절차 (14세 미만 부모 동의)
- [ ] 정서적 안전 (부정적 강화 표현 없는가)
- [ ] 환각 위험 (검증되지 않은 답변 제공 위험)

### 3. 결과 보고

```
🔍 리뷰 결과: [대상]

[축 1: 기술] ✅ 8/8 통과
[축 2: 교수학] ⚠️ 1건 검토 필요
   - L4 프롬프트가 *답을 1단계에서 바로* 제공함
   - 권장: Polya 2~3단계 거치도록 수정

[축 3: 비용] ✅ 통과
   - 추정 학생당 월 800원

[축 4: 안전] ✅ 통과

전체 평가: ⚠️ 1건 수정 후 머지 가능

다음 단계:
> [구체적 권장 액션]
```

### 4. MEMORY.md 갱신 검토
다음 경우 결정 로그 추가 권장:
- 새로운 패턴 도입
- 기존 방식 변경
- 폐기된 접근 추가

## 원칙

### 비판은 구체적으로
- "코드가 별로다" ❌
- "L4 프롬프트가 학생 응답 검증 없이 진행, 시나리오 X에서 환각 위험" ✅

### 통과 기준은 4축 모두
- 한 축 미달이면 미통과
- 특히 *교수학·안전*은 가장 자주 간과

### 자동화 우선
- 린터·타입체크는 도구로
- 사람 리뷰는 *판단이 필요한 영역*에 집중

## 호출 예시

```
> /review                    # 최근 변경
> /review src/prompts/polya  # 특정 디렉터리
> /review PR #42             # PR
```
