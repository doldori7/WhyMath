## 1. 폐기된 수치 2건

| 시점 | 백엔드 | `qwen3.5:27b` 기록값 | 출처 |
|---|---|---|---|
| 2026-05-16 | Windows Ollama 0.24.0 + DirectML | 9.22 tok/s · p50 13,886ms | MEMORY 2026-05-16 · `03a_l3_router_design.md` §A.1 |
| 2026-08-14 | Windows 11 + Ollama + ROCm | 0.5~1 tok/s · 115~300s/call | MEMORY 2026-08-14 · `OPS-43` notes |

**둘 다 판정 근거로 쓸 수 없다.**

### 1.1 왜 폐기하는가 — 환경 사실 (Kiki 구두 보고, 2026-08-21)

| 사실 | 성능 해석에 미치는 영향 |
|---|---|
| **CMOS `auto`** (2026-08-21 아침~) | VGM·전력 프로파일이 기본값 — 두 측정 시점의 설정은 알 수 없다 |
| **이전 구간 냉각 부족 → 성능 하락** | 그 구간 측정치가 **하향 편향**. 편향 크기 미상 |
| **현재 냉각 평균 수준** (증대 예정) | 지금 재도 최종 상태가 아니다 |
| 외부 AI 평가도 기존 테스트에 낙제점 | 독립 출처가 같은 방향 지적 (평가 본문 미확보) |

> 이 표는 계측기 출력이 아니라 **소유자 보고**다. CLAUDE.md "환경 사실의 추론 등재 금지"에 따라
> 그렇게 표기하고, **기존 수치를 무효화하는 근거로만** 쓴다 — 새 수치를 세우는 데는 쓰지 않는다.

### 1.2 함께 회수하는 파생 주장

| 주장 | 판정 |
|---|---|
| "9.22 → 0.5~1 = **9~18배 회귀**" | 🔴 **회수** — 두 끝점 모두 조건 미기록이라 회귀 폭이 스택 탓인지 열 탓인지 분리 불가 |
| "현 스택은 **고장 나 있다**" | 🔴 **회수** — "원인 미상, 스택·열 어느 쪽도 배제 못 함"이 정확하다 |
| MEMORY 2026-08-14 "스택 문제로 **추정**" | ✅ 원문은 처음부터 "추정"이었다 — **이를 단정으로 옮겨 적은 것이 오류**였고 여기서 정정한다 |

> **주의**: 폐기는 "느리지 않다"는 뜻이 **아니다**. `docs/ops/amd395_local_llm_performance.md` §2가 보이듯
> **27B dense가 8~11 t/s인 것은 고장이 아니라 물리 한계**다. 폐기되는 것은 *두 수치의 비교*이지
> 대역폭 천장 자체가 아니다 — 천장은 계산이라 냉각과 무관하게 유효하다.

### 1.3 근본 원인 — 측정 프로토콜 결함 (상환 완료)

`bench_latency.py`의 `detect_machine()`은 `platform`·`python_version`·`machine` **3개만** 기록했고,
호출 계측은 `eval_count` 하나만 읽었다. 즉 **"열이냐 스택이냐"도 "비교해도 되느냐"도 구조적으로 판정 불가**였다.

- `OPS-45` — 프리필/생성 분리 (`prompt_eval_*`/`eval_*`)
- `OPS-46` — 환경 기록 + `environment_comparable()` 기계 판정 + `ENV_SCHEMA_VERSION`

둘 다 **done**. 이제 위 두 결과 파일처럼 `environment` 필드가 없는 과거 JSON은
`environment_comparable == false`로 **기계가 판정**한다 — 같은 오인이 반복되지 않는다.

## 2. 역할 분담 (2026-08-21 확정)

`#848`과 `#849`가 같은 문제를 병렬로 다뤘다. 중복을 없애고 아래로 정리한다.

| | 정본 | 성격 |
|---|---|---|
| **Kiki 머신 측정·튜닝** | `docs/ops/amd395_local_llm_performance.md` + `scripts/ops/*.ps1` (#849) | Windows 네이티브. 전용 VRAM 실바이트·전원 계획·드라이버·서버 로그까지 수집 — Python으로는 못 읽는 것들 |
| **CI 계약·회귀 방지** | `infra/phaiakes9/benchmark/bench_latency.py` + `tests/infra/test_bench_environment_capture.py` (#848) | Linux/CI에서 상시 실행. 계측 계약 15건 동결 + 저장된 결과의 **비교가능성 기계 판정** |
| **폐기 수치 기록** | 이 문서 | 위 §1 |

**설정값이 충돌하면 `#849` 문서가 이긴다.** (예: `OLLAMA_KV_CACHE_TYPE=q8_0`은 #849가
"품질 영향 있어 기본 권장 안 함"으로 판단했다 — 이 문서의 초판 권고는 철회한다.)

## 3. 미결 사항

- **신뢰할 수 있는 성능 기준선이 0건이다.** 계측 *코드*가 준비됐을 뿐 아직 아무것도 측정하지 않았다.
- **측정은 냉각 증설 완료 후** — 부족한 냉각 상태에서 TDP를 올리면 스로틀이 악화된다(#849 L2와 함께 읽을 것).
- **회귀의 실재 여부·원인 미확정** — 절차는 `#849` §4 Phase 0~6.
- **GPU 온도는 Windows stdlib으로 획득 불가** — `bench_latency.py`는 `UNSUPPORTED`로 정직 표기하고
  `--cooling` 수기 + `--thermal-drift-probe`(행동 프록시)로 대체한다. **온도 측정이 아니다.**
  실제 하드웨어 증거는 `collect_gpu_evidence.ps1`이 정본.
