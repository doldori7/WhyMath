## 1. 비전 정의

### Education Knowledge Fabric (교육 지식 패브릭)
과목별 지식 팩(성취기준·원자/개념·오개념·프롬프트·검증축의 5종 데이터 팩)이
**교차 과목 개념 연결로 짜인 단일 직물**. 과목은 실(가닥)이고, 교차 과목 개념 점화
(물리 '순간속도' → 수학 '미분계수')가 씨실이다. 실이 아무리 많아도 씨실이 없으면
직물이 아니라 실 더미다 — **fabric의 가치는 과목 수가 아니라 교차 연결 밀도에서 나온다**
(E축 정본 §3: "과목이 늘수록 가치가 커지는 유일한 축").

### Metadata Operating System (메타데이터 운영 기층)
성취기준 코드·개념 그래프·오개념 DB·검증 메타데이터가 콘텐츠 생성·클라이언트 렌더·
AI 튜터링을 **구동하는 운영 기층**. 이는 CLAUDE.md "표현 ≠ 의미" 원칙(문항·수식·해설은
화면 문자열이 아니라 구조로 저장, 렌더는 각 클라이언트가)의 장기 귀결이다 — 지금의
저작권 안전장치("구조 메타데이터만 인용")가 그대로 제품의 본체가 된다.

> **용어 주의**: "OS"는 내부 지향 표현이다. 대외 정체성 선언의 시기 조건은 §4 참조.

## 2. 단계 지도 — 각 단계가 fabric에 기여하는 것

| 단계 | 내용 | fabric 기여 |
|---|---|---|
| **S0~S5** | 수학 완성 (초·중·고·대학 연결) | 첫 직물 가닥 + **기층 검증**: 개념 원자·오개념·검증축·과목 중립 불변식 4종이 실전에서 증명됨 |
| **E1~E3** | 과학 3부작 (물리→화학→생물) | **씨실 최초 실증**: 물리↔수학 교차 점화 실측 + 팩 한계비용 급감 곡선 확인 (E2 게이트: E1 대비 50% 이하) + 검증축 다변화 1차 (차원 일관성·화학량론·사실 인용 RAG) |
| **E4~E6** | 인문 확장 (역사·사회→국어→영어) | 검증축 다변화 2차 (사건 네트워크·루브릭 κ) — "수식 없는 과목"에서도 기층이 작동함을 증명 |
| **수렴** | fabric 수렴 (시기 미정 — 게이트 결정) | 교차 과목 연결 밀도가 임계 초과 → 단일 과목 앱이 흉내 낼 수 없는 해자 완성, 대외 정체성 전환 검토 (§4 시기 조건) |

**순서는 게이트가 결정하며 달력이 결정하지 않는다** (E축 불변 전제 승계). 특히
**"수학 완성(S5 게이트) 전 어떤 과목도 착수하지 않는다"** — 이 비전 문서는 확장을
서두르는 근거가 아니라, *왜 수학을 먼저 완성하는가*(기층 검증)의 근거다.

## 3. fabric 측정 지표 (정의만 — 수치 목표는 실측 후)

"측정 없는 도입 없음" 원칙에 따라 지표의 **정의**만 선언하고, 수치 목표는 E1 실측
후 확정한다 (FAB-02 fabric 감사 태스크가 추적):

1. **교차 과목 엣지 수** — subject Overlay가 다른 양 끝 노드를 잇는 `prerequisite` 엣지 수
2. **교차 점화 활용률** — 튜터링 retrieval에서 cross-subject 엣지가 실제 소비된 비율
3. **과목 팩 한계비용 곡선** — 6단계 플레이북 소요의 과목별 추이 (E1=100 기준선, E축 §4.1)

## 4. 기존 판정·불변식과의 관계 (무모순 선언)

이 문서는 아래를 **전부 승계하며 하나도 뒤집지 않는다**:

- **"OS 조기 정체성화 금물"** (`math_dsl_evolution.md` §2.3 — "제3자 확장 경계가 명세로
  고정돼야 하는데 현재는 내부 레지스트리 수준·범용 OS는 과대포장"): 유효하다.
  Metadata OS는 **내부 설계 지향**이며, 대외 "OS" 정체성 선언의 시기 조건 =
  **fabric 수렴 단계 진입 + 제3자 확장 경계 명세 고정** 이후. 그 전까지 대외 정체성은
  기존 전략 문서를 따른다.
- **E축 4대 불변 전제** (subject_expansion_e_axis_v1.md): 과목=5종 데이터 팩(코드 포크
  아님) · 순서=게이트 결정 · 수학 완성 선행 · 저작권 위험 순서(국어 ≫ 사회 > 과학 ≥ 수학).
- **구조 붕괴 방어** (CLAUDE.md 2대 철칙·8대 원칙): 교차 과목 연결도 **기존 `prerequisite`
  재사용, 관계 타입 신설 금지** (E축 §3). 과목 경계는 엣지 속성이 아니라 노드 Overlay
  subject에서 유도. fabric이 커져도 LLM에는 Minimal Reasoning Subgraph만.
- **"Subject enum ADD VALUE 금지"** (subject_pack_spec_v1.md §6): 런타임 Subject enum은
  수학 내 수능 선택과목 축 — fabric 확장은 `Problem.subject_area` 축으로.

## 5. 하네스 연결 — 이 비전이 backlog에 실리는 방식

| 비전 요소 | backlog 표현 |
|---|---|
| 수학 완성 선행 | `G-s5-subject-expansion` 게이트 (subject-expansion 트랙 하드락 — 기존) |
| 씨실(교차 점화) 실증 의무 | E1-03·E2~E6 팩 태스크 acceptance의 "교차 과목 prerequisite 엣지 실증" 항목 |
| fabric 수렴 추적 | `FAB-NN-fabric-audit` 반복 태스크 (E축 게이트 뒤·done 시 다음 회차 재생성 — ARCH 감사 패턴) |
| 지표 수치 확정 | E1 실측 완료 시 FAB 감사가 §3 지표에 수치 목표를 backlog add로 등록 |

이 문서 자체는 서사(왜)다. **"현재 무엇을 하는가"를 이 문서에서 읽지 말 것** — 그것은
`python3 scripts/harness/backlog.py status`가 답한다.
