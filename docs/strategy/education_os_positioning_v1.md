> 이 문서는 WhyMath의 콘텐츠·교수법 전략이 지향하는 **제품 북극성("Education OS")**을 명문화한다. **기존 판정·

## 1. 한 줄 북극성

> **"AI가 *생성*하는 앱이 아니라, AI가 *선택*하는 교육 콘텐츠 운영체제(Education Operating System)."**

WhyMath의 경쟁력은 "더 똑똑한 생성 모델"이 아니라 **교수법-중립 콘텐츠 자산 + 학습하는 교수법 policy**다. 콘텐츠는
한 번 생성하면 영구 자산이 되고, 교수법은 학생 상태에 맞춰 런타임에 선택되며, 그 선택은 시간이 지날수록 스스로 더
나아진다.

---

## 2. 3대 서사 기둥

### (a) 비용 해자 (단위경제)
매 질문마다 LLM이 생성하는 경쟁 구조는 학생 수에 비례해 비용이 폭증한다. 우리는 **한 번 생성 → 영구 자산 → 런타임
선택 + 렌더(검색 비용)**라 학생당 **한계비용이 0으로 수렴**한다. "학생당 월 LLM 비용 < 1,000 → 500원"은 마케팅
목표가 아니라 이 구조의 *귀결*이다(`03c §4`·`03:229`). 경쟁사가 모델을 아무리 키워도 *단위경제 자체*는 못 따라온다.

### (b) 개인화 역설 해소
캐시=몰개인화 / 실시간 생성=비용폭발 — 이 딜레마가 대부분의 AI 교육앱을 무너뜨린다. WhyMath는 **교수법-중립 DSL +
런타임 교수법 렌더**(이름·숫자·상황만 얹음)로 "거의 개인화된 수업"을 *검색 + 렌더* 비용에 제공해 역설을 깬다. 진짜
새 조합(오개념 다중 결합 등)만 생성하며 비용의 극히 일부다(`03c §3`).

### (c) 학습하는 해자 (Adaptive)
교수법이 고정 규칙이 아니라 **시간이 지날수록 시스템이 더 나은 교수법을 학습**한다(contextual bandit → RL·
`04d §3`). 각 교수법의 효과를 (학생군 × 개념 × 오개념 유형)별로 측정하고 policy를 갱신한다. **데이터가 쌓일수록
강해지는 policy = 복제 불가 해자**다. 이는 EKF(교차 과목 fabric·`knowledge_fabric_vision_v1.md`)와 결선된다 —
**fabric = 콘텐츠 축, Metadata OS = 운영 축, Adaptive = 자기개선 축.**

## 3. 경쟁 해자 대비

| 경쟁 유형 | 그들의 축 | Education OS의 축 |
|---|---|---|
| 콴다(사진 → 답) | 정답 검색 | 검증된 *교수법* 선택(왜·어떻게) |
| EBSi(영상) | 강의 소비 | 상태-적응 렌더 |
| 실시간 LLM 튜터 | 매번 생성(비용·환각) | 중립 자산 렌더(0원·SymPy 검증) + 학습하는 policy |

우리만 **"교수법-중립 검증 콘텐츠 자산 + 그것을 고르고 스스로 개선하는 선택 엔진"**을 갖는다. 이는 "우리가 만들지
않는 것"(단순 사진→답·강의 영상·객관식 양산·무자비한 게임화, `CLAUDE.md`)과 정확히 반대편에 선다.

## 4. 북극성 → 현재 경로 (게이트가 결정·달력 아님)

1. **S3/S4 (수학)**: 교수법-중립 DSL·Rendering Engine·규칙기반 Runtime Selector를 실증(선택률·검증통과율·학생당
   비용 실측). — `REND-01`·`PED-02`·`CACHE-01`.
2. **policy 학습**: 효과 측정 데이터 축적 후 Adaptive Engine 승격(측정 게이트·강등전). — `PED-03`.
3. **E축 확장**: 과목이 늘수록 콘텐츠 자산이 복리로 쌓이고 팩 한계비용이 급감(EKF §3 "과목 팩 한계비용 곡선"과
   동일 지표를 공유).
4. **fabric 수렴**: 교차 과목 연결 밀도가 임계 초과 → 대외 EOS 정체성 전환 *검토*(§5 조건).

## 5. 무모순 정합 (기존 판정과의 관계)

**북극성 채택 ✓ / 대외 정체성 *선언*은 유예 유지.** 이 둘은 충돌하지 않는다:

- `math_dsl_evolution.md` 판정은 "**제품화 표면(권장 3순위)**"으로서의 학습 OS 서사를 *허용*했고, "**조기 정체성화
  금물**"은 *대외 정체성 선언*만 게이트했다. 본 문서는 전자(제품 북극성)를 채택하고 후자(정체성 선언 유예)를 승계한다.
- 대외 "OS/EOS" 정체성 선언의 시기 조건 = **fabric 수렴 단계 진입 + 제3자 확장 경계 명세 고정**
  (`knowledge_fabric_vision_v1.md §4`). 본 전략이 *전진시키는 축*(내부 운영계층 성숙·콘텐츠 자산 복리·학습 policy)과
  *남는 축*(제3자 확장 경계 명세)을 구분해 명시한다.
- 내부 기층 어휘는 **Metadata OS**로 유지한다(`dev_constitution §0.1`의 어휘 정본화 — 'EKL/EKF/EOS' 중 EKF/
  Metadata OS 통일). "Education OS"는 이 내부 기층이 대외에 드러나는 *제품 서사*이지, 지금 선언하는 정체성이 아니다.
