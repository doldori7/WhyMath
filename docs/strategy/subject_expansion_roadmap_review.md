## 1. 총평

로드맵의 **전략 뼈대는 타당하며 저장소의 기존 방향과 정합**한다:

- **엔진–콘텐츠 분리**(§1.1) — 저장소의 "독립 수학 코어(L1-L4)" 원칙(MEMORY 슬라이스 89: "타 과목·AI 교체가 모두 코어 재사용")과 동일 사상.
- **2028 수능 개편 정렬**(§1.3) — 통합과학·통합사회 신설로 기출이 없는 첫 세대에게 "오개념 진단 + 개념 중심"으로 진입한다는 포지셔닝은 PRD v1.2의 차별화 논리와 정확히 맞물린다. 이 로드맵의 가장 강한 부분.
- **과목별 지식 구조 비교표**(§1.4) — 국어=기능 숙련 모델(위계 약함), 역사=사건 네트워크(스키마 변형이지 새 엔진 아님)라는 판단은 플레이북 "관계 타입 5~8개 제한" 원칙 안에서 소화 가능하다.
- **저작권 위험 서열**(국어 ≫ 사회 > 과학 ≥ 수학)과 4트랙 지문 수급·FCI 원문항 미사용·PhET 코드 도용 금지·뉴스 메타데이터-only RAG — 전부 `docs/data/licensing_safety.md`·저작권 가이드 v2.0의 논리와 정합. 국어 법률 검토 필수 예산화는 CLAUDE.md "변호사 검토 전제" 원칙과 일치.

다만 **P0(공통 기반화) 섹션에 저장소에서 이미 확정·동결된 결정과 정면충돌하는 항목 4건 + 스택 표기 착오 2건**이 있고, 과목 순서에 세션 확정 결정과의 불일치 1건이 있다. 아래 §2·§3이 교정 목록이다.

## 3. 과목 순서 — 미결 사항 1건 (결정 필요)

로드맵은 **화학 먼저(P2-A) → 물리(P2-B)**, 세션 확정 결정(2026-07-01)은 **물리 우선**이다. 근거가 서로 다르다:

| 안 | 근거 | 약점 |
|---|---|---|
| 화학 먼저 (로드맵) | 산염기 적정 프로토타입·30개 기능 브레인스토밍·화학 교육과정 분석 등 *저장소 밖 기존 자산*으로 시작 비용 최소 | 삼중 표상 UI·분자 3D 뷰어·시뮬레이션 3종 등 **신규 개발 요소가 물리 못지않게 큼**. 외부 자산의 실재·현행 스택 이식 가능성 미검증 |
| 물리 먼저 (세션 결정) | SymPy 동치 커널·수식 AST·그래핑 자산 재사용률 최대. 추가분이 단위/차원 해석(`sympy.physics.units` — 커널 교체가 아니라 형제 primitive)뿐이라 **엔진 관점 한계비용 최소**. `04a` §8.1 "물리/화학 확장 = 하네스 재사용 + 도메인 도구만 교체"와 정합 | 물리 시뮬레이션(2D 물리엔진)은 신규 개발 요소 |

**권장**: P2의 목적이 "확장 구조 첫 검증"이라면 **물리 우선**이 목적 정합적이다(검증 대상인 엔진의 재사용률이 가장 높은 과목으로 검증해야 seam의 결함이 드러난다). 화학 우선을 유지하려면 "기존 화학 자산이 실재하고 현행 스택(Flutter WebView·선언적 spec)에 이식 가능한지"를 **P2 착수 전 게이트**로 명시할 것. 어느 쪽이든 확정 시 MEMORY 결정 로그에 기록한다.

## 4. P0 재구성 — "6주 리팩토링"이 아니라 슬라이스 3묶음

로드맵 P0(2026.07~08, 6주)의 목표는 유효하나, 실행 형태는 대형 리팩토링이 아니라 저장소 하우스 스타일(자족 슬라이스 + 게이트)로 재구성한다. P0의 실체는 다음 3묶음이다:

1. **과목 확장 준비 슬라이스 S0~S3** (브랜치 `claude/subject-expansion-architecture-m2db9s`에 계획 수립 완료 — 체크리스트 A부):
   - S0 설계 문서(`subject_expansion_readiness.md`) + MEMORY 로그
   - S1 CurriculumEntry `subject` 축(유일한 마이그레이션 — 의미키 3-튜플 확장)
   - S2 NCIC 출처 표기 파라미터화(`build_ncic_citation_core`) + 과학 코드 수용성 동결 테스트
   - S3 과목 중립성 회귀 게이트("새 수학 하드코딩 유입 금지" 불변식)
2. **기존 등록 부채 트랙** (P0가 새로 발명할 것이 아니라 이미 대장에 있는 것 — 체크리스트 B부): 오개념 canonical 수렴 · 임베딩 namespace 분리 · Problem `Curriculum` enum 잔여 제거 · 그래프 위생(reachability/SCC).
3. **하지 않을 것**: 모노레포 재편(C3) · 노드 subject 내장(C1) · ContentRenderer 인터페이스 신설 — 저장소는 이미 "표현≠의미"(선언적 `Visualization`/`LearningScene` spec + 렌더러 플러그인) 구조이므로, 과목별 표시는 **기존 spec 체계에 과목별 spec 타입 추가**로 해결(새 추상 금지).

완료 판정도 로드맵의 "기존 테스트 100% 통과"를 저장소 게이트로 구체화한다: **pytest 전체(~4,600건) + ruff/black/mypy --strict + import-linter + 노드 금지 필드 게이트 + S3 과목 중립성 게이트 green**.

## 5. 유지할 강점 (v1.1에서 보존)

- §1.3 2028 수능 정렬 논리 전체 — 특히 "기출 부재 시기가 소크라테스식 개념 학습 앱의 최대 기회" 문장.

## 6. v1.1 반영 권장 보완 (누락 4건)

1. **cross-subject 엣지 원칙 추가** (§1.1 공통 엔진 표에): 물리 '순간속도'의 선수개념이 수학 '미분계수'인 식의 과목 간 연결은 **기존 `prerequisite` 재사용**(관계 타입 신설 금지 — 플레이북 5~8개 제한). 과목 경계는 엣지 속성이 아니라 양 끝 노드의 Overlay subject에서 유도. 통합과학·통합사회 시대에 이 앱만의 해자(과목 간 개념 점화 지도)가 되는 항목인데 로드맵에 부재.
2. **P2 착수 트리거 목록** (P2 체크리스트 상단에): 준비 단계에서 의도적으로 보류한 항목들이 곧 P2 첫 슬라이스다 — `dimensional_consistency` primitive(트리거: 물리 문항 검증 소비처 첫 등장), `Problem.subject_area` 컬럼(트리거: 물리 문항 첫 적재), 물리 오개념 시드(`phys-` kebab 접두 규약), PHY AREA 니모닉 실등록(트리거: 물리 원천 코퍼스 category 목록 확정). "예약된 착수 지점"이 명시돼야 P0→P2 연결이 끊기지 않는다.
3. **국어 Phase에 임베딩 재설계 항목**: 오독 패턴 DB는 수식이 아니라 긴 한국어 텍스트 기반 — 현행 수식 중심 임베딩 텍스트 규약(NFKC·chunk 분리·`EMBEDDING_TEXT_FORMAT_VERSION`)의 국어판 검토가 P3 체크리스트에 누락.
4. **Phase 명칭 충돌 해소**: 로드맵의 P0~P4와 저장소 ROADMAP.md의 Phase 0~5(청사진/MVP/풀K-12/영재·대시보드/B2B/글로벌)는 **다른 체계**다. 로드맵 P1(수학 출시)은 저장소 Phase 1(MVP)+1.5에, 로드맵 P2~P4(타 과목)는 저장소 체계에 아직 없는 축이다. v1.1에서 "확장 로드맵 E0~E4" 같은 별도 접두로 개명해 혼동을 차단할 것.
