> **판정 질문 (계획서 006 §24 단일 질문)**: *"이 PR이 EOS 1과목 검증의 blocker인가?"*
> YES → `eos-merge` / `eos-rework` · NO → `eos-postpone` · 중복·사장 → `eos-close`
>
> 006 §24는 이 항목을 단독으로 경고했다 — *"현재 PR을 그대로 계속 merge하면 EOS 전환 선언이
> 무의미하다."* 판정 없이 쌓인 PR은 전환 선언을 장식으로 만든다.
>
> **집행은 Kiki 몫이다**(acceptance ④). 본 세션의 산출물은 **판정표와 라벨까지**이며,
> CLOSE·MERGE 실행은 되돌리기 어려운 행위라 승인 후에 한다. 라벨은 조언이지 지시가 아니다.
>

## §3. ★ 최우선 발견 — #930·#931은 같은 태스크의 병렬 구현이다

두 PR이 **동일한 HARN-38**을 각각 구현했다. 원격 claim은 `claude/harn-38-tyyh3i`(#930)가
보유했고, `claude/failure-definition-signature-scmzdu`(#931)는 claim 없이 같은 일을 했다.

**다행히 자기 수복됐다.** #930의 태스크 notes가 스스로 기록한다:

> *"두 세션이 HARN-38을 병렬 수행해 각각 EOS-69(본 세션)·EOS-71(scmzdu)로 이중 등재 →
> **원격 claim 대장에 먼저 등재된 EOS-71로 통일하고 본 세션이 EOS-69를 철회**했다."*

즉 번호는 EOS-71/72(/73)로 수렴했다. **남은 위험은 단 하나 — `status` 필드다**:

| 파일 | #930 | #931 |
|---|---|---|
| `EOS-71-problem-quarantine-status.yaml` | `status: todo` · `session: null` | `status: in_progress` · `session: scmzdu` |
| `EOS-72-content-lifecycle-state-wiring.yaml` | 내용 상이(같은 축) | 내용 상이 |

**#930이 나중에 머지되면 EOS-71이 `in_progress` → `todo`로 되돌아가 진행 중인 claim이 조용히
사라진다.** 두 브랜치 모두 이 파일을 *신규 추가*하므로 git은 add/add 충돌을 내 자동 병합을
막는다(안전측). 다만 **충돌을 해소하는 사람이 `in_progress`를 살려야 한다**는 것을 모르면
그때 잃는다.

**권고**: ① #931 먼저 머지 ② #930은 main 병합 후 `EOS-71.status = in_progress`·
`session = claude/failure-definition-signature-scmzdu` 보존을 확인하고 푸시 ③ #930이 등재한
`HARN-43`(미push 브랜치 가시성 경고)이 이 사고의 재발방지책이므로 함께 살릴 것.

**부수 확인 — 번호 충돌은 없다**: main 최대 `EOS-64` · #924가 65~70 · #930/#931이 71~73.
세 세션이 같은 최대치에서 각자 할당했는데 우연히 겹치지 않았다. **우연이지 설계가 아니다** —
서로의 미머지 태스크를 볼 수단이 없었고, 그 공백이 정확히 `HARN-43`의 대상이다.

**#847 ⊃ #846** (커밋 `f9749daf`가 #847 브랜치의 조상 — 실측). 독립 PR이 아니라 스택이다.

→ **"trunk 부재 ≠ 미구현"의 교과서 사례**다. 12일간 미착지로 방치됐고, 그 결과 **#924의

일부가 CORE로 승격되고 경계 계약의 강제 범위가 넓어진다.

**REWORK 사유**(MERGE가 아닌 이유): ① ID 정합 — `S1-17`을 등재하거나 `S1-16`으로 귀속시켜야

풀거나 함께 처리할지 결정 필요.

**#847(OPS-02)의 별도 문제 — 존재하지 않는 SHA로 done 처리됐다**:

```
OPS-02 대장: status: done · artifacts: [e05e93f]
$ git cat-file -e e05e93f  → ★객체 자체가 저장소에 없음
```

구현(`scripts/backup/move_backup_to_nas.ps1`·`tests/infra/test_move_backup_to_nas.py`)은
**이 PR에만 있다**. 즉 **완료 선언은 됐는데 코드는 어디에도 착지하지 않았다.** `backlog.py done`
의 PR 증적 게이트(HARN-23)는 2026-08-11 착지라 그 이전 done은 이 검사를 통과하지 않았다 —
같은 부류가 더 있는지는 별도 감사가 필요하다(§6 후속 후보).

## §7. 정직한 공백

1. **CI를 전건 확인하지 않았다** — #930 1건만 실측(green 다수·backend 진행 중). MERGE 판정은
   *내용 관여도* 기준이며 "지금 초록"의 보증이 아니다. 오래된 10건은 31~80 커밋 뒤처져 CI가
   구조적으로 무효다.
2. **판정은 스냅샷이다** — 병렬 세션이 활발해 모집단이 시간당 변한다(오늘만 신규 6·머지 4).
3. **라벨은 조언이다** — 다른 세션이 작업 중인 PR에도 붙였다. 그 세션의 판단을 대체하지 않는다.
4. **#880의 겹침을 실측하지 않았다** — "EOS-45/46/48과 겹칠 수 있다"는 제목·경로 수준의
   추정이며 코드 대조는 하지 않았다. REWORK 판정의 근거는 겹침이 아니라 40커밋 뒤처짐이다.
5. **#882·#893의 "대장 부재"는 main 기준이다** — 다른 미머지 브랜치에 등재분이 있을 수 있다
   (MISC-07~11 선례). 되살릴 때 `git log --all --grep`로 재확인이 필요하다.
