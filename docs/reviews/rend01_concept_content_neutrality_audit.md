# REND-01 감사 노트 — `concept_content` 교수법-중립성

> **결론**: 기존 `db/models/concept_content.py::ConceptContent`의 **어떤 필드도 교수 *방식*을
> 담지 않는다 — 이미 교수법-중립이다.** 새 테이블 신설·컬럼 제거 없이, 이 좌석을 `ConceptDSL`
> (03c §1) 중립 계약의 영속 짝으로 그대로 정렬한다.
>
> - **정본**: `docs/architecture/03c_content_strategy_cache.md` §1 ("기존 `concept_content`를 이
>   중립 계약으로 감사·정렬하는 것이 1차 작업 — 새 테이블 신설이 아니라 기존 좌석의 중립성 확인").
> - **기계 동결**: `tests/backend/l3/render/test_concept_content_neutrality.py`
>   (방식 컬럼 부재 전수 스캔 + 컬럼 집합 스냅샷).

## 2. 헷갈리기 쉬운 두 필드 — 왜 방식이 아닌가

- **`metaphor`(은유)**: 은유는 개념을 이해시키는 *콘텐츠*이지 교수 *방식*이 아니다. "무엇에
  빗댈 수 있는가"(지식)와 "비유로 가르칠까 문답으로 가르칠까"(방식·`PedagogyStrategy.ANALOGY`
  vs `SOCRATIC`)는 다른 축이다. `ANALOGY` 어댑터는 이 은유/예시 *콘텐츠*를 렌더 재료로 쓴다 —
  방식은 어댑터가, 콘텐츠는 좌석이 소유한다(정확한 분리).
- **`misconception`(오개념)**: 오개념은 "학생이 흔히 무엇을 오해하는가"라는 *지식*이다. 반응형
  retrieval 대상(오개념을 초기 context에 preload 금지·CLAUDE.md)이지 방식 지시가 아니다.
  `ConceptDSL`은 이를 본문 없이 `misconception_ids`(id 참조)로만 들고, 좌석은 본문을 보관한다.

## 3. 값 수준(value-level) spot-check 주의 — 기계 스캔의 한계

컬럼명 스캔은 *구조적* 중립성(방식 컬럼 부재)을 동결하나, **필드 *값* 안에 방식 지시가 섞여
들어갈 가능성**은 기계가 전수 보증하지 못한다. 특히 자유서술 필드 2곳을 사람 검수 대상으로 남긴다:

- **`explanation`**: 설명 본문에 "이 부분은 반드시 학생에게 질문으로 유도하라" 같은 *방식 지시*가
  섞이면 값 수준 오염이다(구조는 중립이나 값이 방식을 밀반입). 콘텐츠 검수(review_status)에서
  "설명은 *무엇을* 설명하는가만 담고 *어떻게 가르칠지*는 담지 않는다"를 확인해야 한다.
- **`flashcards[].exposure_condition`**: 암기카드의 *노출 조건*은 "언제 보여줄지"라 방식/스케줄링
  (SPACING·RETRIEVAL)에 근접한다. 현재는 콘텐츠 메타(노출 맥락)로 해석하되, 값이 "분산복습
  간격 3일" 같은 *방식 파라미터*로 진화하면 그때 별도 축(어댑터/스케줄러)으로 분리해야 한다 —
  좌석에 방식 파라미터를 축적하지 않도록 검수에서 감시한다.

이 두 항목은 컬럼 스캔이 아니라 **콘텐츠 검수(사람 폴백)** 소관이다(초인간 검증 기준: 측정 미달
구간은 사람 폴백). 구조 중립성은 위 테스트가 동결하고, 값 중립성은 검수 체크리스트가 맡는다.

## 4. 후속 (범위 밖)

- `ConceptDSL` ↔ `concept_content` 프로젝션 매핑(좌석 → 계약 로딩)은 후속(CACHE-01 supply 경로).
- `PedagogyStrategy` PG native enum 컬럼 백킹은 소비자가 생기면 추가(현재 렌더 레지스트리만 소비).
