## 🔴 지금 반드시 반영 (초기 단계 핵심)

### R1. 침묵 실패 — 예외를 삼킬 땐 "예외 타입명"을 로그에 (§4 보강)
§4 "예외를 무시하지 않는다·로그를 남긴다"는 너무 약하다. best-effort/관측 코드가 예외 *타입명* 없이 "실패"만 남기면 기록이 죽어도 무증상이다. §7이 이미 "로그로 남긴다"를 요구하므로 지금 습관으로 박아야 한다.
- **근거(실측)**: 관측 쓰기가 무타입 경고 뒤에서 **8일간 무증상 전멸**(langfuse 쓰기 표면 불일치). 부록 A-1.
- **적용 문구**: "best-effort/관측 코드가 예외를 삼킬 때는 반드시 예외 **타입명**을 로그에 포함(시크릿·개인정보 값 제외). '실패'만 남기는 무타입 경고 금지."

### R2. "검증"의 정의 — 통과하는 테스트가 곧 정답이 아니다 (§3 보강)
§3 "테스트 없이 완료 금지"는 *무엇이 유효한 검증인지*를 정의하지 않는다. 지금 정의하지 않으면 규칙이 껍데기가 된다. 두 가지만:
- **변별력**: 실패 상태에서 *실제로 실패 신호를 내는지* 확인된 검사만 인정. (근거: 정상 상태에서도 항상 False를 반환하던 사전점검이 검증을 위장 — 부록 A-4)
- **권위 서열**: 도구/기계 증명(SymPy 등) > 측정 통과 > 사람 눈. AI 답변·지식 DB 검증 단계라 "유닛 통과 ≠ 수학적 정답"이 즉시 관련.
- (정교한 6축 초인간검증·강등전은 🟢 유예. 지금은 위 두 줄로 충분.)

### R3. AI 답변은 노출 전 "도구 검증" 통과 필수 (§7 보강)
§7은 출처는 요구하나 답변 *자체의 수학적 정확성*을 도구로 검증하라는 규칙이 없다. 출처가 있어도 유도가 틀릴 수 있다. AI 답변 기능을 *지금 설계 중*이라 소급이 어렵다.
- **적용 문구**: "수학적 주장은 노출 전 도구(SymPy 등)/검증기 통과 필수. 검증 불가 구간은 보류하거나 '불확실'로 표시. 환각을 발견하면 조용히 넘기지 말고 로그+수정."

### R4. 비가역 작업(운영 DB·마이그레이션) 안전장치 (§6 보강)
§6은 "원본 불변·사본에서 가공"까진 있으나 운영 DB에 대한 *비가역 실행* 전 안전장치가 없다. 저자 스스로 "지식 DB는 소급 수정 거의 불가능"이라 했으니 지금 박아야 한다.
- **적용 문구**: "운영 데이터 일괄수정·스키마 마이그레이션은 (1) 백업/스냅샷 선행 (2) 사본·소량 샘플 리허설 (3) 롤백 절차 명시 (4) 실행 후 건수·무결성 검증. 삭제·덮어쓰기 전 대상 실물 확인."

### R5. 지식그래프의 순환 — prerequisite만 DAG (§4 순환참조 규칙을 §6에 맞게 분리)
§4 "순환참조 금지"는 *코드 모듈*엔 맞지만, 지식 개념 그래프는 본질적으로 순환적이다. 뭉뚱그리면 비현실적이거나 방치된다. 지금 스키마에 반영해야 소급을 피한다.
- **적용 문구**: "관계 중 **prerequisite(선수)만 DAG 강제 + 도달성(reachability) 체크**. 그 외 관계는 순환 허용하되 traversal에서 분리. `related_to`/`similar_to`류 약한 관계를 traversal에 쓰지 않는다."

## 🟡 지금 반영 권장 (저비용·곧 부딪힘)

### R6. 의존성 pin에 상한 + SDK는 실물로 검증 (§8 보강)
LLM SDK를 쓰기 시작하는 단계라 곧 문제다. **근거(실측)**: 무상한 pin(`langfuse>=2.50`)이 v2/v3/v4를 혼재시켜 호출 표면이 어긋남 → R1의 8일 사고와 같은 뿌리(부록 A-2).
- **적용 문구**: "의존성은 검증된 범위로 상한을 건다(`>=x,<y`). mock만으로 외부 SDK 정합 선언 금지 — 우리가 호출하는 메서드가 실물에 있는지 확인."

### R7. 환경 사실은 실측 후 확정, 간접 신호를 성공으로 쓰지 마라 (§2 확장: 파일→환경)
§2 "기억만 믿지 말고 파일 다시 읽기"는 좋으나 *환경 사실*(포트·접속경로·프로세스 생존)엔 미적용이다. 로컬 DB·서버를 띄우는 단계면 곧 부딪힌다. **근거(실측)**: 좀비 프로세스의 `/health` 응답·죽은 pid 파일을 "성공"으로 오인(부록 A-3).
- **적용 문구**: "환경 규칙(포트·경로·프로세스 생존)은 실측 증거 후 확정. 성공은 *그 단계 산출물 자체*로 판정 — pid 파일·/health·포트 열림처럼 다른 프로세스가 대신 만족시킬 수 있는 간접 신호를 성공 근거로 쓰지 않는다."
- (정교한 서버 창-운영 런북은 🟢 유예.)

### R8. 시크릿 등록 직후 자가검증 스텝 (§8 보강)
.env는 있으나, 자리표시자 키를 그대로 등록하는 사고가 흔하다. **근거(실측)**: `pk-lf-…` 자리표시자 키가 등록되어 관측이 "0건 통과"로 위장(부록 A-2).
- **적용 문구**: "시크릿 등록 직후 길이·형식·`…` 포함 여부 검사(값은 미출력). 예시에 복사-실행되는 위치엔 자리표시자를 두지 않는다."

### R9. 관계 타입 수 상한(5~8) (§6 "관계 등록제"에 한 줄)
지식 DB 구축 중이 관계 폭발 방지의 적기다.
- **적용 문구**: "관계 타입은 5~8개로 상한. 새 타입은 '없으면 어떤 튜터링 오류가 나는가'에 답하지 못하면 기각."

### R10. 외부 도구가 읽는 설정파일은 ASCII 전용 (신규 한 줄)
한국어 Windows(cp949) + 외부 도구(uvicorn 등) 설정파일 조합이면 지뢰다. **근거(실측)**: 한글 설정키 → 인코딩 오류로 서버 기동 실패(부록 A-5). 서버 설정을 아직 안 만졌다면 이 항목은 🟢.
- **적용 문구**: "로케일 인코딩(한국어 Windows=cp949)으로 읽히는 설정파일은 ASCII 전용. 한국어 설명은 파일이 아니라 문서/런북에."

## 🔁 중복·경합 (요청 항목 — 거의 전부 "지금", 비용 0)

새 규칙 추가가 아니라 *이미 있는 규칙끼리의 모순 제거*라, 지금 고치면 문서가 오히려 **짧아진다**. 초보가 문자 그대로 따르다 겪는 혼란이 여기서 나온다.

### 경합 (동시에 지킬 수 없음)
- **C1** §2 "한 번에 한 **파일**만" ↔ §3 "테스트 없이 완료 금지"(테스트=2번째 파일) ↔ §5 "1기능=1커밋". → 단위를 **"한 기능(관련 테스트 포함) = 한 커밋"**으로 통일하고 '한 파일'은 폐기.
- **C2** §2 "코드 전 **반드시** 4요소 제시"(모든 작업) ↔ §9 "이 형식은 **중요·대규모만**". 적용 범위 모순 → §2를 §1 임계에 맞추거나, §9를 "소규모는 축약"으로 연결.
- **C7** §4 순환참조 금지(코드) ↔ §6 지식그래프 본질 순환 → R5로 분리 해소.
- **C8** §0 "코드보다 데이터 일관성 우선" ↔ §4 코드 품질 — 충돌 시 판단 기준 부재 → **의사결정 우선순위 1줄**(예: 안전·데이터 무결성 > 정확성 > UX > 비용 > 속도).

### 중복 (분산 재서술 → 나중에 표현이 어긋남)
- **C3** "계획 먼저 제시"가 §1·§2·§9에 3중 재서술(임계·문구 상이) → 단일 규칙(임계=§1 → 형식=§9 → 승인 후)으로 통합, §2는 참조.
- **C4** "삭제는 승인 후"가 §2·§3·§6 3곳 → §3에 통합.
- **C5** "중복 구현 금지·재사용"(§3) ≈ "DRY"(§4) 이중 표현 → 하나로.
- **C6** 로깅 규칙이 §4·§6·§7·§8에 흩어짐 → **"로깅 정책" 1절**로 통합(예외 타입명 O·참조 ID·버전 O / 시크릿·개인정보 X). R1이 여기에 자연히 들어간다.

## 부록 A. 실측 사고 근거 색인

이 저장소(WhyMath)의 결정 로그(`MEMORY.md`)·헌법(`CLAUDE.md`)에서 확인된, 위 지적의 근거가 된 실제 사고.

- **A-1 (2026-07-16) 침묵 실패**: 로컬 라우팅 게이트는 통과(30/30)했으나 관측 쓰기 30/30 사망 — 설치된 SDK에 우리가 부른 메서드가 없었고, 무타입 best-effort 경고라 **8일간 무증상**. → R1.
- **A-2 (2026-07-16) 무상한 pin + 자리표시자 키**: `>=2.50` 무상한 pin이 여러 환경에 서로 다른 메이저를 설치 → 표면 불일치. 자리표시자 키(`pk-lf-…`)가 인코딩 크래시를 일으키고 fallback이 "0건"으로 위장. → R6·R8.
- **A-3 (2026-07-17) 간접 신호 오인**: 좀비 서버가 포트를 점유 → 새 서버 즉사·pid 파일은 죽은 pid·/health는 좀비가 응답 → "성공"처럼 보여 트래픽이 잘못된 서버로. → R7.
- **A-4 (2026-07-17) 변별력 없는 검증**: 캡처 파일 지연 생성 때문에 사전 존재검사가 정상 상태에서도 항상 실패 반환 → 검증 스텝 자체가 무효. → R2.
- **A-5 (2026-07-17) 설정파일 인코딩**: 외부 도구가 로케일(cp949)로 읽는 설정파일에 한글 → 기동 실패. → R10.
