# OPS-31 암호화 왕복 실측 — 실 PostgreSQL 16 기준

> acceptance ④("암호화했다고 선언만 하고 산출물을 열어보지 않는 검증은 위장이다")의 증거.
> 픽스처가 아니라 **실 pg_dump 산출물**로 쟀다. 실행: 2026-09-01, 세션 샌드박스,
> PostgreSQL 16.13 + age(불특정 버전, `/usr/bin/age`).

## 왜 실물이어야 했나

계약 테스트(`tests/infra/test_backup_encryption.py`)는 `.dump` 헤더 매직만 갖춘 최소
픽스처를 쓴다 — 그것으로 ①매직 판별과 ②`pg_restore`가 암호문을 *거부*하는 축은 재지만,
**"복호하면 정말 복원되는가"**는 재지 못한다. 그 축은 실 덤프가 있어야 한다.

## 절차와 결과

실 클러스터를 띄우고 미성년 PII를 본뜬 행 2건을 넣은 뒤 `pg_dump -Fc`로 덤프했다.

| # | 무엇을 쟀나 | 결과 |
|---|---|---|
| A | **평문 덤프에서 키 없이 PII가 나오는가** — 암호화가 필요한 이유 | `pg_restore -f -` 출력에 `minor.student@example.kr` **1건 노출** |
| A2 | 평문 덤프의 `pg_restore --list` | **exit 0** (누구나 카탈로그 판독 — 무방비) |
| B | `age-keygen` 키쌍 생성, 공개키만 수신자 파일로 분리 | recipient `age1878a0…qmm59p6` |
| C | `age -R recipients.txt -o x.dump.age x.dump` | **exit 0**, 2808 → 3008 bytes, 헤더 `age-encryption.org/v1` |
| D | **암호문의 `pg_restore --list`** | **exit 1** (거부 — 잠김 확인) |
| D2 | 암호문에서 PII 추출 시도 | **0건** |
| E | 개인키 없이 `age -d` | **exit 1** |
| F | 개인키로 복호 → 원본과 바이트 비교 | `cmp` **exit 0** (바이트 동일) |
| F2 | 복호본 `pg_restore --list` | **exit 0** |
| F3 | **복호본을 실 DB에 복원** (`pg_restore -d restore_target`) | **exit 0** |
| F4 | 복원된 DB에서 행 조회 | `minor.student@example.kr\|OO중학교\|2` · `second@example.kr\|XX고등학교\|3` — **원본 그대로** |

즉 **잠김(D·D2·E)과 복원 가능(F~F4)이 양방향으로 성립**한다. 어느 한쪽만 확인하면
"아무도 못 여는 파일"이나 "아무나 여는 파일"을 통과시킨다.

## 검증기 자신의 변별력 (`verify_encrypted_backup.py`)

위 실물 산출물을 그대로 태웠다.

| 투입 | `reason` | exit |
|---|---|---|
| 정상 암호화본 | `ok — 카탈로그 항목 7건` | **0** |
| 평문 덤프를 `.age`로 개명 | `not_encrypted` | **1** |
| 잘못된 개인키 | `decrypt_failed — no identity matched any of the recipients` | **1** |
| 암호문 절단(앞 1500바이트) | `decrypt_failed — failed to decrypt and authenticate payload chunk` | **1** |
| `age` 바이너리 부재 | `필요한 도구 부재` | **2 (판정 불가)** |

네 가지 실패가 **서로 다른 사유 문면**을 낸다. 예외 타입명만 남기면 8개의 서로 다른
실패가 같은 글자로 보인다는 2026-08-22 교훈의 적용이다. 도구 부재를 0(통과)이나
1(실패)로 뭉개지 않고 **2**로 분리한 것도 같은 축이다 — "검사 못 함"은 "문제 없음"이 아니다.

## 자기 정정 2건 (측정 과정에서 나온 것)

1. **A 항목의 첫 측정이 거짓 0을 냈다.** `pg_restore -a -t app_user "$D"`를 stderr를
   `/dev/null`로 버린 채 돌렸는데, PostgreSQL 16은 `-d`/`-f` 없이는 아예 거부한다
   (`one of -d/--dbname and -f/--file must be specified`). 출력이 비어서 grep이 0을
   냈고, 그것이 "PII가 안 보인다"로 읽힐 뻔했다 — **성공/실패 양쪽에서 같은 값을 내는
   검사**였다(CLAUDE.md "변별력 없는 검증 스텝 금지"의 자기 재현). stderr를 살려
   에러를 보고 `-f -`로 고쳤다.
2. **뮤테이션 하네스 초판도 무효였다.** 셸 이스케이프로 대상 문자열이 어긋나 12건 중
   여러 건이 **적용조차 되지 않은 채** "통과"로 보였다. 적용 여부를 먼저 단언하는
   파이썬 하네스로 다시 짰고, 그러자 3건이 **미검출**로 드러났다(아래).

### ★ 초판이 놓친 3건과 그 원인

①②⑫는 **1차 시도에서 미검출**이었다. 원인이 하나였다: 단언이 스크립트 **원문 전체**를
검사해서, 코드를 망가뜨려도 **헤더 주석에 남은 같은 문자열**이 통과시켰다. 예컨대
`-LogonType S4U`는 주석 설명에도 등장하므로, 실제 설정을 `Password`로 바꿔도
`"-LogonType S4U" in text`는 참이었다.

대책은 주석만 걷어내는 `_strip_ps_comments()`를 두고 계약 단언을 **코드 영역**에서
수행하는 것이다(`scripts/ops/check_ps_scripts.strip_noncode`는 문자열 리터럴까지
지워서 쓸 수 없다 — `"*.dump.age"` 같은 리터럴 자체가 계약이다). ⑫는 추가로
메시지 문면이 아니라 **동사(`Fail`)까지** 함께 동결했다 — `Fail`을 `Write-Host`로
바꾸면 문면은 그대로 남고 스크립트는 평문 백업을 만들고도 exit 0으로 끝난다.

**이 3건이 이 문서에서 가장 중요한 대목이다.** 뮤테이션을 돌리지 않았다면 세 개의
계약이 "green이지만 아무것도 지키지 않는" 상태로 착지했을 것이고, 그 사실은 실제로
로그온 의존이 되살아난 날에야 드러났을 것이다.

## 이 측정이 증명하지 못하는 것

- **`.ps1`이 Windows에서 실제로 그렇게 도는지는 재지 못했다.** 샌드박스·CI에 PowerShell이
  없다(구조적 공백 — `scripts/ops/check_ps_scripts.py`가 같은 이유로 존재한다). 위
  왕복은 `age`·`pg_dump`·`pg_restore`의 **동작**을 실물로 증명하지만, PS1이 그 도구들을
  그 순서로 부르는지는 텍스트 동결 + 런북 §2-1 자가검증이 담당한다.
- **키 사본이 실재하는지 기계는 모른다.** 개인키 분실 = 백업 전량 영구 복구 불가이고,
  이 단일 실패점은 사람의 보관 행위로만 상환된다(런북 §1b·§6).
- **스케줄이 장기적으로 안 빠지는지는 시간이 지나야 안다.** 이 PR이 넣은 것은 누락을
  *줄이는* 설정(S4U·StartWhenAvailable)과 누락을 *보이게 하는* 대장(`backup_status`)이지,
  누락이 0이라는 증명이 아니다.
