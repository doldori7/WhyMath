# 프롬프트 엔지니어링 표준

## 원칙

### 1. 답 미루기가 기본값
모든 학생 응답 프롬프트는 *답 미루기* 기본.
답 제공은 *예외*이며 4단계 중 최후 단계.

### 2. 학습자 모델 컨텍스트 *항상* 주입
- BKT 숙달도
- 오개념 후보
- 정서 상태
- 학년·교과서·진도

### 3. 한국어 친화 톤
- 친근한 반말 (학생 대상)
- 정중한 존댓말 (학부모 대상)
- 위에서 내려다보는 톤 X
- 학생 *언어 그대로* 반영

### 4. 버전 관리
- 모든 프롬프트 버전 번호 (v1, v2, ...)
- 변경 시 *기존 버전 보존*
- Langfuse에 등록

### 5. 테스트 케이스 동반
- 정상 시나리오
- 답 강요 시나리오
- 좌절 시나리오
- 오개념 시나리오

## 표준 구조

```
[학생 컨텍스트]
- 학습자 모델 데이터

[행동 원칙]
- 5가지 절대 원칙

[현재 권장 결정]
- 힌트 단계
- 소크라테스 카테고리

[응답 형식]
- JSON 또는 자연어 명시
```

## A/B 테스트

```python
# Langfuse 변형 관리

v2 = "더 빠른 답"  # 변형 1
v3 = "더 많은 시각화"  # 변형 2

# KPI: 답 미루기 도달 깊이·재방문율·이탈률
```

## 평가 (LLM-as-judge)

```python
EVAL_PROMPT = """
다음 응답을 평가:
1. 답을 직접 제공? (0/1)
2. 질문 비율
3. 부정 표현 있음?
4. 카테고리 일치?
5. 정서 안전?
"""
```

## 절대 금지

❌ "정답은 X입니다" 패턴
❌ "이건 잘못된 거야" (직접 교정)
❌ 부정 표현 ("틀렸어", "못 하네")
❌ 학생 라벨링 ("초보", "약한 학생")
❌ 비교 ("다른 학생은")
