# 오개념 방향 판별 LLM-judge 프롬프트

> **정본(canonical)** — 슬108. 이후 코드(`l4/misconception/judge.py` 등)가 *그대로 인코딩*하는
> 원본. 프롬프트를 바꿀 때는 *여기서 먼저* 고치고 코드를 맞춘다(드리프트 방지·doc-first 불변).

## 무엇을 푸는가 — 방향맹(direction-blindness)의 정본 해법

substring(`diagnose`)·임베딩(`semantic_matches`)은 *고-recall*로 오개념 후보를 올리지만
**방향(⇒ 역방향)·부정(≠·아니다)·등치(=)를 못 가린다**. 이를 슬107이 수치로 못 박았다
(`misconception_diagnosis.md` §측정 하니스: substring·임베딩 *둘 다* FP 프로브에서 발화 —
올바른 역방향·부정·인접 진술을 오개념으로 오탐).

- 예: 오개념 `continuity-implies-differentiability`(틀린 믿음 "연속이면 미분가능")의 후보로,
  학생이 *올바른* "미분가능하면 연속이다"(역방향)를 써도 두 매처 모두 매칭한다(거짓양성).
- 예: 오개념 `composite-function-commutes`(틀린 믿음 "f∘g = g∘f")의 후보로, 학생이 *올바른*
  "합성은 순서를 바꾸면 달라진다"(부정)를 써도 매칭한다(거짓양성).

LLM-judge는 이 후보들을 **검증**한다 — 학생 진술이 *그 오개념의 틀린 믿음을 실제로 표현하는지*,
아니면 *올바른* 진술(역방향·부정·올바른 인접 사실)인지 판정해 **거짓양성을 걸러낸다**.

### judge의 자리(7계층·책임 경계)

- judge는 **검증자(verifier)**다 — *생성자·코치가 아니다*. 답·힌트·풀이를 만들지 않는다.
- judge 출력은 **학생에게 직접 보이지 않는다**(내부 필터). 코드가 이 출력으로 후보 리스트를
  필터링할 뿐, 발화는 여전히 별도 소크라테스 개입(`misconception_diagnosis.md` §개입)이 만든다.
- judge는 *후보 1건*(학생 진술 × 후보 오개념의 `canonical_statement`)을 받아 **3값** 판정한다.

## 코드가 이 출력을 어떻게 쓰는가 (3값 → 필터)

judge는 (학생 진술, 후보 오개념의 `canonical_statement`[*틀린 믿음*])을 받아 3값 중 하나를 낸다:

| 판정 | 의미 | 코드 동작 |
|---|---|---|
| **`예`** | 학생 진술이 *그 틀린 믿음을 실제로 표현*한다(진짜 오개념) | 후보 **유지** |
| **`아니오`** | 학생 진술이 *올바르거나*(역방향·부정·올바른 인접 사실) 그 오개념과 *다른* 말이다 | 후보 **제거**(거짓양성) |
| **`불확실`** | 판단이 어렵다(모호·정보 부족) | 후보 **유지**(보수적) |

**`불확실`은 유지**다 — judge가 학생을 *함부로 오개념으로 단정*하지 않으면서도, 모호할 때
후보를 *섣불리 버리지 않는다*. 즉 필터는 **`아니오`일 때만 제거**한다. 이 보수성은 CLAUDE.md
의사결정 우선순위(1. 학생 안전·웰빙 ≫)와 "모르면 모른다고"에서 온다: 거짓 단정의 해(올바른
풀이를 한 학생에게 "이건 오개념"이라 라벨)가 *놓침*보다 크다.

## SYSTEM 프롬프트

```
당신은 한국 중·고등학교 수학교육의 *진단 검증자*다.

[역할]
당신은 오개념을 *생성하거나 가르치지 않는다*. 답·힌트·풀이·코칭을 만들지 않는다.
당신은 오직 하나만 한다: 주어진 "학생 진술"이 주어진 "오개념(틀린 믿음)"을
*실제로 표현하는지* 판정한다. 당신의 판정은 학생에게 보이지 않는 내부 필터다.

[입력]
- 학생 진술: 학생이 풀이 중 적거나 말한 문장(들).
- 오개념 이름: 후보로 올라온 오개념의 이름.
- 틀린 믿음(canonical): 그 오개념을 가진 학생이 *가정하는 틀린 명제*.

[판정 — 3값 중 하나]
- 예    : 학생 진술이 그 *틀린 믿음을 실제로 표현*한다. (진짜 오개념)
- 아니오 : 학생 진술이 *수학적으로 올바르거나*, 그 오개념과 *다른 말*이다.
- 불확실 : 모호하거나 정보가 부족해 판단하기 어렵다.

[핵심 원칙 — 방향·부정·등치를 정밀히 구분]
1. 함의 방향(⇒): "A이면 B"와 그 역 "B이면 A"는 *다른 명제*다.
   틀린 믿음이 "A이면 B"인데 학생이 *올바른* 역 "B이면 A"를 적었다면 → 아니오.
   (예: 틀린 믿음 "연속이면 미분가능" vs 올바른 "미분가능하면 연속" → 아니오)
2. 부정(≠·아니다·성립하지 않는다): 틀린 믿음이 "A = B"(또는 "A이다")인데
   학생이 *올바르게* "A ≠ B"(또는 "A가 아니다")라고 적었다면 → 아니오.
   (예: 틀린 믿음 "f∘g = g∘f" vs 올바른 "합성은 순서를 바꾸면 달라진다" → 아니오)
3. 등치(=): 두 대상을 동일시한 진술인지, 단지 *나란히 언급·대조*한 진술인지 구분한다.
   대조·비교는 동일시가 아니다.
4. *수학적으로 올바른 진술은 오개념이 아니다.* 주제가 같다는 이유만으로 예라고 하지 않는다.

[보수성 — 불확실을 적극 허용]
- 진술이 단편적·모호해 틀린 믿음을 표현하는지 *확신할 수 없으면* → 불확실.
- 학생을 함부로 오개념으로 단정하지 않는다(거짓 단정 < 놓침, 학생 정서가 먼저).
- 확실히 올바르거나 확실히 다른 말일 때만 아니오. 확실히 틀린 믿음일 때만 예.

[출력 형식 — 반드시 정확히 두 줄, 다른 말 금지]
판정: 예|아니오|불확실
근거: <한 줄 설명. 방향/부정/등치 중 무엇이 근거인지 명시>
```

> **파싱 계약(슬109 명시)**: 코드(`parse_verdict`)는 `판정:` 토큰이 `예`/`아니오`/`불확실`과
> **정확히 일치**(후행 마침표류만 관용)할 때만 인정한다. 헤징("아니오라고 단정하기 어렵다")·
> 수식어·복합 표현은 전부 형식 위반 = `불확실`(후보 유지) 폴백 — 계약 밖 응답에서 판정을
> *추측하지 않는다*. (종전 부분문자열 포함 파싱은 헤징을 `아니오`=제거로 오파싱해 보수성
> 불변식을 깨뜨렸음 — 슬109 교정.)

## USER 템플릿

> 코드가 플레이스홀더를 채워 주입한다. `{misconception_name}`·`{canonical_statement}`는 카탈로그
> (`l4/misconception/catalog.py`)의 `name_kr`·`canonical_statement`에서 온다.

```
다음 학생 진술이 이 오개념(틀린 믿음)을 표현하는가?

[오개념 이름] {misconception_name}
[틀린 믿음(canonical)] {canonical_statement}

[학생 진술]
{student_statement}

위 학생 진술이 *틀린 믿음을 실제로 표현*하면 예, *올바르거나 다른 말*이면 아니오,
*모호하면* 불확실로 판정하라. 정확히 두 줄(판정/근거)로만 답하라.
```

## few-shot 예시

> 모두 카탈로그(`catalog.py`) 실제 오개념 사용·**자작**(교과서·평가원·EBS 본문 0). few-shot은
> SYSTEM 다음, 실제 USER 질의 앞에 같은 USER/응답 형식으로 붙인다. 판정 4종(`예`·`아니오`(역방향)·
> `아니오`(부정)·`불확실`)을 골고루 시연한다 — 방향·부정 구분이 이 프롬프트의 *핵심 가치*이므로
> 역방향·부정 예시를 각각 둔다.

### 예시 1 — 예 (틀린 믿음을 실제로 표현)

오개념: `continuity-implies-differentiability` (연속·미분가능 함의 혼동)

```
다음 학생 진술이 이 오개념(틀린 믿음)을 표현하는가?

[오개념 이름] 연속·미분가능 함의 혼동
[틀린 믿음(canonical)] 연속이면 미분가능하다

[학생 진술]
이 함수는 모든 점에서 연속이니까, 모든 점에서 미분가능해요.

위 학생 진술이 ... 정확히 두 줄(판정/근거)로만 답하라.
```
응답:
```
판정: 예
근거: "연속이면 미분가능"이라는 함의를 그대로 단정함(틀린 믿음과 방향·내용 일치).
```

### 예시 2 — 아니오 (올바른 역방향 ⇒)

오개념: `continuity-implies-differentiability` (연속·미분가능 함의 혼동)

```

[오개념 이름] 연속·미분가능 함의 혼동
[틀린 믿음(canonical)] 연속이면 미분가능하다

[학생 진술]
미분가능하면 연속이에요. 미분가능한 점에서는 함수가 끊기지 않으니까요.

위 학생 진술이 ... 정확히 두 줄(판정/근거)로만 답하라.
```
응답:
```
판정: 아니오
근거: 방향이 역(미분가능⇒연속)이며 이는 참인 정리 — 틀린 믿음(연속⇒미분가능)과 다른 명제.
```

### 예시 3 — 아니오 (올바른 부정 ≠)

오개념: `composite-function-commutes` (합성함수 교환 가정)

```

[틀린 믿음(canonical)] f∘g = g∘f (합성은 교환법칙 성립)

[학생 진술]
합성함수는 순서를 바꾸면 결과가 달라져요. f∘g와 g∘f는 일반적으로 같지 않아요.

응답:
```
판정: 아니오
근거: 합성의 비가환(f∘g ≠ g∘f)을 올바르게 진술 — 틀린 믿음의 부정이므로 오개념 아님.
```

```

### 예시 6 — 예 (등치를 실제로 단정, 부정과 대비)

## 판정 일관성 메모 (코드·평가용)

- **파싱**: 출력 첫 줄 `판정:` 뒤 토큰만 본다(`예`/`아니오`/`불확실`). 둘째 줄 `근거:`는 로깅·
  텔레메트리용(학생 비노출). 형식 위반(두 줄 아님·토큰 외 값) 응답은 **`불확실`로 폴백**한다
  (보수·CLAUDE.md "검증 없이 학생에게 제공 금지"의 안전판).
- **필터 규칙**: `아니오`만 후보 제거. `예`·`불확실`은 유지. (위 "코드가 이 출력을 어떻게 쓰는가")
- **방향맹 정직**: judge는 방향·부정·등치를 *언어 추론으로* 가르는 층이다 — substring·임베딩이
  구조적으로 못 하는 일(`misconception_diagnosis.md` §정직 스코프 X). judge 역시 *완벽하지
  않으므로*(LLM 오류 가능) `불확실` 폴백·보수 유지가 안전망이다.
- **자작 확인**: 본 문서의 모든 학생 진술·오개념 내용은 카탈로그의 자체 생성 `canonical_statement`
  에 근거한 *자작 예시*다(교과서·기출·EBS 복제 0·CLAUDE.md 저작권).
```
