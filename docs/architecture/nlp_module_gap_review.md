## §0. 두 가지 전제 정리

### ①-a 착수 가설이 두 번 뒤집혔다 (스코프 고정)

이 대조는 **가설 두 개가 실측으로 반증된 뒤에** 쓰였다. 기록해 두지 않으면 다음 세션이 같은
오판을 반복한다.

1. **"NLP 계층이 통째로 없다"** → **반증.** 없는 게 아니라 **의도적으로 얇다.** 발화 *생성*(NLG)은
   LLM이 학생 대면으로 GA 가동 중이고(`harness/wh1_primary.py` → `api/coach.py`), 발화 *이해*(NLU)만
   한국어 키워드 화이트리스트다. 이 비대칭은 사고가 아니라 명문화된 설계다 —
   `l4/polya/transitions.py:5-8`: *"v1은 한국어 키워드 화이트리스트 + 길이 임계값. LLM-judged
   전이는 v2. **False-negative(stay 과다)는 교수학적으로 안전, false-positive(잘못 next)는 유해 —
   이 비대칭이 설계의 핵심.**"*
2. **"Qwen3-VL 인식기가 스텁이다"** → **반증.** `l5/ocr/recognize.py:250` `arecognize`는 L3 라우터
   경유(`requires_vision=True`·`images=[...]`·캐시·Langfuse)로 **완전 구현**돼 있다. 스텁인 것은
   동기 진입점 `_recognize_crop`뿐이고 그건 설계상 의도다(비동기 전용). **스텁이라 말하는 쪽이
   틀렸다** — 클래스 docstring과 `CLAUDE.md:76`이 stale하다(§정정).

두 반증 모두 방향이 같다: **이 모듈은 "못 만든" 게 아니라 "만들어 놓고 닿지 않는" 상태**다.
D1이 정확히 그 형태다.

### ①-b 틀의 아키텍처와 정본의 차이 (갭 판정의 전제)

틀은 NLP를 **"학생의 모든 입력을 AI가 이해 가능한 지식 형태로 변환하는 인터페이스 계층"**으로
정의하고 선형 파이프라인(입력 → NLP → Knowledge Graph → AI Tutor → 피드백)을 그린다.
WhyMath 정본은 그 자리를 **세 가지로 분산 대체**한다:

| 틀이 NLP에 맡기는 것 | WhyMath 정본의 대체 | 근거 |
|---|---|---|
| 자유 텍스트 이해 | **입력 UX 유도** — MathLive·구조화 입력 | `05_interaction.md:97` "각 단계는 드롭다운·검색·탭 위주 — **자유 입력 최소화**" |
| 풀이 의미 파악 | **결정론 검증** — SymPy 3상태 (이해하지 않고 *검증*한다) | `l3/verify_step.py` · `l3/symbolic_equivalence.py` |
| 텍스트 단계 분해 | **OCR 공간정보** — bbox 읽기순 | `04a_wh1_tutoring_harness.md:605` "분해는 L5(OCR·공간정보) 책임" |

결정적 근거는 2026-07-19 라이브 재측정이다(`MEMORY.md` 결정 로그). 자유 텍스트 풀이의
미검증률 89%를 실측한 뒤, 해법으로 채택된 것은 **NLP가 아니라 입력 UX**였다(`S3-05` 입력 UX
배칭·`S3-06` 자연 표기 verify·`MOB-06/07` MathLive). 즉 "학생이 자유롭게 쓴 것을 이해한다"가
아니라 "학생이 검증 가능한 모양으로 쓰게 한다"가 정본의 전략이다.

**따라서 이 문서는 "NLU가 없다"를 갭으로 세지 않는다.** 그건 §2의 미채택이거나 §5의 유보다.
갭은 **대체 전략 자체가 뚫린 지점**에서만 성립하며, D1~D4는 전부 그 지점이다.

## §3. 진짜 갭 설계

### D1 — OCR이 학생에게 도달한 적이 없다: 배포 경로 양쪽 비활성 (최우선·`NLP-01`)

**문제**: 기능 69는 코드로 **완결**이다 — 4단 파이프라인(검출·라우팅·인식·조립)·`POST /v1/ocr`·
다중 페이지·핸드오프 정전 구현·모바일 촬영 화면·채팅에서의 진입 버튼까지. 그런데 **두 배포
경로 어느 쪽으로도 학생에게 닿지 않는다.**

| 배포 경로 | OCR 상태 | 실측 근거 |
|---|---|---|
| 컨테이너 | **구조적 불가** | `Dockerfile:43` — "[dev]·[embedding]·**[ocr]** extra는 설치하지 않는다 — 런타임 불요(torch 수 GB)". 즉 검출기·인식기 의존 자체가 이미지에 없다 |
| 네이티브(데모·파일럿) | **OFF** | `scripts/demo/run_demo.ps1`에 `WHYMATH_OCR_*` **0건** + `config.py:1005` `ocr_enabled=False`(기본) |
| (참고) systemd 템플릿 | ON | `infra/phaiakes9/systemd/whymath.env.example:27` — 그러나 **파일럿 런처가 아니다** |

`docker-compose.pilot.yml`은 **DB만** 띄운다(파일럿 API는 네이티브 `run_demo.ps1`). 따라서 S3-01
파일럿 학생이 사진 풀이 버튼을 누르면 `/v1/ocr` → **503**이다.

**왜 아무도 몰랐는가 — 변별력 없는 실패**: `ocr_controller.dart:71-74`가 503(비활성)·401(미인증)·
422(이미지 누락)·네트워크 실패를 **전부 같은 문구**(`"풀이를 인식하지 못했어요. 잠시 후 다시
시도해 주세요."`)로 graceful 처리한다. 학생에게도 운영자에게도 **"기능이 꺼져 있음"과 "인식에
실패함"이 무변별**이다. CLAUDE.md "변별력 없는 검증 스텝 금지"(2026-07-17 등재)의 **런타임 판**이다 —
성공/실패 양쪽에서 같은 값을 내는 것은 검증이 아니라 위장이라는 규칙이, 검증 스텝이 아니라
*사용자 대면 실패 경로*에서 되풀이됐다.

**핵심 판단 (Kiki 결정, 2026-07-31)**: 이번 범위는 **가시화까지**다. 활성화는 하지 않는다 —
모델 자산 다운로드·Phaiakes9 라이브 검증(실모델·정확도 목표 90%)이 선행 조건이고, 지금 필요한
것은 **"꺼져 있음이 보이는 것"**이다. 켜는 절차는 §5-①에 남긴다.

**정합 설계** (신규 스키마 0 · 모델 0 · 활성화 0)
- **① 503 사유 분리**: 비활성(`ocr_enabled=False`)과 부품 적재 실패(import·모델 자산 부재)를 서로
  다른 기계 판독 사유 코드로 낸다. 적재 실패는 **예외 타입명을 로그에 포함**(시크릿·필드값 제외 —
  침묵 실패 금지).
- **② 클라 문구 분기**: 모바일이 비활성과 인식 실패를 다른 문구로 표시한다.
- **③ 도달 관측**: 요청·성공·503(사유별) 카운트를 리포트에 노출한다. **미활성일 때 "0건 통과"가
  아니라 "미활성"으로 표시**된다(`ops/cost_probe` 이중 회계 선례 — 인프라가 죽으면 "측정 실패"가
  보여야지 "0건 통과"로 위장되면 안 된다).

**dead code 금지 충족**: 신규 테이블 0. 인식기·파이프라인은 이미 실재 — 배선·관측만 추가한다.
**측정 없는 도입 없음**: 도달 카운터가 0이면 0으로 보인다(현재는 **아무것도 안 보인다**).
**변별력**: 비활성 상태와 적재 실패 상태가 서로 다른 값을 내는지 실측한다 — 같은 값이면 이 설계
자체가 실패다.

**acceptance 후보**
1. 파일럿 런처 서버에서 `/v1/ocr` 503 재현 + 컨테이너 경로 extra 미설치 확인(주장 확인 또는 반증).
2. 두 사유 코드가 서로 다른 값을 냄 + 적재 실패 로그에 예외 타입명 포함.
3. 모바일 문구 분기를 위젯 테스트로 동결 + 도달 리포트가 CI에서 **실제로 실행**되는지 확인
   (OPS-03·OPS-10 — "저장소에 존재함"과 "돌아감"은 다르다).

**의존**: 없음(즉시 착수). **태스크**: 신설 — `NLP-01-ocr-reachability-observability`.

### D2 — 답안은 적재되는데 채점 권위는 클라이언트에 있다 (`NLP-02`)

**문제**: `POST /v1/me/attempts`가 `is_correct: bool`을 **클라이언트 보고**로 받아 그대로 BKT·
스킬 숙달 전파를 구동한다. `api/me.py:585`가 스스로 자인한다 — *"v1: `is_correct`는 **클라이언트
보고**(서버측 답안 채점[OCR·answer-check]은 L3/L5 후속)."* 즉 **학습자 모델 전체가 검증되지 않은
클라이언트 불리언 위에 서 있다.**

**핵심 판단 — 재료가 이미 다 있다. 잇는 선만 없다.**

| 재료 | 실재 위치 | 상태 |
|---|---|---|
| 학생 답안 원문 | `api/me.py:593` 요청 슬롯 → `me.py:671` → `db/models/activity.py:176` `problem_attempt.student_answer` | **이미 받고 이미 적재된다** |
| 검산기 | `l3/verify_answer.py`(3상태 pass/fail/unverifiable) · `POST /v1/verify-answer` | **이미 완성** |
| 소비 | — | **0** |

`MEMORY.md`에 "서버측 답안 채점"이 **3회 반복 명시된 미착수 후속**인데 백로그 태스크는 **0건**
이었다(전수 확인). 반복 기록은 우선순위가 아니라 **망각의 증거**다.

**핵심 판단 (Kiki 결정, 2026-07-31)**: **이중 회계 관측 먼저.** 서버 검산을 파생하되 BKT 입력은
당분간 클라 보고를 유지하고, **불일치율만 측정**한다. "클라이언트를 믿어도 되는가"를 데이터로
판단한 뒤 권위를 옮긴다 — CLAUDE.md "측정 없는 도입 없음"에 정합. 권위 이관 조건은 §5-②.

**정합 설계** (신규 컬럼 0 · 신규 테이블 0)
- `student_answer`가 있고 문항이 검산 가능하면(`conditions`·`answer_map` 보유) 서버가
  `verify_answer`로 3상태를 파생한다.
- **`unverifiable`을 오답으로 강등하지 않는다** — 판정 불가는 판정 불가다(교수학 금기: 부정적
  피드백의 정서적 강화 금지 + "모르면 모른다고").
- 불일치는 `client_grade_mismatch`로 **반드시 관측**한다(침묵 실패 금지).
- `ARCH-12`(QuizMode 클라 채점 = 데모 예외) 결정의 강제 트리거("학생 노출 경로 진입 시 백엔드
  verify 리팩터 강제")와 **같은 축**이므로 그 결정과 정합을 맞춘다.

**dead code 금지 충족**: 기존 슬롯 `student_answer`의 **소비 0을 해소**한다(신규 좌석 0).
**측정 없는 도입 없음**: 불일치율 + `unverifiable` 비율을 노출한다 — 후자가 곧 이 기능의 **실효
커버리지**이며, 낮으면 권위 이관을 해선 안 된다는 신호다.
**변별력**: 의도적으로 어긋난 `is_correct`를 주입해 카운터가 실제로 오르는지 실측 → 복원해 정상
동작 실측.

**acceptance 후보**
1. 검산 가능 문항에서 3상태 파생 + `unverifiable`이 오답으로 새지 않음(회귀 동결).
2. 불일치 리포트가 **"검산 가능 표본 N건 중 M건"**으로 표시(분모 없는 0 금지).
3. **BKT 입력 경로 불변**을 테스트로 동결(이번 슬라이스는 관측만 — 권위 이관 아님).

**의존**: 없음. **태스크**: 신설 — `NLP-02-server-answer-grading-shadow`.

### D3 — 단계 분해 규약이 코어에 없고 클라마다 재구현된다 (`NLP-03`)

**문제**: `api/verify.py:8-10`과 `04a:605`가 "텍스트→단계 분해는 **L5(OCR·공간정보) 책임**"이라
넘긴다. 그런데 L5 `assemble.py`가 하는 것은 **이미지 bbox 읽기순 정렬**이다 — 텍스트 입력에는
적용되지 않는다. 실제 텍스트 분해는 **Flutter 클라이언트**에 있다(`chat_controller.dart:84`
`_splitSteps` — 개행 분해).

**먼저 반증한 것**: 이건 "클라가 수학을 한다"(슬라이스 89 위반)가 **아니다.** 해당 주석이
*"수학 검증·단계 의미 추론은 절대 하지 않는다"*고 못 박고 있고 실제로 줄 분해만 한다. 정직하게
severity를 내린다. 진짜 문제는 다른 셋이다:

1. **규약이 코어에 없다** — 웹·PDF·타 클라는 각자 재구현해야 한다. 같은 파일 계열의
   `api/ocr_handoff.py`는 **"정전(canonical) 구현"을 백엔드에 두고 클라가 미러링**하는데,
   **텍스트 경로만 정본이 없다.**
2. **드리프트가 이미 자인돼 있다** — `latex_to_plain.dart:13`이 백엔드
   `l5/ocr/verify.py _latex_to_sympifiable`를 미러링한다고 주석으로 선언한다(동기화 장치 없음).
   그리고 실제로 터졌다: MathLive의 `\displaylines{}` 행 구분자 `\\`가 `'\n'` 분해에 걸리지 않아
   **단일 0-전이 스텝**이 되어 verify가 미결정한 2026-07-20 실기기 사고.
3. **분해 책임이 학생에게 전가된다** — "한 줄에 한 단계씩" 적어야 검증받는데, 이 규약은 어디에도
   학생에게 고지되지 않는다.

**정합 설계** (LLM 0)
- 분해 규약을 **`data/` 계약 JSON + 백엔드 순수 함수**로 정본화하고, **`notation_contract.json`
  선례를 그대로 따른다** — 백엔드 pytest와 클라 테스트가 *같은 파일*을 읽는 교차 골든 게이트
  (`tests/backend/l3/test_notation_contract.py` ↔ `src/web/graphing-calculator/test/notation_contract.test.js`).
- **LLM 분해는 명시적 미채택**: `verify.py`가 든 사유(방정식 풀이와 변형 체인 혼동 → **거짓
  incorrect**)가 그대로 유효하다. 분해는 **형태 판별**이지 **의미 이해**가 아니어야 한다 — 이것이
  이 모듈에서 NLU를 들이지 않는 이유의 가장 구체적인 사례다.
- 분해 불가·모호는 **fail-closed 보류**(`unverifiable` 사유 기록)한다. 조용히 1스텝으로 뭉개서
  0-전이를 만들지 않는다(2026-07-20 재발 방지).

**dead code 금지 충족**: 계약 + 순수 함수 + 클라 함수의 **이관**(추가가 아니라 대체).
**측정 없는 도입 없음**: 0-전이 제출 비율을 노출한다 — 분해가 실패하는 실사용 빈도가 곧 이
계약의 필요성 근거다.

**acceptance 후보**
1. 계약 JSON 1개를 백엔드·모바일 테스트가 **동시에** 읽어 동일 판정(교차 골든).
2. `\displaylines` 다행 입력이 0-전이로 뭉개지지 않음(2026-07-20 회귀 동결).
3. 분해 보류가 `unverifiable` 사유로 관측됨(침묵 실패 0).

**의존**: 없음(D2와 독립). 현재 실동작 중이므로 **S4**(긴급 아님).
**태스크**: 신설 — `NLP-03-solution-segmentation-contract`.

## §4. 정직한 공백 — 지금 하지 않는 것 (7종)

1. **키워드 화이트리스트의 커버리지를 측정하지 않는다** — `select.py`의 2조 토큰, `transitions.py`의

   §5-③의 발화 조건이 그 측정을 포함하기 때문이다(중복 등재 회피).
2. **논리 오류·증명 오류를 유형화하지 않는다** — 현행은 "계산 오류 있음/없음" 1비트 + `unverifiable`
   (판정 안 함)뿐이다. 유형화는 PRM 모델이 실재해야 의미가 있다(§2-③).
3. **`NLP_TASK_TYPES`의 `classify` 상수는 호출자가 0이다** — 라우터에 좌석은 있으나 쓰는 코드가
   없다. 지금 지우지 않는다(§5-③이 발화하면 첫 소비자가 된다). **다만 dead 상태임을 여기 기록**해
   둔다 — 기록 없는 미사용 상수가 다음 세션에 "이미 되는 것"으로 오독되는 것이 이 프로젝트의
   반복 실수다.
4. **OCR 라이브 정확도가 미검증이다** — 목표 90%(PRD §12.3)에 대한 Phaiakes9 실모델 측정이
   아직 없다. D1은 이 측정을 **하지 않는다**(가시화만).
5. **`student_answer`의 PII 취급을 이번에 바꾸지 않는다** — 미성년 풀이 원문이므로 D2가 로그·
   리포트에 **값을 싣지 않는다**(카운트만). 봉투 암호화 확대 여부는 SEC 축의 판단이다.
6. **음성 입력(STT)은 대조 대상이 아니다** — 정본의 `speech`는 출력(Math-to-Speech·결정론 규칙
   엔진·LLM 0)이며 틀의 40개 세부에도 STT는 없다.
7. **`05_interaction.md`의 대화 파이프라인 의사코드를 개정하지 않는다** — 거기엔 NLP 단계가
   없고(학생 입력 → 바로 L4 pedagogy decision), 그건 §0-①-b대로 **정확한 서술**이다. 틀에 맞춰
   NLP 박스를 그려 넣는 것은 없는 계층을 문서에 만드는 일이다.

## §6. 반복 실수 — "완비된 소비 경로 + 미도달 공급원" 3회차 (재발방지 등재)

| 회차 | 사례 | 형태 |
|---|---|---|
| 1 | `tests/infra` 199건이 어떤 잡도 실행하지 않음(OPS-03) | 만들고 **CI에 배선 안 함** |
| 2 | 전 시각화 스택 학생 도달 0회(VIZ-01) | 만들고 **적재 안 함** |
| 3 | **OCR 전 파이프라인이 배포 경로 양쪽에서 비활성**(D1) | 만들고 **배포에 넣지 않음** |

공통 구조는 하나다: **소비측이 완비돼 있어서 "존재함"이 "돌아감"으로 읽힌다.** 엔드포인트가 있고,
클라 버튼이 있고, 테스트 파일이 있다. 그래서 공급측(배포·적재·잡 배선)의 부재가 보이지 않는다.
그리고 3회 전부 **graceful 실패**가 증상을 덮었다.

CLAUDE.md에 이미 있는 규칙 — *"검증 장치를 만들고 배선 확인 없이 완료 선언 금지"* — 은 **검증
장치**에 한정돼 있다. 이번 사례는 검증 장치가 아니라 **학생 대면 기능**이었다. 이 규칙을
**런타임 기능 일반으로 확장**하고, 판정 기준을 "코드가 있는가"가 아니라 **"학생에게 닿는 경로가
실측되는가"**로 두는 것을 제안한다. D1의 도달 카운터가 그 판정을 기계화하는 첫 사례다.
