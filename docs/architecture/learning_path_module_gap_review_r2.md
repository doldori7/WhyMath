## §0. 재점검 사유 — 왜 v1을 덮어쓰지 않고 r2를 새로 쓰는가

### ① 확장 제안 58~62가 merged 정본에 한 번도 대조된 적이 없다

첨부 docx는 기능 54~57 뒤에 「WhyMath 관점의 확장 제안」으로 후보 5건(58~62)을 더 싣는다.
v1은 이것을 다루지 않았다 — 범위 블록인용이 "4모듈"로 못박혀 있고, 본문 전수 grep에서
`적응형|일정 최적화|목표 추적|추천 엔진|시뮬레이션|기능 5[89]|기능 6[0-2]|확장 제안|확장 후보`가
**0건**이다(부록 A).

이는 v1의 누락이라기보다 **사고의 흔적**이다. 같은 날 두 세션이 같은 docx를 독립적으로 대조했고
(`MEMORY.md:1598-1625`), 파일 경로가 충돌해 한쪽이 **설계 전량을 회수**했다. 회수된 쪽
(커밋 `85981e97`, 트렁크 미도달)이 바로 58~62를 대조한 쪽이었다. 그 판정은 **git에는 있으나
어떤 정본에도 없다.**

### ② 회수된 판정은 승계 대상이지 재도출 대상이 아니다

`85981e97`의 확장 제안 판정은 실측에 근거했고 지금도 유효하다. 이 문서는 그것을 **재litigate하지
않고 승계**한다(§1 표의 「판정」 열에 출처를 명기). 특히:

- **58**은 "경로는 상태가 아니라 파생 — 영속 슬롯 소생은 **이중 진실원천**"으로 **판정 종결**됐다.
- **59·62**는 불채택, **60**은 `S4-18` 선점.

회수된 세션이 도달한 결론을 다시 계산하는 것은 같은 토큰을 두 번 쓰는 일이고, 더 나쁘게는
**다른 결론이 나오면 정본이 두 벌 생긴다**.

### ③ v1 이후 착지 6건이 지형을 바꿨다

### §1 종합 — 확장 제안발 신규 태스크 **0건**

5건 중 **셋(58·59·62)은 미채택**, **하나(60)는 이미 착지**, **하나(61)는 절반 착지 + 절반
저작권 레일 차단**이다. 외부 틀이 "더 강력한 Path Engine"으로 제안한 5축 중 WhyMath가 **하지
않기로 결정한 것이 3축**이라는 사실 자체가 이 대조의 산출물이다 — 미구현이 아니라 결정이다.

**그래서 이 문서의 갭은 확장 제안이 아니라 다른 데서 나온다.** v1이 설계한 것들이 착지하면서
생긴 **이음매**다(§3).

### (횡단) 틀의 「학습 경로 재최적화」 순환 다이어그램 대조

틀은 `진단 → 수준분석 → 경로생성 → 학습수행 → 평가·오개념분석 → **경로 자동 수정** → (반복)`
선순환을 그리고 이것을 "WhyMath의 차별화 포인트"라 부른다. 실측 대조:

| 단계 | 실재 | 비고 |
|---|---|---|
| 진단 → 수준분석 | ✅ | `concept_diagnosis.py` BKT×IRT 교차검증 |
| 경로 생성 | ✅ | `l2/learning_path.py` Kahn |
| 학습 수행 | ⚠️ | 서버 좌석(`POST /v1/me/attempts`)은 완비, **클라가 호출하지 않는다**(`src/mobile/lib/` 전수 `me/attempts` **0건**) |
| 평가·오개념 분석 | ✅ | `l4/misconception/*` · `ASM-03` capture |
| 경로 자동 수정 | ✅(파생) | 영속 plan이 없어 **매 조회가 곧 재최적화**다(§1-58) |

즉 **순환은 끊어져 있지 않고, 한 마디(학습 수행 → 서버)의 클라 배선이 없을 뿐**이다.
그 마디는 이 문서 소관이 아니다 — `REC-01`이 가시화했고 공급측 태스크가 소유한다.
**이 문서는 그 마디를 다시 설계하지 않는다.**

## §3. 잔여 갭 설계 (D4~D6)

번호는 v1의 D1~D3을 잇는다(`gamification_module_gap_review_r2.md`가 D5~D7로 이은 선례).

### D4 — 정렬 정직 표기가 **영속 경계**에서 소실 (`PATH-09`)

**문제**: `POST /v1/me/assessments/capture`(`api/me.py:2614-2620`)가 학습 경로를 이렇게 저장한다:

```python
path = await build_learning_path(session, gaps)
recommended_path_items = [step.model_dump(mode="json") for step in path.steps]
```

**`path.steps`만 꺼낸다.** `ordering_basis`·`ordering_edge_count`·`has_cycle`은 부모
`LearningPath`의 필드이므로(`l2/learning_path.py:132-145`) **통째로 버려진다.**
그리고 이 값은 학생이 다시 읽는다 — `StudentAssessment.recommended_path`
(`schema/assessment.py:145`)는 **학생 대면 정본**이고 `GET /v1/me/assessments`
(`api/me.py:423`, `response_model=list[StudentAssessmentSchema]`)가 그대로 반환한다.

결과: **학생은 96.4%의 확률로 "제약 없이 tiebreak로만 정해진 순서"를 「권장 학습 경로」라는
이름으로 다시 읽는데, 그 사실을 알 방법이 없다.** 실시간 엔드포인트는 `PATH-02` 덕에 정직한데
**영속 스냅샷은 정직하지 않다.** 같은 사실에 대해 두 표면이 다른 말을 한다.

**비대칭이 결정적 증거다.** 두 정직 표기의 운명이 갈린다:

| 표기 | 소속 모델 | 영속 생존 | 실제 발생률 |
|---|---|---|---|
| `is_cycle_residual` | `LearningStep`(자식) | **생존** | **0%** — 원자 백본은 DAG 보장(`validate.py` `prerequisite_cycle` hard error) |
| `ordering_basis` | `LearningPath`(부모) | **소실** | **96.4%가 `tiebreak_only`**(v1 §0-① 전수 실측) |

**살아남은 쪽은 한 번도 발생하지 않는 축이고, 죽은 쪽은 96.4%인 축이다.**
이것은 우연이지 설계가 아니다 — `model_dump()`를 자식에 걸었느냐 부모에 걸었느냐가 갈랐다.

**왜 지금까지 안 드러났는가** (두 겹의 무증상):
1. `PATH-02`는 **자기 엔드포인트 응답**만 변별력 있게 검증했다. 그 필드가 다른 좌석을 통해
   영속화된다는 사실은 `PATH-02`의 시야 밖이었다.
2. `ASM-03`은 v1 P3("writer가 reader보다 먼저 가지 않는다")을 **참조하지 않았다.** P3은
   v1 문서 안에만 있었고 **기계가 읽는 곳(테스트·계약)에 없었다.** 산문 규칙은 다른 태스크를
   막지 못한다 — CLAUDE.md "정본화를 집행으로 착각한 완료 선언 금지"(2026-08-04)의
   *문서 축* 변형이다.

**정합 설계 (신규 컬럼 0 · 마이그레이션 0 · DB 스키마 변경 0 · LLM 0 · 네트워크 0)**:
`recommended_path`는 JSONB 배열이므로 컬럼을 늘리지 않고 담을 수 있다. `capture` 좌석이
**이미 손에 들고 있는** `path` 객체에서 파생만 한다 — `build_learning_path`를 다시 부르지
않는다. 각 step dict에 정렬 근거를 동반 기록하거나(배열 원소 자체가 자기 근거를 갖게 함),
경로 전체에 1회 기록하는 헤더 원소를 둔다. **어느 형태든 "빈 배열"과 "tiebreak_only 배열"과
"topological 배열" 셋이 판독 가능해야 한다.**

재사용 좌석: `l2/learning_path.py`의 `LearningPath` 모델(그대로 읽기) ·
`api/me.py`의 기존 `capture` 조립 경로. **새 함수 신설 최소화.**

**변별력**: `steps` 튜플이 **완전히 동일**하고 `ordering_basis`만 다른 fixture 2종을 구성해,
영속 산출물이 두 경우를 **구별하는지** assert한다. 구별하지 못하면 실패다.
(v1 D2가 "변별력(이번 리뷰 최대 핵심)"으로 세운 것과 같은 형태 — 성공/실패 양쪽에서 같은
값을 내는 검사는 검증이 아니라 위장이다.)

**하지 말 것**:
- 새 컬럼·마이그레이션 신설 — v1 §2-④ 이중 진실원천. JSONB 안에서 끝낸다.
- 예측 5필드(`estimated_grade`/`estimated_score`/`estimated_percentile`/
  `target_university_id`/`admission_probability`) 접근 — `ASM-07` 봉인 소관.
- `LearningPath` 재계산 — 이미 있는 객체에서 파생만.
- 과거 행 백필 — writer 0행 시절 데이터가 없다(`assessment_seat_reach_report.py`가 실측 소유).

**acceptance 후보**:
1. **현행 실측 고정** — `capture`가 저장한 `recommended_path`에서 정렬 근거를 복원할 수 없음을 재현하는 테스트를 먼저 세운다(결함 재현).
2. **정합 설계 본체** — `capture` 좌석이 `path.ordering_basis`·`ordering_edge_count`·`has_cycle`을 `recommended_path` JSONB 안에 동반 기록한다. 신규 컬럼·마이그레이션 **0**을 리뷰 게이트로 확인한다.
3. **변별력** — `steps`가 완전히 동일하고 `ordering_basis`만 다른 fixture 2종에서 영속 산출물이 갈리는지 assert한다. 갈리지 않으면 실패다.
4. **계약 안정·날조 방지** — 정렬 근거는 `build_learning_path`가 산출한 값을 **그대로** 옮길 뿐 재계산·보정하지 않는다. `LearningPath` 재호출 0을 확인한다.
5. **노출 정합** — `GET /v1/me/assessments`(`StudentAssessment`) 응답에서도 그 근거가 판독 가능함을 확인하고, 예측 5필드가 여전히 응답 스키마에 부재함을 회귀로 동결한다.
6. **범위 밖 명시** — 과거 행 백필 · 신규 컬럼 · 모바일 렌더(D5 태스크 소관) · `PATH-03` 전이 엣지 · 전역 경로는 이 태스크 범위 밖이다.

**의존**: 없음(`PATH-02`·`ASM-03` 착지분 위에서 바로 가능).
**태스크**: 신설 — `PATH-09`(S3 · priority 3 · layer=backend).

### D5 — 정렬 정직 표기가 **렌더 경계**에서 소실 (`PATH-10`)

**문제**: Flutter는 이 필드들을 **파싱한다** —
`src/mobile/lib/features/problems/data/problem_models.dart:248,251`:

```dart
@JsonKey(name: 'ordering_edge_count') @Default(0) int orderingEdgeCount,
@JsonKey(name: 'ordering_basis') @Default('empty') String orderingBasis,
```

그런데 `src/mobile/lib/` 전역에서 이 두 필드를 **읽는 위젯이 0개**다. 전수 grep 결과
참조는 위 2줄이 전부다(부록 B). 값은 네트워크를 건너 freezed 모델까지 도달한 뒤
**화면 직전에서 멈춘다.**

**같은 화면이 다른 정직 신호는 렌더한다** — 이게 이 갭의 성격을 확정한다.
`me_screen.dart` `_LearningPathSection._buildLoaded`는:

- `steps.isEmpty` → "지금은 특별히 복습할 막힌 선수개념이 없어요"(정상 결과임을 명시)
- `path.hasCycle` → 경고 아이콘 + "일부 순서는 참고용으로만 표시돼요" —
  주석까지 달려 있다: `// 서버 정직 신호: has_cycle — 삼키지 않고 그대로 알린다`
- `step.isCycleResidual` → "순환 잔여 단계"

**세 개를 렌더하면서 `orderingBasis`만 렌더하지 않는다.** 그리고 D4와 **똑같이**, 렌더된
`hasCycle`은 발생률 **0%**이고 렌더되지 않은 `tiebreak_only`는 **96.4%**다.
학생이 실제로 보게 되는 유일한 화면에서, **거의 항상 참인 사실만 표시되지 않는다.**

**왜 지금까지 안 드러났는가**: `PATH-05`는 회수 브랜치(`85981e97` D3)를 재작성해 착지했는데,
원본 D3의 조항 **"`has_cycle`·transitive 절단 표시 등 서버의 정직 신호를 삼키지 않고 노출한다"**
중 `has_cycle`만 승계됐다. `ordering_basis`는 `PATH-02`가 나중에 만든 필드라 회수 브랜치의
문장에 이름이 없었고, 재작성 시점에 **이름으로 열거되지 않은 것은 옮겨지지 않았다.**
선례 동형: `gamification_module_gap_review_r2.md` D6 — **"네트워크 갭이 아니라 렌더 갭"**.

**정합 설계 (네트워크 호출 추가 0 · 신규 상태 0 · 신규 API 0)**:
`_LearningPathSection._buildLoaded`에 `hasCycle` 배너와 **동형의** 표기를 하나 더 둔다 —
`orderingBasis == 'tiebreak_only'`일 때 "이 순서는 선수관계 제약이 없어 **참고용**"이라는
취지의 **중립 문구**. 이미 있는 `_MessageRow(dense: true)`를 재사용한다.

**어조 제약 (교수학)**: 문구는 학생의 결손·부족을 지적하지 않는다. 말하는 대상은 **데이터의
한계**이지 학생이 아니다. CLAUDE.md "부정적 피드백을 정서적으로 강화하는 표현 금지".

**반게임화 선 긋기**: `docs/design/ui/00_index.md` 전역 UI 불변식 2는 **"정답률 랭킹·스트릭·
카운트다운·보상 연출 금지. 학습 경로 시각화는 **허용**"**이다. 이 태스크는 허용의 경계 **안쪽**에
있지만, 진척 UI는 게임화로 미끄러지기 쉬운 표면이므로 **허용을 받은 자리에서 바로 선을 긋는다** —
랭킹·스트릭·카운트다운·보상 연출이 **0임을 테스트로 동결**한다(회수 브랜치 D3의 조항 승계).

**변별력**: `orderingBasis`가 `'topological'`인 상태와 `'tiebreak_only'`인 상태에서
**위젯 트리의 텍스트가 실제로 달라지는지** widget test로 확인한다. 두 상태에서 같은 화면이
나오면 실패다.

**하지 말 것**:
- 서버 응답 형태 변경 — 이 태스크는 `src/backend` **0줄**이다.
- `orderingEdgeCount` 숫자를 학생에게 그대로 노출 — 계측 수치는 학생 대면 정보가 아니다.
  판단은 `orderingBasis` 라벨로만 한다.
- 순서에 "신뢰도 점수"류 파생 지표 신설 — 날조.

**acceptance 후보**:
1. **현행 실측 고정** — `orderingBasis`가 `tiebreak_only`여도 화면 텍스트가 `topological`일 때와 동일함을 재현하는 widget test를 먼저 세운다(결함 재현).
2. **정합 설계 본체** — `_LearningPathSection`이 `tiebreak_only`일 때 `hasCycle` 배너와 동형의 중립 문구를 표기한다. 신규 API 호출·신규 상태 **0**.
3. **변별력** — 두 `orderingBasis` 값에서 위젯 트리 텍스트가 갈리는지 assert한다. 갈리지 않으면 실패다.
4. **어조·반게임화 동결** — 문구가 학생의 부족이 아니라 데이터 한계를 말함을 확인하고, 랭킹·스트릭·카운트다운·보상 연출이 이 섹션에 **0**임을 테스트로 동결한다(전역 UI 불변식 2).
5. **정직 신호 전수 확인** — `steps.isEmpty`·`hasCycle`·`isCycleResidual`·`orderingBasis` **네 신호가 모두** 화면에 도달함을 한 테스트에서 확인한다(다음 재작성에서 또 하나가 누락되지 않도록).
6. **범위 밖 명시** — 서버 응답 변경 · `orderingEdgeCount` 숫자 노출 · 영속 스냅샷(D4 태스크 소관) · 완주율/진척률 UI · 전역 경로 화면은 이 태스크 범위 밖이다.

**의존**: 없음(`PATH-05` 착지분 위에서 바로 가능). D4와 **독립**이다 — 두 경계는 서로를
경유하지 않는다.
**태스크**: 신설 — `PATH-10`(S3 · priority 3 · **layer=mobile**).

### D6 — v1 유보 발화조건의 **계측기가 착지하지 않았고 소유자가 없다** (`PATH-11`)

**문제**: v1 §5는 학생 **전역 학습 경로**(기능 54의 핵심)를 4조건 AND로 유보하면서, 조건 ③을
이렇게 썼다:

> ③ `PATH-01` 리포트가 **다중 약개념 교차 집합**의 제약 밀도를 산출하고, 전역 병합이 개념별
> 나열보다 **순서를 더 결정한다**는 수치를 낼 것
> […] **이 측정은 `PATH-01` 리포트의 축 하나 추가로 가능**하므로 유보 결정에 별도 비용이 들지 않는다.

`PATH-01`은 **done**이다. 그런데 `OrderabilityReport`
(`harness/learning_path_orderability_report.py:411-424`)의 필드는
`corpus_concept_total` · `corpus_edge_total` · `direct_predecessor_distribution` ·
`population_size` · `cells`(깊이 × 축 그리드)뿐이고, `_summarize`는 **개념 하나씩**
(`for code in population_codes`) 평가한다. **다중 약개념 교차 집합 축이 없다**(부록 C).

**규칙 위반의 형태**: CLAUDE.md **"만료 없는 유예·제외 금지"**(2026-08-03 등재) —
"유예·제외는 반드시 만료 또는 재확인 지점을 동반한다". v1은 조건은 달았으나, 그 조건을
**측정할 수단을 아무도 소유하지 않는 상태**로 남겼다. "`PATH-01` 확장으로 가능"은 **예측이지
소유가 아니다.** 그 결과 전역 경로 유보는 지금 **해제될 수도 영구화될 수도 없는** 상태다.

이것은 v1의 §6과도 맞물린다 — v1은 "docstring 속 계획은 백로그를 대신하지 못한다"를 인접
사례로 관찰했는데, **v1 자신이 산문 속 계획으로 같은 일을 했다.**

**정합 설계 (신규 쿼리 0 · DB 접근 0 · LLM 0 · 네트워크 0 · 코퍼스 읽기 전용)**:
`build_report`에 **축 하나**를 추가한다 — 약개념 k개(k = 2, 3, 5)를 결정론적으로 표집한
집합의 **합집합**에 대해 제약 밀도·결정도를 산출하고, **같은 개념들을 개별로 처리했을 때와
비교**한다. 핵심 질문은 하나다: **병합이 순서를 더 결정하는가?**

재사용 좌석: `order_learning_path`를 **그대로 재호출**하고 Kahn 루프·`_tiebreak` 비교자를
재구현하지 않는다(`PATH-01`이 확립한 규율 — `learning_path_orderability_report.py:281`).
표집은 `_concept_id_for_code`와 같은 **결정론적 매핑**을 써 교차 실행 재현성을 지킨다
(`Math.random` 금지 — 재현성).

**이 태스크는 전역 경로를 만들지 않는다.** 만들 근거가 있는지 **측정만** 한다.
`build_learning_path`·엔드포인트·응답 스키마 **전부 무변경**이다.

**판정으로 이어지는 설계**: 결과는 둘 중 하나로 착지한다.
- 병합이 순서를 **유의미하게 더 결정한다** → v1 §5 조건 ③ **충족**(나머지 3조건은 그대로).
- 병합이 순서를 **더 결정하지 못한다** → 전역 경로는 **순수한 복잡도 증가**임이 측정으로
  확정되고, 유보는 **영구 미채택으로 승격**된다(§5로 이관).
**어느 쪽이든 결론이 난다** — 그게 이 태스크의 존재 이유다.

**상한 정직 표기**: `PATH-01`이 이미 못박은 구조적 상한을 승계한다 — 모든 비율은
`weak_only=True` 필터 **이전**의 코퍼스 구조 상한이며 실측 런타임 비율은 그 **이하**다.
**진짜 병렬 집합이 존재하므로 100%는 목표가 아니다.**

**변별력**: 교차 밀도가 높은 합성 그래프와 낮은 합성 그래프 2종에서 산출 수치가
**실제로 갈리는지** 확인한다. 두 그래프에서 같은 값이 나오면 그 축은 아무것도 재지 않는 것이다.

**하지 말 것**:
- 전역 경로 **구현** — 4조건 AND 중 ①(입력 루프)이 여전히 미충족이다. 측정만 한다.
- 실 DB 접근 — `PATH-01`과 같이 코퍼스 파일만 읽는다(입력 루프와 무관하게 즉시 착수 가능한 이유).
- 표집을 난수로 — 재현성이 깨진다.
- 결과를 근거로 이 태스크 안에서 유보를 해제 — 판정은 별도 결정이다.

**acceptance 후보**:
1. **현행 실측 고정** — `OrderabilityReport`에 다중 약개념 교차 집합 축이 부재함을 재현하는 테스트를 먼저 세운다(v1 §5-③이 요구한 수치가 산출 불가임을 고정).

## §9. 반복 실수 — **9회차 (새로운 축)** 등재

v1 §6은 8회차까지의 표를 남겼고 형태는 전부 `만들고 **X하지 않음**`이었다:

| 회차 | 형태 |
|---|---|
| 1~8 | 만들고 **배선 안 함** / **적재 안 함** / **배포에 넣지 않음** / **입력을 잇지 않음** / **켜지 않음** / **공급원을 잇지 않음** / **분해하지 않음** / **기본값으로 껐음** |
| **9(신규)** | **만들고 켰는데, 경계를 넘을 때 흘림** |

**9회차가 새로운 축인 이유**: 1~8은 전부 *한 좌석 안에서* 미완이었다. 이번 것은 **좌석은 완성됐고
정상 작동한다** — `GET /v1/me/weak-concepts/{id}/learning-path`는 `ordering_basis`를 정확히
반환한다. 결함은 그 값이 **다른 좌석으로 건너갈 때** 발생한다(영속 D4 · 렌더 D5).
**두 경계에서 독립적으로, 같은 방식으로 재생산됐다.**

그리고 이번 사례에는 특히 나쁜 성질이 있다 — **살아남은 정직 표기와 죽은 정직 표기의 비대칭**:

| | 발생률 | 영속 | 렌더 |
|---|---|---|---|
| `has_cycle` / `is_cycle_residual` | **0%**(DAG 보장) | 생존 | 생존(주석까지 달림) |
| `ordering_basis = tiebreak_only` | **96.4%** | 소실 | 소실 |

**정직 표기가 한 번도 발생하지 않는 축에만 두 경계를 다 통과했다.** 표면적으로는 "정직 신호를
성실히 다루는 코드"로 보이는데(실제로 주석까지 달려 있다), 실제로 거의 항상 참인 사실만 빠진다.
v1 D2가 진단한 것이 정확히 이 비대칭이었고 `PATH-02`가 응답 계층에서 그것을 고쳤는데,
**한 겹 바깥에서 같은 비대칭이 두 번 재생산됐다.**

**재발방지 형태로 남길 원칙**:

> **정직 표기는 그것을 만든 응답 밖으로 나갈 때 함께 가야 한다.**
> 영속·렌더·재조회 — 어느 경계에서든 표기가 떨어지면 **그 순간부터 침묵 실패**다.
> 그리고 정직 표기를 **여러 개** 내보내는 좌석은, 소비처가 그 **전부**를 다루는지 한 검사에서
> 확인한다 — *일부만* 다루는 소비처는 성실해 **보이기** 때문에 가장 오래 살아남는다.

이 원칙은 CLAUDE.md의 두 기존 금기 사이에 있는 **빈칸**이다 — "침묵 실패 금지"는 *예외를
삼키는 것*을, "정본화를 집행으로 착각한 완료 선언 금지"는 *계약이 서빙 경로에 없는 것*을 막는데,
**계약이 있고 서빙 경로도 있는데 경계에서 필드가 떨어지는 것**은 둘 다 아니다.
**CLAUDE.md 등재 후보로 제안한다** — 다만 헌법 개정은 별도 판단이므로 **이 커밋에서
CLAUDE.md를 고치지 않는다.**

**부수 관찰(태스크 신설 없음)**: `PATH-05`가 회수 브랜치 D3를 재작성하며 정직 신호를
