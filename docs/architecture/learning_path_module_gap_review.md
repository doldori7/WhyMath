## §0. 세 가지 전제 정리

### ① 표기 정리 — "08. 학습 분석"이 아니라 학습 경로(Path)다

제공 파일은 `08.`로 번호되고 요청 문구는 "학습 분석"이었으나, **본문은 전부 학습 경로(Path)**다
(모듈 54~57 + 확장 후보 58~62). 대조 대상은 파일명·요청 문구가 아니라 **본문**으로 잡는다. 따라서
이 문서는 "학습 분석 대시보드"가 아니라 **경로 엔진**의 갭 점검이며, 분석·관측 축은
`REC-01`(추천 도달 관측)이 이미 좌석을 갖고 있어 여기서 다시 열지 않는다.

### ② 착수 가설이 반증됐다 — 경로 엔진은 이미 프로덕션이고, 기능 55는 초과 충족이다

| 문서가 요구하는 것 | WhyMath 현행 | 실측 |
|---|---|---|
| 부족한 선수 개념 자동 탐색 | `l2/prerequisite_recommendation.py:230` `build_prerequisite_stmt` — **SQLAlchemy Core 재귀 CTE**(원시 SQL 0), `max_depth` 1~5 다단계, depth guard가 쿼리 *안*에 있음, 결정론 정렬(depth asc → edge_strength desc nullslast → concept_id) | 483줄 실구현 |
| 학습 순서 생성 | `l2/learning_path.py:143` `order_learning_path` — **Kahn 위상정렬**. 막힌 선수들 *사이*의 선수 의존을 풀어 근본→말단 순서를 낸다 | 271줄 실구현 |
| AI 설명("왜 필요한가") | `l4/prerequisite_coaching.py:32` `recommend_prerequisite_coaching` + `GET /me/weak-concepts/{id}/coaching`(`api/me.py:1446`) | 실구현 |

**초과 지점 둘을 기록해 둔다** — 틀이 요구하지 않았는데 WhyMath가 이미 더 한 것:

1. **문서의 "학습 순서"는 선형 나열인데, WhyMath는 부분순서(partial order)를 푼다.** 문서 55의
   예시(이차방정식→인수분해→다항식 연산→정수 계산)는 *한 줄 사슬*이다. 실제 선수 그래프에서는 두
   선수가 **둘 다 직접 선수(depth=1)인데 그 둘 사이에도 선수 의존이 있는** 경우가 흔하고, depth
   정렬로는 이걸 못 짚는다. `order_learning_path`가 in-degree 0(근본)부터 방출해 이 순서를 낸다 —
   LTHC(기초 우선)의 기계적 구현이다.
2. **사이클을 조용히 버리지 않는다.** Kahn이 전 노드를 방출하지 못하면 잔여를 결정론 순서로
   append하며 `has_cycle`·`is_cycle_residual`로 표시한다(`l2/learning_path.py:101`·`:65`). 누락 0 +
   정직 표시 — CLAUDE.md "환각 발견 시 조용히 넘어가지 말고 로그"의 그래프판이다.

### ③ 더 큰 반증 둘 — 경로에 진입점이 없고, 경로 코퍼스는 추적에서 누락됐다

**(가) 진입점 부재.** 경로·개념 API가 **전부 `concept_id`를 경로 인자로 요구**한다:

| 엔드포인트 | 위치 | 인자 |
|---|---|---|
| `GET /v1/me/weak-concepts/**{concept_id}**/prerequisites` | `api/me.py:1391` | `concept_id` **필수** |
| `GET /v1/me/weak-concepts/**{concept_id}**/coaching` | `api/me.py:1446` | `concept_id` **필수** |
| `GET /v1/me/weak-concepts/**{concept_id}**/learning-path` | `api/me.py:1507` | `concept_id` **필수** |

그런데 **그 `concept_id`를 고르는 조립 좌석이 0**이다. 학생은 "어느 개념부터 시작해야 하는가"를
모르는 상태로 앱에 들어오는데, 경로 API는 그 답을 *이미 알고 있다고 전제*한다. 재료는 **둘 다
실재**한다 — `GET /v1/me/weak-concepts`(`api/me.py:1324`, **무인자**·weakness 정렬·상위 N)와
`build_learning_path`(`l2/learning_path.py:247`). **한 번도 이어 붙인 적이 없을 뿐이다.**

같은 축의 파생 사실 셋:

1. **클라 도달 0회.** Flutter가 실제 호출하는 `/v1/` 엔드포인트는 **13종**(전수 실측·부록)이고 경로
   API는 **0종**이다. 도달하는 L2 표면은 `/v1/me/diagnosis/concepts` 하나뿐이다.
2. **기본 `max_depth=1`.** 세 엔드포인트 전부 기본값이 1이다(`api/me.py:1402`·`:1455`·`:1518`,
   `fetch_prerequisites` 기본 `max_depth=1` — `l2/prerequisite_recommendation.py:285`). 즉 호출되더라도
   문서가 그리는 다단계 연쇄는 **기본값으로 나오지 않는다**. 다홉은 명시 인자를 준 호출자만 본다.
3. **응답이 "왜 비었는지"를 말하지 않는다.** `LearningPath`(`l2/learning_path.py:101`)의 필드는
   `steps`·`has_cycle` **2개뿐**이다. 상류에 `problem_attempt` **0행**(클라가 `POST /v1/me/attempts`
   — `api/me.py:644` — 을 호출하지 않음)이 겹쳐, 경로는 호출돼도 빈 배열을 돌려준다. **"경로가
   없음(=잘 하고 있음)"과 "아직 측정 안 됨"이 같은 모양**이다.

**(나) 경로 코퍼스 677행이 추적에서 통째로 누락됐다.** `docs/data/concept_content_corpus_v1.md`
(2026-06-20 데이터 카드)는 **와이매스 자체 저작** 두 데이터셋을 같이 명세했다:

| 데이터셋 | 규모 | 코퍼스 파일 | 로더 | 백로그 태스크 |
|---|---|---|---|---|
| ③ 7계층 본문(L1_HOOK~L5_META) | 437개념 | ✅ `data/corpus/concept_content_v1/content.json` | ✅ `l1/concept_content/populate.py` | ✅ 착지 |
| ② **7주체 S1~S7 학습경로** | **677행**(초119·중60·고기본34·고일반93·고진로127·재수130·영재114) | ❌ `data/corpus/learning_paths_v1/` **미존재** | ❌ 0 | ❌ **0건** |

**한 데이터 카드의 자매 데이터셋 중 하나만 착지하고, 나머지는 아무도 추적하지 않았다.** 그리고
누락된 쪽이 하필 **이번 대조의 주제 그 자체**다 — 각 행이 소단원별로
`S1 진단게이트 / S2 개념형성 / S3 유도연습 / S4 적응숙련(오개념·시드) / S5 숙달게이트 / S6 확장전이 /
S7 간격복습` 7단계를 **페르소나·트랙별로** 설계해 둔 것이라, 문서 54(개인별 경로)·56(복습)·57(목표)이
요구하는 교수학 설계가 이미 사람 손으로 만들어져 있다는 뜻이다.

### D1 — 경로 엔진은 완성돼 있는데 학생이 시작할 수 없다 (최우선·신규 태스크)

학생 앱은 그 `concept_id`를 어디서도 얻지 못하고(경로 API 클라 도달 0종), 서버에도 "최약점을 골라

**정합 설계** (신규 알고리즘 0 · 신규 테이블·마이그레이션 0 · 순수 파생 · 클라 배선 0)

  상위 N개 약점 각각에 `recommend_prerequisite_gaps`(`:448`, **`max_depth≥2`**) →

- **② 정직 표기 — 이 설계의 핵심**. `LearningPath`는 현재 `steps`·`has_cycle` 2필드뿐이다. 여기에

  - `entry_source` — 시작점을 **어떻게 골랐는지**(최약점 N개 / 지정 concept / 후보 없음)
  - `entry_concept_ids` — 실제로 진입점이 된 개념들(재현 가능성)
