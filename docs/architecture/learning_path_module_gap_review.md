## §0. 전제 — 실측 현황 스냅샷 (2026-07-30 기준)

**이미 가동 중이고 외부 문서보다 엄격한 것**:

- **위상정렬 경로 엔진 (완전 결정론 + 정직한 사이클 잔여)**:
  `l2/learning_path.py:143` `order_learning_path`는 Kahn 위상정렬로 막힌 선수개념을 학습 순서로
  배열한다. 핵심은 **사이클을 조용히 버리지 않는 것**이다 — Kahn이 모든 노드를 방출하지 못하면
  잔여를 `_tiebreak` 정렬해 deterministic append하고 `is_cycle_residual=True`·`has_cycle=True`로
  표시한다(`:197-205`). 데이터는 이미 비순환 보장(`concept_graph/validate.py` `prerequisite_cycle`
  hard error)인데도 방어를 넣고 *그 방어가 발동했음을 응답에 노출*한다. 조용한 누락 0.
- **재귀 CTE 선수 탐색 + 깊이 상한**: `l2/prerequisite_recommendation.py:230`
  `build_prerequisite_stmt` — `MAX_PREREQUISITE_DEPTH: int = 5`(`:123`) 상한, MIN depth dedup
  (같은 개념이 여러 경로로 닿으면 *가장 가까운* 깊이로 축약), `weakness = min(bkt, irt)`
  보수적 결합. 외부 문서의 "선수 개념 추천"보다 한 단계 위다.
- **원자축 울타리 + 조용한 탈락 금지**: `l2/axis_exclusions.py`가 축 불일치로 탈락한 후보를

② **점수·등급·합격 확률 예측 시뮬레이션**(외부 62) — 승계(`ai_tutor` §2-⑧). "학습 시간·정답률만으로
우열을 매기는 게임화 금지"(CLAUDE.md 교수학 금기)의 직접 위반. PRD FR-018/FR-031이 같은 축에

**성취기준 커버리지**뿐(`S4-18` acceptance ②).

③ **스트릭·랭킹·학습시간 리더보드·복습 독촉 푸시** — 승계(`ai_tutor` §2-③) + `docs/design/ui/00_index.md`
불변식 2("정답률 랭킹·스트릭·카운트다운·보상 연출 금지"). 복습 스케줄이 있어도 **압박 알림으로

④ **`assessment.recommended_path` 영속 소생** — writer/reader 0인 JSONB 슬롯을 살리지 않는다.

파생 즉시성이 이미 "실시간 재구성"이므로 재최적화 루프를 따로 만들 필요가 없다.

⑤ **`study_plan`/주간·일일 학습계획 *엔티티*** — 테이블 신설은 계속 불채택(`ai_tutor` §4-⑤ 승계).
단 **FR-010 시즌 플랜 *기능*은 유보 해제됐다**(Kiki 결정 2026-07-30 → D7·D8). 화해 지점: PRD는
"시즌별 학습 플랜 자동 생성"을 요구했고 *엔티티*를 요구하지 않았으므로, **파생으로 구현하면 기능이
착지하면서 엔티티 불채택이 유지된다**(§2-④ "경로는 상태가 아니라 파생"의 시즌 축 적용). 주간·일일
단위 쪼개기는 여전히 불채택 — 수요 미관측이고, 시간 단위 계획은 §2-⑥의 학습시간 신호를 요구한다.

⑥ **학습시간 기반 일정 최적화**(외부 59) — `learning_session` writer 0. **"생산자 없는 신호는
필드로 만들지 않는다"** 선례(`l4/pedagogy/runtime_selector.py:96-112`)를 그대로 적용한다. 중요한 것은
writer 부재가 **누락이 아니라 결정**이라는 점이다 — `S3-16` acceptance ③이 `learning_session` 행

⑦ **협업필터링 기반 경로 추천** — `02_learner_model.md`이 스스로 사용자 수 부족을 경고한다.

⑧ **복습 주기 고정 상수(1·3·7·14·30일)** — BKT 파생과 이중 진실원천이 되고, 더 결정적으로

## §3. 설계 — D1~D6

실행 순서 `D1 → D2 → D3`. D4~D6은 코드 변경 0.

**D1~D3은 새로 발명한 갭이 아니다.** 셋 모두 이 프로젝트가 스스로 미룬 항목이며 MEMORY에
문자 그대로 남아 있다 — `L2104`(PR #305) NOT: "다(多)약개념 통합 경로·transitive 내부 엣지
(비-weak 중간 노드 의존)" · `L2100`(PR #307) NOT: "다(多)약개념 통합 경로·transitive 내부 엣지·
**Flutter 클라 소비**". 외부 EOS 틀이 한 일은 새 요구를 들여온 것이 아니라 **6주 묵은 NOT
목록이 아직 상환되지 않았음을 드러낸 것**이다. 이 문서의 기여는 그 세 항목에 (a) 왜 지금인지의
근거와 (b) 상환 시 지켜야 할 불변식(§2)을 붙인 것이다.

### D1. 다(多)약개념 통합 경로 + 개념 난이도 축 첫 reader 〔신규 태스크〕

**문제**: 현재 경로는 약개념 **하나**를 인자로 받는다(`/weak-concepts/{concept_id}/learning-path`).
학생에게 약개념이 5개면 경로도 5개가 나오고, 그것들이 선수를 공유할 때 **같은 개념을 여러 경로에서
중복해 되짚는다**. 외부 54가 말하는 "개인별 학습 경로"는 학생 단위 하나여야 한다.

**설계**:
- `order_learning_path`를 여러 약개념의 선수 **합집합**에 대해 호출하는 조립 좌석 신설. 순수 정렬
  함수 자체는 이미 집합을 받으므로 **신규 알고리즘 0** — 입력을 모으는 층만 추가한다.
- `_tiebreak`(`l2/learning_path.py:120`)에 `intrinsic_difficulty` 축을 삽입한다. **위상 제약이
  항상 우선**이고 난이도는 위상적으로 동등한 노드들 사이의 tiebreak로만 쓴다(쉬운 것 먼저).
  이것이 `intrinsic_difficulty`의 **L2 첫 reader**다.
- 주입 seam은 신설하지 않는다 — `l1/atom_graph/axis.py:52` `ATOM_AXIS_META_COLUMNS`에 1열을
  추가하면 `prerequisite_recommendation.py:275`가 이미 그 목록을 SELECT하므로 자동으로 흐른다.
- `GET /v1/me/learning-path` 신설(concept_id 없는 학생 단위 좌석). 기존 개념별 좌석은 유지.
- MEMORY `L2104`·`L2100`의 NOT(후속) 명시 항목을 상환한다.

**동결할 것**: 결정론 재현(같은 입력 → 같은 순서) · 중복 개념 0 · 난이도 축이 위상 제약을
역전시키지 않음 · 난이도 미주입(NULL) 시 기존 순서와 동일(하위호환·데이터 0 안전).

### D2. transitive 순서 보정 + max_nodes 예산 〔신규 태스크〕

**문제**: `build_learning_path`가 쓰는 내부 엣지는 막힌 집합 *내* **직접** 엣지뿐이다. A→X→B에서
X가 약개념이 아니면 A·B 사이 순서를 못 잡는다 — 코드가 스스로 적어 둔 한계(`:257-258`).

**설계**: `fetch_internal_prerequisite_edges`를 확장해 **비-weak 중간 노드를 경유하는 축약 엣지**를
추가로 산출한다(중간 노드는 경로에 *넣지 않고* 순서 제약만 전달). 반드시 `max_nodes`/depth 예산을
동반한다 — 예산 없는 transitive 확장이 정확히 §2-⑨가 막는 폭발 경로이기 때문이다. 예산 초과 시
조용히 자르지 않고 **잘렸음을 응답에 표시**한다(사이클 잔여 정직 표기와 동형 계약).

### D3. 클라이언트 경로 소비 — 「나」탭 학습 경로 시각화 〔신규 태스크·layer=mobile〕

**문제**: §0의 낙차 — 서버가 계산한 경로를 아무도 보지 않는다. 이것이 이 영역 최대 갭이고,
서버 로직이 이미 있으므로 **가장 값싼 갭**이기도 하다.

**설계**: `me_screen.dart`의 "준비 중" 2종(`학습 경로`·`진단 결과`)을 실 API 소비로 교체한다 —
D1의 학생 단위 좌석 + 기존 `/v1/me/diagnosis/concepts`. 반게임화 근거를 코드 주석에 명기한다
(`00_index.md` 불변식 2가 경로 시각화를 *명시적으로 허용*).

**동결할 것**: 랭킹·스트릭·카운트다운·보상 연출이 **0임을 테스트로 동결**한다. 경로 시각화는
허용의 경계 안쪽이지만, 진척 UI는 게임화로 미끄러지기 쉬운 표면이라 허용을 받은 자리에서
바로 선을 그어 둔다. `has_cycle`·transitive 절단 표시 등 서버의 정직 신호를 **삼키지 않고** 노출한다.

### D4. `S4-18` 정합 확인 — 모듈 56·57·60은 개정 불요 〔태스크 변경 0〕

`S4-18-review-time-axis`가 이미 56(복습 시간축)·57(목표축 첫 reader)·60(목표 커버리지)을 정확히
선점하고 있다. acceptance를 실측 대조한 결과 이 문서가 요구할 것이 **하나도 남지 않는다**:
- ① `GET /v1/me/review-queue`를 `apply_forgetting` **조회 시점 순수 파생**으로 규정하고
  `next_review_at` 컬럼·마이그레이션 신설 0을 리뷰 게이트로 못박음 → §2-①·§2-⑧과 일치.
- ② `target_*` 첫 reader를 **D-day + 목표 성취기준 커버리지 %**로 한정하고 "점수·등급 예측 필드
  부재를 테스트로 동결" → §2-② 그대로.
- ③ `decay_model='bkt_p_forget'`·`calibrated=false` **정직 표기** + SM-2/FSRS 미도입 명시.

따라서 **재설계·중복 등재·YAML 개정 모두 하지 않는다.** 외부 모듈 번호(56·57·60) ↔ `S4-18`
대응은 이 문서 §1 crosswalk가 보유한다 — 태스크 `notes`에는 CLI 조작 창구가 없으므로 손편집하지
않고(자매편 6편의 선례와 동일: 기존 태스크 YAML 무수정), 대응 관계의 진실 원천을 문서 한 곳에 둔다.

남는 판단 하나는 **priority 5가 적정한가**이며, 이는 §4-3(경로 축 KPI 0)이 해소되지 않은 상태에서
근거를 댈 수 없으므로 **올리지 않는다** — 우선순위를 인상으로 바꾸는 것이 정확히 이 프로젝트가
금지하는 "점추정·인상 판정"이다.

### D5. 소유권 분열 정본 정정 〔정본 개정·코드 0〕

§0의 표를 정본에 반영한다. `06_application_modes.md`에는 차원 1·6이 **전방 진도 경로**이고 그
입력 데이터가 미비하다는 사실을(§4-1), `02_learner_model.md`에는 L2 경로 좌석이 **후방 결손
복구**로 스코프 한정된다는 사실과 난이도 축 계약을 적는다. 이 정정이 없으면 미래 세션이 "학습
경로는 이미 있다"를 근거로 전방 축을 구현했다고 오인한다.

것은 어떨까?" → **채택하고 주축으로 승격한다.** 최초 설계(달력 10구간)보다 우월하며, 이유가
셋인데 셋 다 WhyMath 불변식과 직결된다:

1. **카운트다운 금지 문제가 근본적으로 해소된다.** 달력 주축은 본질적으로 시간 압박이라, 원래
   설계는 "시간은 내부 입력으로만"이라는 *우회*를 필요로 했다. 진도율 주축은 시간을 주축에서
   아예 빼므로 우회가 불필요하다 — 규칙을 피해 가는 설계보다 규칙이 필요 없는 설계가 낫다.
2. **개인차를 흡수한다.** 달력 국면은 모든 고3에게 동일하다("5월이니 실전 시작"). 개념 완성이
   절반인 학생에게 5월이라고 실전을 시키면 **교수학적으로 틀리다**. 진도율은 학생 상태에
   맞으며, 이는 이 앱의 정체성(메타인지·단계별 진단)과 정확히 일치한다.
3. **페르소나 이식성.** 달력 국면은 고3 전제다 — 페르소나 C(검정고시 N수)·E(홈스쿨링 영재)는
   3월 학평을 보지 않는다. 진도율은 페르소나 중립이라 PRD의 "공유 메타인지 코어 + 첫 노출 A"
   구조에 맞는다.

**⚠️ 실측한 제약 — 분모가 문제다**: 진도율 = 숙달/전체인데, **전체를 성취기준 정본으로 잡으면
안 된다.** 실측(2026-07-30): 문제은행 distinct 코드 78개 중 **고등은 46개**이고(32개는 중등),
고등 성취기준 정본은 **509개** → **콘텐츠 커버리지 9.0%**. 과목별로도 12대수 9/18 · 12미적Ⅰ
5/20 · 12확통 4/17 · 10공수1 6/19 수준이다. 이 분모를 쓰면 **학생이 모든 문제를 다 풀어도
진도율 9%**가 상한이고, 그건 가짜 지표이자 좌절을 주는 표시다(부정적 피드백 강화 금지).

**설계 — 이중 회계**: 두 수를 **분리해서 함께** 낸다(핵심 판정치 이중 회계 원칙과 같은 결).
- `subject_progress[과목]` · `grade_progress[학년]` = 숙달 성취기준 / **학습 가능**(문항 존재) 성취기준
- `content_coverage[과목]` = 학습 가능 성취기준 / **성취기준 정본** ← 이건 학생 지표가 아니라
  **콘텐츠 생산 백로그 지표**다. 숨기면 진도율이 실제보다 완성돼 보인다.
- 정직 표기: `calibrated=false`(BKT 미보정 승계 — §2-⑧과 동일 이유)

**국면 판정 = 진도율 밴드**(달력 아님): 개념 형성 구간 → 숙달 구간 → 실전 구간. **밴드 경계를
코드 상수로 박지 않는다** — 캘리브레이션 전 상수는 근거가 0이라는 §2-⑧을 그대로 적용해, 경계도
데이터로 두고 `calibrated=false`를 표기한다.

**표현 규칙 2개 — 여기서 미끄러지면 금기 위반이다**:
- **학년 진도율에 학년 라벨을 쓰지 않는다.** 고3 학생의 자재 절반이 중등 코드다(1,363/2,647).
  이걸 "너는 중3 수준"으로 표현하면 **낙인**이다 → "지수·로그의 기초 연결이 남아 있다"처럼
  **개념 이름으로** 말한다. 학년 라벨의 학생 대면 부재를 테스트로 동결.
- **또래 비교·백분위 금지**(§2-⑩ 신설). 진도율은 **자기 참조만**.

**`S4-18`과의 단일 진실원천 정리**: `S4-18` acceptance ②의 "목표 성취기준 커버리지 %"가 진도율의
한 형태라 **이중 진실원천 위험**이 있다. 이 좌석을 단일 진실원천으로 하고 `S4-18`이 **소비**하도록
순서를 잡는다(`S4-18`은 미착수·priority 5라 순서 조정 비용 0).

### D8. 고3 대입 시즌 골격 코퍼스 — 달력은 **보조 제약**으로 〔신규 태스크〕

**Kiki 결정(2026-07-30)**: FR-010을 P0로 유지하고 **시즌별 내용 배분까지 구성**한다. 아키텍처
유보(`ai_tutor` §4-⑤·§5-⑤)는 이로써 **발화**한다.

**달력을 버리지는 않는다 — 축을 내린다.** 수능은 실제로 11월에 있고 모의고사 회차는 **외부 고정
이벤트**로 실재하므로, 달력은 ①회차 안내 ②정합성 점검("남은 범위가 남은 기간에 물리적으로
가능한가")에만 쓴다. **②의 결과를 학생에게 압박으로 노출하지 않는다.** 배분 결정권은 D7 진도율이
갖는다.

**참고 입력의 지위 — WhyMath 명세가 아니다**: Kiki가 고3 연간 로드맵(모의고사 7회·4대 분기점·
과목별 진도 권장 4단계·학생부 일정)을 함께 제공했으나, 그것은 **"일반적인 고3 수학 입시대비용이며
WhyMath 전용이 아니다"**(Kiki 명시). 외부 EOS 틀 문서와 **같은 지위**다 — 참고 자료이지 그대로
구현할 명세가 아니다. 따라서 이 문서는 그것을 ①채택 ②투영 ③범위 밖으로 분리해 가른다. **WhyMath
정본은 로드맵 원문이 아니라 아래 투영표와 이 코퍼스**이며, 원문과 어긋나는 부분은 어긋난 채로
둔다(수학 학습 앱의 경계가 일반 입시 로드맵보다 좁기 때문이다). **특히 로드맵의 월별 구간 자체는
정본으로 받지 않는다** — 구간 판정은 D7 진도율이 하고, 로드맵에서 취하는 것은 *시험 회차의 실재성*과
*각 회차의 성격*뿐이다.

**선결 데이터가 없다**: `exam_calendar` grep **0건**. 시험 일정과 수능 출제범위 표가 저장소에
없으며, 둘 다 **연도마다 바뀌므로**(2028 수능 개편) 코드 상수가 아니라 데이터여야 한다. 규모는
연 7행 + 과목 목록으로 작고, 평가원·교육청 시행 공고는 **공공 사실정보**라 저작권 안전하다.

**설계**: `data/corpus/exam_calendar_v1/`(기존 26 코퍼스 패턴·`_provenance.json` 동반) +
L1 로더. 담는 것은 ①시험 회차(월·시행기관·성격) ②학년도별 실제 시행일 ③수능 출제범위 과목 목록.

**축 분리 — 로드맵의 두 종류 정보를 다르게 다룬다**:

| 로드맵이 준 정보 | 지위 | 어디로 가는가 |
|---|---|---|
| 시험 회차·시행기관·성격(3월 교육청 학평 / 6·9월 평가원 모평 / 7·10월 교육청 / 11월 수능) | ✅ **외부 사실** — 학생 상태와 무관하게 실재 | 이 코퍼스(D8) |

| 월별 학습 구간("5월 실전 시작", "8월 2~3회독") | ⚠️ **일반 권장이지 개인 판정이 아니다** | **정본으로 받지 않음** — 구간 판정은 D7 진도율 |

데이터 차단은 시즌 플랜 *전체*를 막지 않고 *이 두 구간*에만 걸린다. 그 구간은 회차만 적재하고
범위는 비운다 — 없는 근거로 채우지 않는다.

**범위 밖 — Kiki 로드맵에서 WhyMath가 가져가지 않는 것** (명시 분리):

### D9. 시즌 플랜 파생 엔진 — 진도율 국면 + 범위 배분 〔신규 태스크〕

**핵심 설계 결정 — `study_plan` 테이블을 만들지 않는다.** §2-④의 "경로는 상태가 아니라 파생"을
시즌 플랜에도 적용한다: 진단이 바뀌면 계획도 바뀌어야 하는데 영속 사본은 어긋나는 순간 이중
진실원천이 된다. **그리고 이것이 두 정본을 화해시키는 지점이다** — PRD FR-010은 "시즌별 학습
플랜 자동 생성"을 요구했고 *엔티티*를 요구한 적이 없다. 기능은 착지하고 §2-⑤의 엔티티 불채택은
유지된다.

**설계**: `GET /v1/me/season-plan`(파생·읽기 전용). **주 입력은 D7 진도율**이고, D8 코퍼스(회차)와
`target_exam_date`는 보조다. 출력 = 현재 국면(진도율 밴드) + 그 국면의 범위 배분(성취기준 코드
집합) + 우선순위 + 다음 회차 안내.

- **국면은 진도율이 정한다** — 달력이 아니다(D7). 같은 5월이라도 대수 진도율 40%인 학생은 개념
  형성 구간, 85%인 학생은 실전 구간이다.
- **과목 축은 필드가 아니라 성취기준 코드 파싱으로 얻는다.** 실측: `problem.subject`는 2,647건
  전부 `'공통'`으로 균일해 무용하지만, `achievement_standard_codes`는 **100% 커버리지**이고
  코드가 과목·학년을 내장한다(`[12미적Ⅰ-…]`·`[9수…]`). 새 태깅 백필 없이 즉시 가능하다.
- **배분 규칙은 신규 알고리즘이 아니다** — 약점 우선 + 선수 위상 순서로, 기존
  `order_learning_path`(D1 통합 좌석)를 국면별 범위로 스코프해 재사용한다.

**반드시 동결할 것**:
- **잔여 일수를 압박에 쓰지 않는다.** `00_index.md:41` 불변식 2가 "카운트다운 금지"를 명시한다.
  진도율 주축 채택으로 이 위험은 크게 줄었지만(시간이 더는 주축이 아니다), 회차 안내가 카운트다운
  으로 변질될 수 있으므로 초조 연출·독촉 부재를 테스트로 동결한다. 학생 대면 표현은 **국면 + 범위
  + 다음 회차**까지이고, "수능까지 D-97" 같은 잔여일 강조는 금지.
- **점수·등급·합격 예측 필드 부재**(§2-②) · **또래 비교·백분위 필드 부재**(§2-⑩) · **학년 라벨
  학생 대면 부재**(D7 표현 규칙).
- 내신 구간은 `range_scope` 빈 상태를 정직하게 노출 — 차원 6 부재를 가짜 배분으로 덮지 않는다.

### D10. 과목 이수구분 참고 데이터 + 학생 수강 과목 온보딩 (Kiki 제안 심화) 〔신규 태스크〕

**Kiki 제안(2026-07-30, 2차)**: "기간 구분"에서 한 발 더 들어가 — **학년트랙(2학년 과정/3학년
과정) 안에서 몇 과목 중 현재 어느 과목을, 그 과목의 몇 단원 중 몇 단원·소단원을 진행 중인지**로
표시하자는 제안. 예시로 "3학년 과정(미적분Ⅱ·경제수학·인공지능수학·직무수학 등, 진로에 따라 선택)
중 경제수학 진행 중 → 경제수학 전체 몇 단원 중 현재 몇 번째 소단원"을 들었다. **채택한다** —
D7(진도율 %)보다 학생에게 더 직관적인 표현 형태이고, 학교 현장 언어("지금 미적분1 배우고
있어요")와 일치한다.

`standards_v1`(성취기준 코드)를 다시 보니 **22개 고등 과목 전부**에서 코드가
`[과목-단원번호-소단원번호]` 구조로 완전히 파싱된다 — 실측: `12미적Ⅰ`(3단원: 01 함수의 극한과
연속·02 미분·03 적분) · `12경수`(4단원: 01 수와 경제 ~ 04 미분과 경제) · `12인수`(5단원) 등.

기본 순서는 **출판사 무관 진행 위치를 보여주는 정도(coarse)**로만 쓰고, 학교별 정밀 정렬(자동

고시 제2022-33호 [별책 4])을 제공해 실측 대조했다.** HWP5 바이너리 → `pyhwp`(DocInfo 파싱 실패
