## §0. 틀의 아키텍처와 WhyMath 정본의 정면 충돌 (§1 판정의 전제)

틀은 콘텐츠 생성 흐름을 이렇게 그린다:

```
교육과정 → 성취기준 → 개념 DB → 교수전략(Pedagogy) → AI Content Engine → QA 엔진 → 콘텐츠 배포
```

**교수전략이 AI Content Engine의 *입력*이다.** WhyMath 정본은 이 순서를 **명시적으로 거부**한다
(`04d_adaptive_pedagogy_engine.md` §0): 교수전략을 DSL *이전*에 고정하면 같은 교육목적이라도
학생·상황·오답패턴마다 달라져야 할 교수법이 **콘텐츠에 각인**된다. 정본 흐름은:

```
교육과정 → 개념 → 교수법-중립 ConceptDSL(영구 자산) → [런타임] 교수법 선택 → 얇게 렌더
```

- 저장되는 것은 (개념 × 교수법)의 **곱이 아니라 합**이다 — 조합 폭발 방지(무한 온톨로지 금지).
- 이것은 설계 문서가 아니라 **가동 중인 코드**다: `PED-01`(교수법 팩)·`PED-02`(런타임 선택기)·
  `PED-03`(적응 정책)·`REND-01`(렌더 어댑터 5종)·`CACHE-01`(`supply()`) 전부 **done**.
- 기계 강제까지 있다: `l3/render/dsl.py:35` `PEDAGOGY_METHOD_BLOCKLIST` 7종("소크라테스식"·"강의식"·
  "발견학습"·"게임형"…)이 DSL 필드에 교수 *방식 지시어*가 들어가면 `ValueError`로 거부하고,
  `l4/content_supply.py`의 `supply()`가 `decide()` 게이트를 **내부에서** 호출해 우회를 불가능하게 한다
  ("캐시 히트가 교수학을 위반하면 히트를 버린다 — 비용이 교수학을 이길 수 없다", `03c:131`).

> **따라서 틀 순서대로 만드는 것은 신규 기능이 아니라 퇴행이다.** 확장 후보 66("교수전략 기반 콘텐츠
> 생성 — 직접교수·탐구학습·PBL")은 갭이 아니라 **이미 더 정교하게 풀린 문제**이며 §2-⑥에 등재한다.

### D1. 맥락·스토리형 문항 생성 — **기각** (태스크 0 · §2 + §4-①로 분해)

당초 후보 설계는 "서사 래핑은 미채택하되 **모델링 맥락 슬롯**은 rephrase의 봉인 모델(수치·정답·선지
불변, `question_text`만 변경)을 확장해 채택"이었다. **기각한다.**

**⑴ `problem_bank:131` 번복 여부는 쟁점이 아니다.** `:131`은 기능 20(유형 *관리*) 행이고 거기서
대체된 것은 "실생활형"이라는 **분류 라벨**이지 실생활 문항의 *생성*이 아니다. 형식적으로는 번복이
아니다. **그러나 이 방어는 D1을 구하지 못한다** — D1이 넘어야 할 벽은 분류 판정이 아니라 검증
게이트이고, 그 벽에서 D1은 이미 한 번 무너진 설계다.

**⑵ 결정적 반증 — `S3-15`가 D1을 이미 실행하고 실패했다.** `S3-15-rephrase-pipeline-redesign`
(**status: done**) acceptance 원문:

> "rotation-0/1/2 3라운드 전부 `corpus_audit_eval` **FAIL**(결함 12%→5.5%→1%로 개선되나 **매 라운드
> 신규 결함 유형 재발** … 둘 다 기존 `rephrase_hygiene.py` 패턴 미포착)이 왜 발생하는지 근본원인
> 분석: **LLM 자유 재작성 방식 자체가** 매 생성마다 **예측불가 신규 결함**을 내는지 … **패턴 패치
> 축적(`rephrase_hygiene.py` 신규 축 추가) 단독으로는 재시도 금지**"

해결책은 게이트 강화가 아니라 **전수 감사 + 항목 단위 사람 교정**(429/429·Wilson 0.63%)이었다.
그리고 실측 결함 목록에 **바로 그 결함류**가 있다:

> `ai_review_batch_v0_4corpora_2026-07.md:661` — `wm-skel-126a2ead2c3c` | QUAD-EQ | 객관식 | **defect** |
> 발문 **'원판을 다루는' 허위 맥락** + '작게 하는 수' 왜곡. **수학·선지 정상**

**즉 rephrase 봉인 모델은 "맥락 환각"을 이미 결함으로 산출했고, 감사가 그것을 잡아 제거했다.
D1은 그 결함류를 *기능으로 승격*하자는 제안이다.** 게다가 rephrase는 D1보다 **훨씬 약한**
변환(표현만 바꿈)이었는데도 3라운드 실패했다 — 맥락 도입은 명제 내용을 추가하는 **더 강한** 변환이다.

**⑶ 제안했던 게이트("조건 재추출 검증")는 존재하지 않는 능력을 전제한다.** 봉인 모델이 성립한 유일한
이유는 수치·정답·선지가 텍스트 **밖 구조 필드**에 있어 기계 비교가 결정 가능했기 때문이다. 맥락
문항의 진짜 위험은 그 필드에 없다:

> 원본 `x² − 5x = 0`의 두 근 중 더 큰 근 (answer `5`)
> → 맥락 래핑 "티셔츠를 x장 팔 때 이익이 `x² − 5x = 0`이 되는 판매량 중 큰 값"

`classify_invariance_failure`는 **PASS**한다(수치·정답·선지 전부 불변). 그런데 근 `0`은 수학적으로
유효하지만 "0장 판매"는 맥락상 무의미하고, 문맥이 "이익이 0이 되는 최소 판매량"으로 읽히면 **정답이
바뀐다**. 봉인 게이트는 이 결함을 **원리적으로** 못 잡는다. 그리고 "조건 재추출"은 자연어→수학 조건
파싱을 요구하는데, `l3/verify_step.py`가 정확히 그 지점을 **`unverifiable`로 정직 반환**하도록 설계돼
있다. 저장소에 그 능력이 없다. → **"측정 없는 기계 게이트를 인간 검수 대체로 선언 금지"·"변별력 없는
검증 스텝 금지"** 위반.

부수적으로 `rephrase_hygiene.py`의 폐쇄 목록 축들은 근거가 *"이 코퍼스 맥락에서 관찰된 적 없는 정상
용법"*이다. 쇼핑·금융·스포츠·건축 어휘를 들이면 그 **모집단 논거 자체가 붕괴**한다 — 후보 설계의
"기존 위생 게이트가 무력화된다"는 인식은 옳았으나, 결론이 "전용 게이트 신설"이 아니라
**"게이트를 만들 수 없다"**여야 했다.

**⑷ 수요 실재는 판정을 바꾸지 않는다 — 단, 트리거 근거는 된다.** `standards_v1` 895 성취기준에
"실생활" 51회·"상황" 41회·"모델" 25회. 수요는 실재한다. 그러나 규약은 "수요가 있으면 만든다"가
아니라 **"검증 게이트가 성립하면 만든다"**(검증 권위 서열). 수요는 *우선순위* 입력이지 *채택 근거*가
아니다. → §4-①의 발화 조건 ③으로 기록한다.

**⑸ 분해 착지**: 서사 래핑 전량 → §2-① / LLM 맥락 재서술 → §2-② / 관심사·지역 개인화 → §2-③ /
"최신 사례" → §2-④ / **결정론 맥락 슬롯만 §4-① 트리거**. **태스크 등재 0.**

### D2. 개념 공급 무결성 — `assessment` 참조 주입 + 개념 코퍼스 감사 (백로그 `S3-26`)

**목적**: 기능 58의 진짜 갭 — ①R4(숙달) 경로의 437개 전 개념 404 ②개념 콘텐츠가 검수 게이트를 한 번도
통과한 적 없이 학생에게 노출 중. 틀의 "QA 엔진" 박스가 WhyMath에서 실제로 비어 있는 **유일한 지점**.

- **핵심 해법 — 신규 저작 0·LLM 0**: `ConceptAssessment(conditions, answer_map, prompt)`는
  docstring이 명시하듯 "`l3.verify_answer.verify_answer()`의 **입력 형식 그대로**"다
  (`l3/render/dsl.py:49`). 그리고 **이미 6축 초인간 검증을 통과한 문항 2,647건**이 같은 형식을 갖고
  있다. → **개념 태그(`standard_codes`·`unit_codes`)로 문항 뱅크를 참조 주입**한다. 신규 저작 0,
  LLM 0, 검증 앵커는 원천에서 상속. `visualization_card_keys` 참조 키 축 선례 동형.
- **단일 슬라이스 (쪼개기 금지)** — `solution D1`의 **"writer·reader 동반(협상 불가)"** 규약 동형.
  관측만 하면 리포트만 남고, 공급만 하면 관측이 없다. 따라서 ⑴ `assessment` 공급원 ⑵ 개념 코퍼스
  감사(`review_status` 축 + 결함율 리포트) ⑶ `SupplyTally.dsl_render_rate` 리포트 배선(현재 소비처 0)을
  **한 태스크**로 묶는다.
- **경계**: 신규 학생 대면 **축** 0 — 기존 표면(`/study`)의 404 해소·기존 검증 통과 자산의 참조일 뿐,
  새로운 콘텐츠 종류를 학생에게 노출하지 않는다. 개념 설명 LLM 생성 폴백은 **켜지 않는다**(§2-② 정합).

- **검증**: 404 재현 → 해소 전후 실측(숙달 신호 주입 시 렌더 성공률 0% → N%) + `dsl_render_rate`
  리포트에 어댑터별 분해 + 참조 주입 실패 개념(문항 미보유)을 **미커버로 명시 기록**(침묵 통과 금지).

### D3. 문항 유형 필드 신설 + 결정론 백필 (백로그 `S3-27`)

**목적**: 기능 59의 선행 병목 — "무엇이 없는지"를 볼 수 없는 상태의 해소. 스코프 정정: `problem_type_codes`
**필드 자체가 없으므로** 백필이 아니라 **필드 신설 + 백필**이다.

- **유보 해제 논증(필수)**: `problem_bank_gap_review §5-③`은 유형 축 도입을 발화 조건부로 유보했고,
  그 조건 ⑴("유형별 공백을 저작 우선순위로 쓰겠다는 결정")이 **본 문서에서 기능 59 대응으로 성립**한다
  — `solution D1`의 유보 해제 선례 동형. ARCH-18이 유형 축을 스코프아웃한 사유("전 문항 미태깅")도
  이 태스크가 정확히 해소한다.
- **실행 가능성 논거**: 17유형은 **인지 행동** 기준이라 문항 텍스트 추론이 어렵다. 그러나
  **스켈레톤 생성기 18종이 각각 하나의 인지 행동을 고정 산출**한다 → 텍스트 NLP가 아니라
  **생성기 identity → 유형 매핑표**로 결정론 유도한다(`problem_types.jsonl`의 `behavior_skills`가 다리).
  **LLM 0·재실행 바이트 결정론** — `S3-10`(persona_fit 규칙 기반 백필) 동형.
- **정직 고지**: 계보 미영속 코퍼스(`rephrased_v0` 429문 — `S4-14` 미착지로 원 생성기 추적 불가)는
  태깅 불가로 **명시 제외**하고 미태깅 건수를 리포트에 기록한다. 따라서 `S4-14` **의존 아님**(부분
  커버를 정직 고지로 해소 — 인플라이트 태스크 대기 불필요).
- **경계**: `problem_type_node` FK 연결·유형별 *생성* 확대는 스코프 밖(`problem_bank §5-③` 형태 판정
  준수). 이 태스크는 **관측 축**이다.
- **변별력 검증 의무**: 매핑표의 임의 1밴드를 오매핑시킨 상태에서 거버넌스 테스트가 exit 1을 내는지
  실측한 뒤, 정상 상태 exit 0을 실측한다(성공/실패 동일값이면 위장).
- **산출**: `ARCH-18` `harness/problem_bank_coverage.py`에 **유형×단원 매트릭스 + 17유형 중 0커버 유형
  목록** 축 추가 — 이것이 §4-① 트리거의 **발화 계측기**가 된다.

### D4. L3 생성 프롬프트 정본화 + 감사 (백로그 `OPS-15`)

**목적**: D1을 기각한 자리에 남는 실제 부채. "새 LLM 생성 경로를 열지 않는다"고 판정했다면, **이미
