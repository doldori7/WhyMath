## §1. 7계층 코어 개요 — 경계가 곧 자산

WhyMath의 뼈대는 **책임 레이어 L1~L7**(무엇을 책임지나)이고, 이와 직교하는 두 번째 축으로 **5블록 배포 토폴로지**(Client / Backend / DB / ML / Content Pipeline — 무엇이 어디서 실행되나)가 있습니다. 의존성은 **상위→하위 단방향만** 허용되며(L7→…→L1, 역방향 금지), 이 규칙은 문서가 아니라 CI의 **import-linter로 강제**됩니다.

이 아키텍처의 가장 중요한 결정은 **L1–L4 = UI와 무관한 독립 수학 코어**, **L5 = 클라이언트**라는 분리입니다. 수학 로직을 클라이언트에 절대 넣지 않고, 클라(Flutter·웹·PDF·AI)는 API로만 소비합니다. 짝을 이루는 원칙이 **"표현 ≠ 의미"** — 문항·수식·해설은 화면 문자열이 아니라 항상 구조(AST/JSON)로 코어에 저장하고, 렌더는 각 클라이언트가 담당합니다. 이 두 원칙 덕분에 나중에 웹·PDF·타 과목을 붙여도 코어를 다시 쓰지 않습니다.

**현재 상태**: L1–L4는 Phase 1 MVP 요구를 이미 초과하는 두께(백엔드 ~344 .py/64k줄, 테스트가 소스보다 많음). L5는 골격 실동작, L6은 게이팅만, L7은 의도적으로 코드 0. 즉 *코어는 과잉 성숙, 제품 루프는 미성숙*입니다.

> 정본: [`00_overview.md`](00_overview.md)

## §2. L1 데이터 기반 — 진짜 해자

**역할**: 한국 수학 교육 데이터의 *진실 원천*을 정의·수집·관리합니다. 1~2년 누적되면 B2B 라이선싱이 가능한 자산이라 "진짜 해자"로 규정됩니다.

**핵심 설계 결정**: 첫째, **저작권 안전선이 스키마급 원칙**입니다 — 교과서·기출의 본문·예제·그림을 일절 복제하지 않고 *구조 메타데이터*(단원·코드·문항번호)만 보유하며, 문제는 자체 동등문제로 대체합니다. 둘째, **`concept_id`는 canonical `math.<area>.<slug>`** 형태로 교육과정·언어·렌더러와 무관한 의미론 PK입니다. 개념 명칭(한·영·일)조차 노드에 넣지 않고 locale 계층으로 분리하는 "Concept Purity"를 지킵니다.

**현재 구현 상태**: 🟢 실질 구현. 2026-07-04 **원자 백본으로 runtime 진실 원천을 단일화**했습니다 — 원자 1,837개·선수엣지 3,220개(초·중·고+대학 4축)·오개념 839·성취기준 895·pgvector 임베딩. 구 437 개념그래프는 `legacy_snapshot`(readonly·audit_only)으로 격하되었습니다.

**리스크**: 한때 구 개념그래프와 신 원자 백본이 공존해 "이중 truth source"가 7대 붕괴 연쇄의 *유지보수 지옥* 입구였으나, S0에서 해소 중입니다. 남은 리스크는 크로스워크(437↔1,837)의 1:N/N:1 매핑이 mastery 이력·오개념 crosslink를 오염시킬 가능성으로, 거버넌스 테스트가 재유입을 동결합니다.

## §3. L2 학습자 모델 — 시간축의 상태

**역할**: LLM이 현재 발화만 보는 것과 달리, L2는 학생의 *시간축에 걸친 장기 상태*(6개월·1년·3년 학습 곡선)를 통계 모델로 추적·예측합니다. 출력은 L3·L4에 *요약 상태*로 주입됩니다.

**핵심 설계 결정**: **BKT(Phase 1) → IRT(Phase 2) → DKT(Phase 3+)는 대체가 아니라 공존·보강**입니다. BKT는 콜드스타트(초기 100명 단계)에 필수고, IRT/DKT는 데이터가 쌓여야 작동하기 때문입니다. 또 하나의 축은 **정서 신호 모델** — 세션시간·연속오답·응답시간 z-score·rage quit 등 입력 7종을 FLOW/FRUSTRATED/BORED/OVERWHELMED/AT_RISK 5분류로 판정해 L4의 정서 안전 결정에 넘깁니다.

**경계**: **`StudentProfile`은 L1이 소유하고 L2는 읽기만** 합니다. L2는 동적 상태(`MasteryState`·`LearnerState`)만 생산하고 정적 프로필은 수정하지 않습니다 — 7계층 경계를 명시적으로 지키는 사례입니다. 저장은 TimescaleDB `mastery_history` 하이퍼테이블.

**현재 상태**: 🟢 실질 구현(12파일/~2.3k줄) — BKT·IRT·능력추정·mastery 추적·약개념/선수 추천·학습경로. **리스크**는 실사용자 데이터가 0건이라 IRT/정서 신호의 파라미터가 아직 검증되지 않았다는 점입니다(S3 파일럿 대상).

> 정본: [`02_learner_model.md`](02_learner_model.md)

## §4. L3 콘텐츠 생성·검증 — LLM의 모든 책임

**역할**: LLM 호출의 *모든 책임*(라우팅·호출·도구·검증·캐싱·비용추적)을 단일 계층에 집약합니다. 목표는 "비용 1/10, 환각 0에 가까운 LLM 활용"입니다.

**핵심 설계 결정 — 3축 라우터**: 축1 비용·위치(LOCAL/CLOUD_MID/CLOUD_HIGH, 목표 분포 **로컬 80%/중급 18%/최고 2%**), 축2 로컬 크기(fast/mid/quality), 축3 **태스크 패밀리(MATH vs GENERAL)**. 세 번째 축은 2026-05-20 실측에서 나왔습니다 — NLP 추출을 수학특화 모델에 돌리면 7b조차 정확도 0%라, 수학 추론은 MATH(qwen2-math), NLP 추출·매칭은 GENERAL(qwen2.5)로 분기하도록 패밀리를 1급 차원으로 승격했습니다. FAST(1.5b)만 동기 SLA(p50<2s)를 통과해 즉답 기본경로가 되고, QUALITY(27b)는 비동기 큐 전용입니다.

**환각 방어**: WhyMath 5중(스키마·PRM·도구·자기일관성·사람검수)과 PRD 4중을 *하나의 파이프라인*으로 통합합니다. 계산은 LLM에 시키지 않고 **SymPy/Wolfram** 도구로 넘기며, 풀이는 자연어가 아니라 *개념 노드 시퀀스*(`SolutionPath`)로 인코딩해 6가지 접근(대수·기하·조합·귀납·시각·역방향)을 태깅합니다.

**현재 상태**: 🟢 인프라 완비 / 🔴 라이브 미검증. 라우터+Anthropic/Ollama provider·3-tier 검증·Redis 캐시·Celery 큐·Langfuse가 다 있으나, **실측 비용·프롬프트 캐싱·guard_cloud 임계값이 전부 Phaiakes9 라이브 키 대기**입니다(S1 사람 병목). 정직하게, "개념 시퀀스 동치성 자동판정"은 연구 난제로 규정하고 휴리스틱+사람 확정 원칙을 유지합니다.

> 정본: [`03_content_generation.md`](03_content_generation.md) · 라우터 상세 [`03a_l3_router_design.md`](03a_l3_router_design.md)

## §5. L4 교수학 엔진 — 핵심 차별화

**역할**: 학생 발화·상태에서 *교수학적 결정*을 내립니다. L3이 *생성*이라면 L4는 *결정*입니다("지금 Polya 어느 단계? 답을 어디까지 미룰까? 어떤 소크라테스 카테고리? 오개념 개입?"). "한국에서 이 계층을 제대로 만든 곳이 없다"는 것이 차별화 근거입니다.

**핵심 설계 결정 — 5원칙**: 답 미루기·소크라테스 우선·메타인지 명시화·다중 풀이 노출·정서 안전. **답 미루기 4단계**(방향→의사코드→부분풀이→전체풀이)는 "가능한 가장 빠른 단계에서 멈춤"이 규칙이며, PRD의 graded hint 3단계를 1:1로 흡수하되 4단계(전체 풀이)를 WhyMath 고유 안전망으로 한 칸 더 둡니다. 각 단계의 `reveals`를 기록해 *세션당 노출량*을 KPI(답 미루기 도달 깊이)로 추적합니다.

**오개념 비낙인 설계**: 오개념을 *지목·낙인하지 않고 질문 종류만 바꿉니다*. 고신뢰(≥0.65)+최근(turns≤2) 활성 오개념 가설이 있으면 소크라테스 카테고리를 ASSUMPTION("왜 그렇게 가정했어?")으로 전환해 잘못된 전제를 학생 스스로 표면화하게 하고, 반환은 카테고리 enum뿐 — `misconception_id`는 구조적으로 노출 불가입니다. 정서 안전 톤 필터가 "틀렸·못 해·바보"를 금지하고 "흥미로운 시도네"를 권장합니다.

**현재 상태**: 🟢 최대 계층(62파일/~10.5k줄) — Polya·소크라테스·LTHC·오개념 진단/가설/판정(judge)/shadow harvest·톤 필터·메타인지 트리거. **리스크**는 이 정교한 엔진이 실제 학생 앞에서 작동한 증거가 0건이라는 점(S1/S3에서 실증).

> 정본: [`04_pedagogy_engine.md`](04_pedagogy_engine.md)

## §6. L5 상호작용 — 유일한 접점

**역할**: 학생과 시스템의 *유일한 접점*입니다. 클라이언트 UI + FastAPI 서버(오케스트레이터)로 구성됩니다.

**핵심 설계 결정 — 슬라이스 89의 4요소**: ① 독립 수학 코어(L1-L4·API로만 소비) ② 학생 클라이언트 = **Flutter 단일**(패드 중심 네이티브·수학 로직 미포함) ③ 별도 웹 = React/Next(교사·SEO·Phase 3+) ④ 2개 국소 비상구 = MathLive(수식 입력)·three.js(3D) WebView. Flutter Web이 아니라 네이티브 태블릿(Impeller)을 고른 이유는 저지연 손글씨 때문입니다. **정서 안전 UI**로 게이미피케이션(정답률 랭킹·스트릭)을 금지하고 학습경로·Polya 단계·답 미루기 단계를 항상 화면에 명시합니다.

또 하나의 특징은 **수식 음성화(Math-to-Speech)**를 오디오 합성이 아니라 *LaTeX→모호성 없는 한국어 낭독 문자열 변환*으로 본 것입니다 — 코어가 `SpeechSpec` 선언적 명세를 결정론 규칙엔진(LLM 0·환각 0)으로 산출하고, 클라는 합성만 합니다.

**현재 상태**: 🟡 골격 실동작 — Flutter 앱 화면 9개(auth/chat/ocr/onboarding)·백엔드 OCR(콴다식 4단계 파이프라인·`POST /v1/ocr`)·WebView 그래핑 계산기. **핵심 리스크**는 온보딩→진단→문제→풀이입력→코칭→검증의 **E2E 학습 루프가 한 번도 연결된 적 없다**는 것입니다 — S1의 정확한 목표.

> 정본: [`05_interaction.md`](05_interaction.md)

## §7. L6 응용 모드 — 하나의 코어, 여러 진입점

**역할**: 같은 7계층 코어 위에 *시장별 진입점*만 다르게 얹습니다. 단일 코드베이스로 여러 모드(학교진도·수능·사고력·메타인지·영재·자유학기·디버깅)를 유지합니다.

**핵심 설계 결정**: PRD가 제안한 3개 앱 분리(학생·교사·학부모)를 반려하고 **Flutter 단일 앱 + `ModeConfig` 분기**(content_filter·polya_emphasis·metacog_freq·gamification_level·default_cost_tier)로 갔습니다 — 1인 팀 과부하와 코어 상태(BKT·오개념) 공유 때문입니다. 그 위에 **자동 커리큘럼 정렬 7차원**(활성 개념 풀·표기·깊이·풀이 스타일 순서·용어·인접 개념 순서·평가 형식)이 얹힙니다. **모드와 정렬은 직교(곱집합)** — 모드가 콘텐츠 풀·교수학 가중치를 정하고, 정렬이 그 위에서 학생 교과서 좌표를 조정하되, 모드를 바꿔도 코어 상태·정렬은 일관 유지됩니다.

**현재 상태**: 🟡 게이팅만 — 6개 모드 각 `gating.py` 1개뿐이라, **wedge인 수능 모드조차 본격 엔진이 없습니다**. 자동 정렬은 차원 3(깊이)만 학교진도 모드에 1차 배선(우선순위 보너스). **리스크**가 큰 이유는 코어가 아무리 좋아도 학생이 실제로 만나는 건 L6이기 때문 — S3에서 수능 모드 본격 엔진(시그니처 경로·킬러 단계 진입·모의 채점)을 구현합니다.

## §8. L7 커뮤니티·소셜 — 안전선이 기능을 지배

**역할**: 학생·학부모·교사를 잇는 *사회적 학습* 인프라입니다. 느리지만 "데이터 누적→모델 개선→콘텐츠 풍부" 선순환의 결정적 자산입니다.

**핵심 설계 결정 — 안전선이 기능 정의를 지배**: **다중 풀이 갤러리**는 *본인 풀이 완료 후에만* 타 학생 익명 풀이를 열람하게 하고 다양성을 우선하며 "최고 풀이" 랭킹을 금지합니다. **Live Problems**(NRICH 모델)는 주 1회 신규·익명 제출·마감 후 큐레이션 공개. **학부모 보고서**(주 1회 opt-in)는 비교·랭킹 없이 약점·강점·메타인지 순간·5분 대화 주제만, L4 톤 필터를 적용합니다. 자동 채점도 정답/오답 이분법이 아니라 *어느 단계에서 막혔는지*까지 전달합니다.

**현재 상태**: ⚪ 코드 0 — 문서만 존재하며 Phase 3+로 의도적 보류. **리스크가 아니라 의도된 순서**입니다: Phase 1~2는 학생 경험(L5 루프·L6 수능)에 집중하고, L7은 데이터·사용자가 쌓인 뒤 착수합니다.

## §9. 하네스 — LLM 호출 방식을 바꾸는 횡단 인프라

**역할**: 하네스는 새 계층이 아니라 **L3·L4의 LLM 호출 *방식*을 바꾸는 횡단 인프라**입니다. "모델 크기보다 환경(검증기+상태관리+탐색)이 능력을 결정한다"(rStar-Math·AlphaProof)는 통찰이 근거입니다.

**WH-1 튜터링 하네스 (온라인)**: 오개념 가설·증거 그래프를 프롬프트가 아니라 **DB 레코드로 외부화**하고, LLM은 매 턴 "다음 교수학적 행동"만 판단합니다(도구 루프). 활성 오개념 가설 세트는 최대 5개·시간감쇠 ×0.85·ε-탐색 강제·반박증거 우선기록으로 확증편향을 방지합니다. 전용 도구 8종(read_student_state·verify_step 3상태·match_misconception·curate_hypothesis·select_probe 등)을 갖췄습니다.

**WH-S 솔버 하네스 (오프라인 배치)**: 시스템 자체 풀이력을 자기진화 루프로 상승시킵니다. MCTS 탐색 + **3-Tier 검증기 스택**(Tier1 수치·Tier2 SymPy 기호·Tier3 Lean4 형식) + STaR/rStar-Math 자기진화. `verified/unverified/failed` 3등급으로 보상 해킹을 차단하며(unverified는 학습 데이터에서 절대 배제), L3/L1 업스트림으로서 검증 풀이·PRM을 WH-1에 공급하되 학생 세션에는 개입하지 않습니다.

**도입 단계화 — "측정 없는 도입 없음"**: Phase 1~2는 WH-1 0단계(평가 하네스·대리지표 7종) + verify_step·match_misconception 2도구 삽입, WH-S S0~S1(Tier1+2·MCTS-lite). Phase 2~3에서 전체 도구 루프·자기진화·PRM으로 확장. Lean4 Tier3(자동형식화)와 자체 모델 SFT/RL은 장기 보류입니다. **현재 상태**: 둘 다 🟡 골격 — 상태 저장소 스키마는 구현, LLM 정책 구동은 후속.

> 정본: [`04a_wh1_tutoring_harness.md`](04a_wh1_tutoring_harness.md) · [`03b_wh_s_solver_harness.md`](03b_wh_s_solver_harness.md)

## §10. 코딩 완성 단계 S0~S5 — 게이트가 기간에 우선

**역할**: 사업 페이즈(Phase)와 별개로, 코드를 *어떤 순서로 완성하는가*를 정의하는 실제 작업 로드맵입니다. 각 단계는 **진입 게이트 → 완료 정의(DoD) → 탈출 게이트**를 가지며, 미달 시 다음 단계로 강행하지 않습니다.

**단계별 요지**: **S0 정합성 회복**(✅완료) — 이중 truth source를 청산해 원자 백본으로 단일화. **S1 E2E 수직 슬라이스**(🔄진행) — "고3 1명이 미적분 1문제를 온보딩부터 검증까지 Flutter 앱에서 완주"하는 증거 확보, 탈출 게이트는 실기기 15분 완주 시연 + 루프당 비용 실측 + PRM 우회 불가 증명. **S2 콘텐츠 공장**(🔄착수) — 검증 통과 동등문제 100문+, SymPy 동치 게이트→PRM→검수 파이프라인. **S3 파일럿** — 진짜 학생 5~10명 측정으로 KPI 베이스라인. **S4 K-12 완성** — 미적분에서 전 학년으로 수평 확장. **S5 확장 게이트** — 물리 진입 *가부 판정*.

**확장 대비 불변식**: 모든 단계에 과목 중립 원칙이 걸려 있습니다 — 루프 어디에도 `if subject == "math"` 금지, 검증기는 plugin(SymPy 자리에 물리 단위·차원 검증기 삽입), 측정 지표 중립, 커리큘럼은 Overlay. 수학 완성 과정에서 "수학 전용 하드코딩"이 스며들면 물리 확장 비용이 폭발하기 때문입니다.

**현재 위치**: S1 마무리 + S2 병행. 무게중심이 *설계 정본화 → 수직 슬라이스 실증*으로 이동한 국면입니다.

> 정본: [`../strategy/status_roadmap_2026-07.md`](../strategy/status_roadmap_2026-07.md) · 페이즈는 [`../../ROADMAP.md`](../../ROADMAP.md)

## §11. 데이터·법적 전략 — 나중에 못 고치는 리스크의 선제 차단

**역할**: 콘텐츠 백본을 *법적 안전조합*만으로 구성해, 사후에 교정 불가능한 저작권·개인정보 리스크를 원천 차단합니다.

**핵심 설계 결정**: 무제한·영리 허용 소스(NCIC 성취기준·공공누리 AI유형·AIHub + LLM 학습용 NuminaMath/PRM800K/PhET/Metamath)만 사용하고, **EBS·평가원·검정교과서 본문·문항은 상업 이용 금지**(저작권법 §32 단서)로 보아 *구조 메타데이터만* 보유한 채 **자체 생성 동등문제로 본문을 대체**합니다(빌드타임 사전생성 + SymPy 동치 게이트). 또한 **SA(ShareAlike) 전염**을 피하려 CC BY-SA 자료(AoPS·LibreTexts 등)를 AI 학습에 직접 쓰지 않고 사실·구조만 추출하며, Khan Academy(NC+SA 이중독성)는 완전 격리합니다.

**현재 상태**: 위험 소스 0건. 실제 백본 = A-/A/A+ 등급 21종 ~4M 레코드, NCIC 본문 redaction 삼중 방어, OCR은 공개 오픈소스·로컬 ONNX만(AGPL ultralytics는 코드에서 이중 차단). **리스크**는 전 조합이 "변호사 최종 검토 전제"라는 점 — 법률 검토는 코드로 대체할 수 없는 사람 게이트입니다.

> 정본: [`../data/licensing_safety.md`](../data/licensing_safety.md)

## §12. 리스크·병목 — 지금 가장 큰 위험은 검증 부채

종합 판정은 **"코어는 과잉 성숙, 제품 루프는 미성숙"**입니다. L1–L4와 품질 인프라는 Phase 1 요구를 초과했지만, 학생이 실제로 겪는 경험(L5 루프·L6 수능)은 골격입니다. 지금 가장 큰 리스크는 기술 부채가 아니라 **검증 부채** — 이 코어가 실제 고3의 30번 문제 앞에서 작동한다는 증거가 0건입니다.

**병목 Top 5**: ① 이중 truth source(S0에서 해소 중) ② Phaiakes9 라이브 검증 ③ E2E 루프 부재(S1) ④ 도메인 파트너 부재(M1.3 게이트) ⑤ L6 수능 모드 얇음. 이 중 **②와 ④는 AI가 못 푸는 사람 병목**입니다 — Phaiakes9 라이브 키·실측 비용 검증, 그리고 수학 교육 도메인 파트너·시범 사용자 채널은 Kiki의 수동 시간에 달려 있고, 이 둘이 크리티컬 패스에 있어 전체 일정을 좌우합니다.

**완화 방향**: 신규 설계 검토는 실증(S1)에서 발견된 문제에 의해서만 착수하고(정본화 국면 종료), AI는 측정 스크립트·대시보드를 선제 준비해 사람 병목의 대기 시간을 최소화합니다.

> 정본: [`../strategy/status_roadmap_2026-07.md`](../strategy/status_roadmap_2026-07.md) §2·§4
