## §2. 진짜 갭 설계

### G1 — 채점 권위 잠금이 **자기 잠금**이고, 현행 유일 경로의 커버리지가 **0**이다 (최대 갭 · `REC-05`)

**문제**. 1차는 입력 루프 미도달(D1)의 상류 원인을 채점 권위 공백으로 지목하고 순서를 잠갔다:

> §5-① 클라 attempt 제출 배선의 발화 트리거 = "`NLP-02` 관측이 착지해 **서버가 채점 권위를 가질
> 수 있음**이 확인됐을 때. 순서를 바꾸지 않는다"

`NLP-02`는 **done**으로 착지했다(`harness/attempt_grading_shadow_report.py`). 그런데 그 관측은
**설계상 결코 값을 낼 수 없다**. 두 겹의 0이 겹쳐 있다:

| 겹 | 실측 | 귀결 |
|---|---|---|
| ① **표본 0** | 리포트의 입력은 `problem_attempt` 행인데 앱이 `POST /v1/me/attempts`를 호출하지 않아 0행(2026-08-04 재실측 — 앱 호출 `/v1/` **13종 불변**) | `verifiable_count = 0` |
| ② **파생 가능 문항 0** | 파생 게이트 `derive_verify_inputs`(`:93`)는 모든 조건의 `formal`이 존재하고 자유기호 합집합이 정확히 `{x}`일 때만 입력을 만든다(`:128`). 코퍼스 2,647문항 중 `conditions_parsed`가 비어있지 않은 것은 **30건**이고, **그 30건 전부 `formal`이 `null`**이다 | attempt가 아무리 쌓여도 **verdict 0건** |

②가 결정적이다. ①은 언젠가 풀릴 수 있는 0이지만 ②는 **코퍼스가 바뀌지 않는 한 영구 0**이다.
`Condition.formal`은 스키마상 `default=None`인 선택 필드이고(`schema/problem.py:85`), 생성기 어느
것도 채우지 않는다. 즉 잠금은 이렇게 닫혀 있다:

```
attempt 0행 ─┐
             ├→ shadow verdict 0 → "권위를 가질 수 있는가" 판정 불가
formal 0건 ──┘        ↓
              §5-① 발화 조건 미충족 → 클라 attempt 배선 안 함 → attempt 0행 (순환)
```

**정직 표기가 오히려 실패를 덮는다**: `ShadowGradingReport.mismatch_rate`는 `verifiable_count == 0`이면
`None`을 돌려준다(`:230-234` — "분모 없는 0 금지" 규약 준수). 규약 자체는 옳지만, **분모가 0인 이유가
'표본이 없어서'인지 '파생이 원리적으로 불가능해서'인지 리포트가 구분하지 않는다.** 두 상태가 같은
값(`None`)을 낸다 — CLAUDE.md "변별력 없는 검증 스텝 금지"(2026-07-17 등재)의 리포트판이다.

**해제 재료는 attempt 없이도 이미 있다.** 채점 가능성은 **코퍼스만으로 정적 측정**할 수 있고,
그 값은 1%가 아니다(2026-08-04 실측, `data/corpus/problem_bank_*/problems.jsonl` 전량):

| 버킷 | 정의 | 실측 | 채점 결정성 |
|---|---|---|---|
| **A. 선택형 정확일치** | `choices` 보유 ∧ `answer`가 그 원소와 문자열 일치 | **1,616 / 2,647 (61.1%)** — 일치율 **1,616/1,616 (100%)** | **자명**(문자열 비교 1회·SymPy 불요) |
| **B. 수치 단답** | `question_format=단답형` ∧ `answer_format ∈ {자연수, 실수, 분수}` | **1,031 / 2,647 (38.9%)** — 자연수 558·실수 411·분수 62 | 정규화 규칙 필요(표기 변형) |
| **C. 조건 기반 symbolic 파생**(NLP-02 현행 유일 경로) | `conditions_parsed[*].formal` 전건 존재 ∧ 자유기호 = `{x}` | **0 / 2,647 (0.0%)** | — |

`answer` 결측은 **0건**이다. 즉 **코퍼스 전량이 A 또는 B에 든다.** 서버가 채점 권위를 가질 수
없어서 잠긴 것이 아니라, **가질 수 있는 61.1%를 한 번도 재지 않은 채** 0%짜리 경로 하나로 판정을
기다려 온 것이다.

**정합 설계** (신규 스키마 0 · 마이그레이션 0 · 클라 배선 0 · 권위 이관 0 — **관측만**)

- **① 코퍼스 정적 채점 가능성 리포트**: 문항 전량을 A/B/C **상호배타 버킷**으로 분류해 분모와
  함께 낸다. C가 0이면 "0건 통과"가 아니라 **"파생 불가(formal 전건 결측)"**로 표시한다
  (`REC-01`의 `NOT_REACHED` · `NLP-02`의 분모 없는 0 금지 규약 승계).
- **② shadow 리포트의 구조적 0 분리**: `verifiable_count == 0`의 원인을 **"표본 없음(attempt 0행)"**과
  **"파생 가능 문항 0(코퍼스 formal 결측)"**으로 나눠 **서로 다른 값**을 내게 한다.
- **③ 권위 이관·클라 배선은 범위 밖 동결**: `is_correct` 소비·BKT 입력·클라 계약 **무변경**
  (`NLP-02` acceptance③ 동결 승계). 이 태스크는 **결정의 입력 수치만** 만든다.
- **④ 결정은 사람이 한다** — 학습자 모델 전체(BKT·θ·추천)의 입력을 바꾸는 판단이므로 `REC-07`
  (owner=kiki·`depends_on: REC-05`)로 등재한다. `ASM-02`·`CUR-03` 선례.

**dead code 금지 충족**: 신규 테이블 0. 리포트 1개와 기존 리포트의 사유 분리만 추가한다.
**변별력**: 코퍼스에 `formal` 1건을 주입하면 C 버킷이 0→1로 오르고 되돌리면 0으로 복귀해야 한다.

**태스크**: 신설 — `REC-05-grading-coverage-ceiling` · `REC-07-grading-authority-transfer-decision`(kiki).

### G2 — 반복 호출 시 **동일 문항이 고정 반환**된다 (`REC-06`)

**문제**. 세 가지가 겹쳐 학생이 진도를 만들 수 없다. 전부 소스로 확정되는 사실이다:

| 단계 | 코드 | attempt 0행에서의 값 |
|---|---|---|
| θ 추정 | `l2/irt.py:77` `if not responses: return initial` | **θ = 0.0 고정** |
| 출제 이력 제외 | `api/me.py:1832` `attempted_ids = {...}` ← `ProblemAttempt`(`:1825`) · `:1967` `notin_(attempted_ids)` | **제외 0건**(집합이 비어 `where`가 아예 붙지 않음) |
| 선택 | `l2/irt.py:268` `select_weighted_item` — 가중 정보량 **결정론 argmax**, 동률은 낮은 인덱스 | **매번 같은 1건** |

⇒ 같은 학생이 `GET /v1/me/next-problem`을 몇 번을 불러도 **같은 문항을 받는다.** 1차는 "θ=0
콜드스타트"까지만 짚었고, 이 **학생 대면 귀결**은 어디에도 적히지 않았다. 앱의 다음 문제 흐름이
진도를 만들지 못한다는 뜻이며, 실기기 시연에서 즉시 보이는 형태다.

부가로 **후보 조회에는 결정론이 없다**: `candidate_stmt`의 `ORDER BY |b−θ|`(`api/me.py:1968`)에
2차 정렬 키가 없어 동률 구간의 순서가 PG 임의다. 결정론이 선택기(`select_weighted_item`)에만
있고 그 앞 단계에는 없다 — 같은 DB 상태에서 후보 풀 구성이 달라질 수 있다.

**왜 "다양성 가중을 넣자"가 답이 아닌가**: 반복의 원인은 선택기가 다양성을 모른다는 것이 아니라
**제외 축의 입력이 0**이라는 것이다. 가중을 얹으면 원인이 아니라 증상을 가린다 — 1차 D4가
"밴드 상수를 넣는 것이 답이 아니다"라고 판정한 것과 같은 형태다.

**정합 설계** (신규 스키마 0 · 무작위화 0 · 학생 축 이력 좌석 신설 0)

- **① 반복 추천 리포트**: 동일 조건 N회 연속 호출 시 서로 다른 `problem_id` 개수(= 진도 폭)와
  후보 풀 50의 개념·유형 집중도(`S3-27`이 채운 17유형 축)를 낸다. 합성 프로브·코퍼스만 쓰므로
  **attempt 0행에서도 산출된다**.
- **② 원인 구분**: 반복이 **"제외 축 0행(입력 미도달)"** 때문인지 **"후보 풀이 실제로 1건"**
  때문인지 서로 다른 값을 낸다(`l2/axis_exclusions.py` 사유 계상 패턴 답습 — 침묵 실패 금지).
- **③ 후보 조회 결정론 동결**: `ORDER BY`에 2차 키(`problem_id`)를 더해 동률 구간 순서를 고정한다.
  **무작위화가 아니다** — 기존 선택 결과의 회귀 0을 테스트로 동결한다.
- **④ 범위 밖 동결**: 노출 통제(randomesque top-k)·다양성 가중·학생 축 노출 이력 좌석 신설은
  하지 않는다. 이유는 G3이다.

**변별력**: attempt 1건을 주입하면 그 문항이 후보에서 빠져 반환 문항이 실제로 바뀌고, 되돌리면
원복돼야 한다. **태스크**: 신설 — `REC-06-repeat-recommendation-visibility`.

## §6. 반복 실수 — 새 형태 "만들었는데 **커버리지가 0**" (7회차 계열)
