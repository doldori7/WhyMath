## §0. 재점검 사유 — 왜 v1을 덮어쓰지 않고 r2를 새로 쓰는가

### ① v1의 승계 판정 5건 중 3건의 전제가 바뀌었다

v1은 진짜 갭을 2건(D1·D2)만 세우고, 나머지는 "이미 다른 태스크가 소유한 축이니 **재설계하지
않고 승계**한다"고 §3 등재요약에 명시했다. 그 승계는 그 시점에 옳았다. 그런데 승계 대상 중
`NLP-02`가 **done이 됐고**, v1이 만든 `ASM-01`·`ASM-02`도 done이 됐으며, v1이 "범위 밖"으로
명시 제외한 축들이 `ASM-03`·`ASM-04`·`ASM-05`·`ASM-07`로 착지했다.

| v1의 승계·유보 | v1 시점 판정 | 2026-08-11 현재 |
|---|---|---|
| 모듈 50·54·57 → `NLP-02` | "재설계 금지·승계" | **done** — 그러나 실효 커버리지 0.00%(**D3**) |
| 확장 56 → `S4-15` | "재설계 금지·승계"(`S3-01` 잠금) | todo·잠금 유지 — **변화 없음**(승계 계속 유효) |
| `REC-04` 목적 분리 | "승계" | 변화 없음(승계 계속 유효) |
| D1 좌석 writer 0 → `ASM-01` | "가시화만, 활성화는 범위 밖" | `ASM-01` done → `ASM-03`가 **활성화까지 착지** |
| 모듈 51 총괄평가 "완전 부재" | §4 정직한 공백 | `ASM-04`가 **조립까지 착지** — 판정 갱신 필요 |

**승계는 소유권 이전이지 작동 보장이 아니다.** r2의 존재 이유가 이것이다 — v1이 "저쪽이
소유한다"고 넘긴 축들이 착지한 뒤 *실제로 작동하는지*는 아무도 다시 보지 않았다.

### ② 이번 대조가 계획 단계의 갭 순위를 뒤집었다 (정직 표기)

순위가 **두 번** 바뀌었다. 착수 계획은 최대 갭을 "세트 시행 귀속 단절"로 잡았고, 착수 후 실측에서
shadow 파생 가능 비율 0.00%가 드러나 그것이 1위가 됐다가, PR 직전에 그 축이 **중복으로 밝혀져**
(④) 다시 내려갔다. 계획↔문서 대응은 최종적으로 이렇다:

| 착수 계획 | 초판 | **최종** | 사유 |
|---|---|---|---|
| 계획 D3(귀속 단절) | D5 | **D5**(2위) | 유효·미소유. 실응답 0행이라 severity는 D4 아래 |

  정직 표기 관례 · `ASM-01`의 "생성 경로 부재" 선례).
- **② 포착 슬롯 신설은 별도**: `AttemptSubmitRequest`에 `selected_choice_index: int | None`을

    이 제약을 갖고 있으므로 **승계**한다.

    별도 판정 경로를 신설하지 않는다(이중 진실원천 금지).
  - **점수·오답률 노출 금지** — v1 §2-① 승계.

**변별력**: ①에서 `distractor_map`을 가진 문항에 합성 시도를 넣어 "역추적 가능 0 / 시도 N"의

`session_id`(학습 세션)는 있으나 **`assessment_id`가 없다**(전수 grep 확인).

결과:
- 외부 틀 모듈 51의 분석 축(문항별 정답률 · 성취도 · 교육과정 달성률)이 **원천적으로 계산 불가**.
- `PATCH /assessments/{id}/complete`(`api/me.py:2481-2503`)는 `completed_at` **시각만 찍는다** —
  결과를 계산하는 코드가 0이다. 즉 "완료된 모의고사"는 존재할 수 있지만 그 안이 비어 있다.
- 세트 단위 심리측정(신뢰도 등)도 정의 자체가 불가능하다(§5-⑦ 발화 조건의 근거).

`ASM-04`는 이 한계를 **스스로 정직하게 자인**했다("세트 시행·채점 폐루프는 범위 밖(구성까지)").
문제는 그 자인에 **후속 소유자가 붙지 않았다**는 것이다 — 백로그 전수 grep에서 "시행"·"폐루프"를
소유한 태스크는 0건이다. 같은 artifacts가 자인한 잔여 2건(`partial_credit` 호출자 0 ·
멱등 창 미설정으로 같은 청사진 2회 POST 시 행 2건)도 마찬가지로 무주공산이다.

**핵심 판단 — 관측 먼저**(Kiki 결정 2026-08-11): 귀속 좌석(`problem_attempt.assessment_id`
컬럼 + 마이그레이션)을 지금 만들면 실응답 0행 위에 좌석부터 세우는 형태가 된다. 이 시리즈의
선례(`ASM-01` — 활성화가 아니라 가시화)를 따라 **먼저 "귀속 불가"를 보이게** 하고, 좌석 신설은
관측 결과를 발화 조건으로 삼는 별도 결정으로 분리한다.

**정합 설계** (신규 스키마 0 · 마이그레이션 0 · 신규 엔드포인트 0)

`ASM-01`의 `harness/assessment_seat_reach_report.py`가 만든 **DB형 4단 분리**를 그대로
답습한다(`collect_*`(AsyncSession 주입·ORM 쿼리빌더) → `build_report`(순수) →
`render_report`/`report_to_json`/`dump_json`(정렬 고정) → `main` CLI(exit 0/2 · **게이트 아님**)).

리포트가 말해야 하는 것:
1. `실전모의고사` 행 수와 각 세트의 선언 문항 수(`pattern_diagnosis` 헤더에서).
2. 세트 문항 id들에 대한 `problem_attempt` 존재 여부.
3. **그러나 그 시도가 이 세트에서 나온 것인지 판별할 수 없다**는 사실 — `unattributable`이라는
   **명시 상태**로 표기한다. "귀속 0건"으로 적으면 "아무도 안 풀었다"와 구분되지 않는다.
4. `completed_at`이 찍힌 세트 중 결과 산출물이 0인 건수(위 "빈 완료" 관측).
5. 같은 청사진의 중복 세트 건수(`ASM-04` 자인한 멱등 창 미설정의 실제 영향 — 0일 수도 있다).

**점수·등급·평균·표준편차를 산출하지 않는다** — CLAUDE.md 게임화 금기 · v1 §2-① 승계. 이
리포트가 내는 것은 성적이 아니라 **분석의 *가능성* 여부**다.

**변별력**: 합성 세트 + 그 세트 문항에 대한 합성 시도를 넣어 `unattributable` 카운터가 실제로
오르는지 → 제거 시 복원되는지 실측. 세트에 없는 문항의 시도는 카운터에 잡히지 않는지도 확인
(양방향 변별력).

**범위 밖**: `problem_attempt.assessment_id` 컬럼 신설·마이그레이션(별도 결정) · 채점·점수 산출 ·
`partial_credit` 호출자 배선 · 멱등 창 설계.

### D6 — 좌석은 채워지는데 **그것을 보는 화면이 정본 계획에도 없다** (`ASM-11` · 발화 조건부)

**문제**: `ASM-03`·`ASM-04`가 `Assessment` 행을 만들기 시작했다. 그런데:

- Flutter 학생 앱에서 `/me/assessments`·capture·assemble 소비 **0건**(`src/mobile/lib` 전수
  grep — `Icons.assessment_outlined` 아이콘명 1건이 유일 매치).
- 학생 UI 정본 계획에도 **적재된 assessment 행을 보는 화면이 없다**. "나" 탭은 실시간 진단
  엔드포인트를 읽으므로(`docs/design/ui/01_student_pipeline_to_menus.md:102`·`:82` —
  `diagnosis_controller.dart` → `GET /v1/me/next-problem`) **좌석을 우회한다**.

즉 v1 D1이 진단한 구조 — *"실동작 진단이 이 테이블을 아예 거치지 않고 즉석 계산해서, 진단이
작동한다는 체감과 좌석이 비어 있다는 사실이 서로 가려 왔다"* — 가 **writer 착지 이후에도 그대로**다.
이번엔 방향만 뒤집혔다: 좌석은 채워지는데 **아무도 보지 않는다.**

`learning_path_module_gap_review_r2.md` D5(Flutter가 파싱은 하는데 읽는 위젯이 0개)와 **동형**이고,
이 시리즈의 "완비된 소비 경로 + 미도달 공급원" 패턴의 **거울상**이다(§6).

**핵심 판단 — 화면부터 만들지 않는다**: 실응답 0행·파일럿 미가동 상태에서 화면을 먼저 만들면
"입력 없는 파이프라인"이다(`S4-15`를 잠근 것과 같은 논리). 그러나 **조건 없이 미루면 v1이
반복한 "만료 없는 유예"**가 된다. 그래서 태스크는 **등재하되 발화 조건을 명시**한다.

**정합 설계** (이 문서는 Flutter 구현을 설계하지 않는다 — `src/mobile` 무수정)

- **①** UI 정본(`docs/design/ui/02_student_ui_master_plan.md`)에 좌석 뷰가 부재하다는 사실을
  태스크 acceptance에 실측으로 고정한다(주장 확인 또는 반증 — 반증되면 범위 재조정).
- **②** 발화 조건 = **`S3-01-pilot-cohort` 가동 + D5(귀속) 해소**. 귀속이 없으면 세트 결과
  화면에 보여줄 내용 자체가 없다.
- **③** 노출 제약 선승계: 화면이 생기더라도 **예측 5필드는 구조적으로 부재**하다
  (`schema/assessment.py::STUDENT_HIDDEN_PREDICTION_FIELDS` · `ASM-07` 봉인이 이미 물려 있음).
  점수·등급·랭킹은 만들지 않는다(전역 UI 불변식 2 — 반게임화).

**의존**: `S3-01-pilot-cohort` · D5(`ASM-10`).

**인접 축(중복 아님·착수 시 조율)**: `REC-10-next-problem-honesty-fields-render`(todo·mobile)가
같은 계열의 Flutter 렌더 갭을 소유한다 — 다만 대상 표면이 다르다(`NextProblemResponse`의 추천
정직 표기 필드 vs 이 D6의 `/me/assessments` **좌석 뷰**). 두 태스크가 `src/mobile`을 같이
건드리므로 병렬 착수 시 파일 겹침을 먼저 확인한다(`docs/standards/parallel_sessions.md`).
