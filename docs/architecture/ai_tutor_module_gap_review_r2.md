## §2. 잔여 갭 — 실측 (G1~G6)

### G1 — 개념 질의 경로 부재 (v1 `✅` 오판정 · 문서의 대표 예시가 작동하지 않는다) → D7

외부 문서 §37이 가장 앞에 놓은 대화 예시가 이것이다:

> 학생: 왜 음수끼리는 곱하면 양수가 되나요?
> AI: 먼저 음수의 곱셈이 어떤 상황을 의미하는지 함께 생각해 볼까요?

현행 WhyMath에 이 발화를 넣으면 코치는 **문제풀이 스캐폴드**를 반환한다. 4개 축 전부에서
개념 질의를 받을 좌석이 없다:

1. **발화 템플릿이 문항·개념과 무관한 정적 문자열**이다 — `l4/polya/prompts.py:43-85`
   `_STAGE_1_PROMPT`~`_STAGE_4_PROMPT`는 "이 문제, 잠깐 같이 읽어볼까? / 1. *주어진 정보*가
   뭐야?"처럼 **풀 문제가 있다고 전제**한다. 학생이 무엇을 물었는지 반영되는 슬롯이 0이다.
2. **LLM이 학생의 질문을 볼 수 없다** — `harness/wh1_llm_policy.py:202-203` `_build_prompt`는
   "`TurnState`를 비민감 JSON 요약으로 압축 — **학생 원문·정답 원문 미포함**"이라고 스스로
   명시하고, 실제 요약 필드는 `turn_index`·`tool_calls`·가설 id·verify 판정뿐이다.
   `harness/wh1_primary.py:144`도 "학생 원문·풀이 단계는 프롬프트가 아니라 정책 보유값으로만
   사적 사용(S1-a 계약)"이라 못박는다. **이건 프라이버시 설계의 정상 작동이지 결함이 아니다** —
   다만 그 결과로 "학생이 물은 것에 답한다"가 구조적으로 불가능하다.
3. **요청 스키마에 개념 축이 없다** — `api/coach.py:198` `CoachRequest`의 필드는
   `student_input`·`student_solution`·`polya_state`·`mastery_level`·`bkt_mastery`·
   `coaching_focus`·`solution_steps`·`solution_step_types`. `concept_id`가 없고 `problem_id`도
   세션 생성 시에만 붙는다.
4. **개념 설명 콘텐츠는 있는데 학생 경로 reader가 0이다** —
   `db/models/concept_content.py:76,82`에 `metaphor`·`explanation` 컬럼이 실재하나 백엔드
   소비처가 없다. 조회 좌석인 `api/concepts.py:31,206`은 스스로 "**학생 직접 노출이 아니라**
   L2/L4·교사 도구가 소비하는 내부 표면"이라 노출 계약을 선언한다.

**왜 v1이 놓쳤는가**: v1은 "자연어 질의응답"과 "개념 설명"을 한 행으로 압축해 `POST /v1/coach`
엔드포인트의 **존재**를 충족 근거로 삼았다(`v1:86`). 엔드포인트는 있고 대화도 되지만, 그것이
답하는 질문의 **종류**를 확인하지 않았다 — 표면 존재를 능력으로 읽은 판정이다.

### G2 — 의도가 기록되나 라우팅하지 않는다 (G1과 한 쌍) → D7

`PED-04`(v1 D1)가 `student_intent` writer를 놓았다. 실측 배선:

- **writer 3곳**: `api/coach.py:1687`(턴 메타 적재) · `:1964`(`create_session`) ·
  `:2277`(`append_turns`) ← `l4/turn_meta.py:203` `classify_student_intent`(결정론·LLM 0회,
  `답시도`/`질문`/`막힘표현`/`포기`/`이해확인` 5종).
- **reader 1곳**: `api/coach.py:1458` — 세션 회상용 **컬럼 투영**뿐이다.
- **교수 결정 경로의 reader 0**: `PolyaCoach.decide`(전이) · `select_category`(질문 유형) ·
  `decide_hint_level`(도움량) 어느 것도 `student_intent`를 인자로 받지 않는다.

즉 튜터는 **학생이 무엇을 하려는지 판단해 기록해 놓고, 그 판단을 쓰지 않는다**. 이건 v1이
진단한 "계산은 하는데 기록하지 않는다"의 **거울상** — 이번엔 기록은 하는데 읽지 않는다.

**이건 "선언≠집행"이 아니라 설계가 애초에 절반이었던 축이다.** v1 D1은 writer만 약속했고
(`v1:250-255`) reader는 `recent_categories` 회전과 세션 회상 2종만 설계했다 — `student_intent`
소비는 **처음부터 범위에 없었다**. `PED-04`는 약속한 것을 전부 지켰다. 갭은 구현이 아니라
설계에 있다. `질문` 의도가 G1의 라우팅 키이므로 두 갭은 **한 슬라이스**로 묶는다.

### G3 — WH-1 primary 작동 비율 미관측 (최대 갭 · 신뢰 축) → D8

WH-1 primary는 `config.py:168` `wh1_primary_enabled` 기본 **True**(2026-07-20 GA)로, 코치
세션/턴의 **학생 대면 발화 정본 경로**다. 실패하면 결정론 정적 템플릿으로 폴백한다 — 안전
설계로서 옳다. 문제는 **폴백이 일어났다는 사실이 어디에도 남지 않는다**는 것이다.

**① 폴백 3경로 중 가장 흔한 하나가 원장에서 빠진다**

| 폴백 사유 | 위치 | 관측 레코드 |
|---|---|---|
| provider 실패·타임아웃 | `harness/wh1_primary.py:172-178` | **없음** — `logger.warning` 후 `return None` |
| `budget_exhausted`·발화 없음 | `wh1_primary.py:182` | `_safe_emit` ✅ |
| 프로즈 게이트 거부 | `wh1_primary.py:205` | `_safe_emit` ✅ |

Ollama 미기동·클라우드 타임아웃은 프로덕션에서 **가장 흔한 실패**인데 정확히 그 경로만

### D8 — WH-1 primary 작동 비율 관측 (G3 · 최우선 · 백로그 `PED-18`)

**문제**: 학생 대면 발화의 정본 경로가 GA 3주가 지나도록 **작동 비율 좌석이 없다**. 폴백 3경로

**핵심 판단**: 새 관측 인프라를 만들지 않는다. **이미 있는 원장에 빠진 사유 하나를 채우고,
이미 있는 지표 세트에 좌석 하나를 여는 일**이다(`PED-06`의 "활성화가 아니라 가시화" 계열).

**정합 설계** (신규 테이블·마이그레이션·enum 0)
- **① 폴백 원장 결손 봉합** — `harness/wh1_primary.py:172-178` 예외 경로가 관측 레코드를
  남기게 한다. 이 경로에는 `TurnOutcome`이 없으므로 기존
  `Wh1HarnessShadowObservation`(`harness/wh1_shadow.py:59`)의 `status` 값 공간을 넓히는 형태로
  간다 — **신규 모델 0**. 실을 수 있는 것은 **예외 타입명뿐**(원문·시크릿·필드값 0). 모델의
  `extra="forbid"`가 프라이버시 계약을 구조적으로 강제하는 성질을 깨지 않는다.
  *착수 시 확정 항목*: `status` 리터럴 확장 vs nullable 사유 필드 — 수확기
  (`wh1_shadow_harvest.summarize`)의 구판 레코드 하위호환(`n_correct: None` 선례)을 실측한 뒤
  택일한다.
- **② 라이브 집계 좌석** — `harness/wh1_evaluation.py`에 대리지표 ⑰
  `primary_utterance_rate`(= 발화 채택 턴 / primary 시도 턴). 시도 턴이 0이면 값이 아니라
  **`MetricStatus` 미계측**으로 낸다(0%와 "아직 안 돌았음"을 구분 — 기존 `NO_DATA` 관례).
  폴백 사유 분포는 `note`에 정직 표기한다.
- **③ 노출 계층 배정 — 좌석과 같은 슬라이스에서** —
  `harness/growth_evidence_exposure.py:65` `_STATIC_TIER`에 **`INTERNAL_ONLY`** 로 등재한다.
  선례는 `tokens_per_turn`(시스템 품질·비용 지표라 INTERNAL_ONLY)이며 ⑰도 같은 성격이다.
  좌석만 만들고 계층을 잇지 않으면 `PED-06`→`PED-08`(정본화≠집행)의 재발이다 —
  `PED-14` acceptance ④가 같은 규칙을 이미 명문화했다.
- **④ 하지 않는 것** — 폴백 시 **학생 대면 동작 변경 0**(정적 템플릿 폴백은 안전 설계로 유지) ·
  경보·알림 배선 0 · `/harness-metrics` 원시 표면 구조 변경 0(`PED-08`이 동결한 경계) ·

**dead code 금지 충족**: 신규 테이블·컬럼·enum 0. writer(①)와 reader(②③)가 **동일 슬라이스**.

**측정 없는 도입 없음**: 이 태스크 자체가 측정 인프라이며 학생 대면 변화가 0이다. 따라서
성립 근거는 **변별력 양방향 실증**에 있다 — provider를 강제 실패시키면 비율이 떨어지고

**의존**: 없음(즉시 착수 가능). **D7(`PED-19`)의 판정 전제**. **태스크**: `PED-18` 등재.

경향**이 있다 — v1 D5의 acceptance 3항은 전부 서버 항목이었고(`review-queue` 반환·첫 reader·
정직 표기), 학생 도달을 묻는 항목이 하나도 없었다. 착지 판정이 acceptance를 따르므로,
