## 책임

학생·학부모·교사를 잇는 *사회적 학습* 인프라.

## 핵심 컴포넌트

### 1. 다중 풀이 갤러리
- 학생 본인 풀이 완료 *후* 다른 학생 익명 풀이 열람
- 다양성 우선 (같은 접근 중복 최소)
- 수준 다양성 (자기보다 우수 + 비슷)
- 랭킹·경쟁 **금지**

### 2. Live Problems (NRICH 모델)
- 풀이 미공개 문제 주 1회 신규
- 학생 풀이 익명 제출
- 마감 후 모범 풀이 큐레이션 공개
- 학생 *기여 경험* (수학 커뮤니티 의식)

### 3. 학부모 보고서
- 주 1회 푸시 (학생이 *동의 시*)
- 학생 약점·강점·메타인지 순간
- 5분 대화 주제 추천
- 비교·랭킹 ❌
- **PRD 학부모 기능 통합**: PRD v1.1의 *주간 리포트*는 이 컴포넌트로 흡수한다. PRD가 강조하는 **긍정 톤** 원칙 — 부모에게 가는 모든 표현은 비난·불안 조장이 아니라 *구체적·정직한 관찰 + 행동 제안* — 은 아래 "표현 안전선"과 같은 결이며 L4 톤 필터(`04_pedagogy_engine.md`)를 학부모 보고서 생성에도 적용한다.

### 4. 교사 대시보드 (Phase 3+, B2B)
- 학급 학습 상태
- 학생별 인사이트 (PII 최소)
- 콘텐츠 추천
- 학부모 보고서 발송
- **PRD 교사 기능 통합**: PRD v1.1의 교사 기능 — *숙제 출제*, *자동 채점*, *수업 영사(projection) 모드* — 를 이 컴포넌트로 흡수한다.
  - *숙제 출제*: 교사가 성취기준 코드·단원 기준으로 문항 세트를 학급에 배정. L6 모드의 콘텐츠 풀을 재사용.
  - *자동 채점*: 학생 손글씨 풀이를 L5 OCR → L3 PRM 단계 검증으로 채점. 단, "정답/오답" 이분법이 아니라 *어느 단계에서 막혔는지*까지 교사에게 전달 (WhyMath 단계별 진단 철학 유지).
  - *수업 영사 모드*: 교사가 교실 화면에 띄우는 뷰 — 학급 집계·익명 풀이 다양성을 보여주되 *개별 학생 식별 정보는 표시하지 않는다* (아래 안전선).
  - 세 기능 모두 **Phase 3+ B2B**로 배치 — Phase 1~2는 학생 경험 집중.

### 5. 학교·교사 콘텐츠 기여 (Phase 4+)
- NRICH 교사 기여 모델
- 검수 후 production
- 출처·인용 명시

## 안전선

### 학생 데이터 노출 안전선
- ❌ 학생 이름·학교 표시
- ❌ 다른 학생 풀이를 *본인 풀이 전에* 노출
- ❌ "최고 풀이" 랭킹
- ❌ 부모에게 *불필요한* 학생 PII
- ✅ 익명·집계만

### 표현 안전선
- ❌ 학생 비난·비교
- ❌ 과장된 칭찬
- ✅ 구체적·정직한 관찰
- ✅ 행동 제안

## 전달 형태 — 단일 앱 모드 분기 (PRD 3개 앱 분리는 반려)

> MathScope PRD v1.1을 정본으로 흡수하며 정렬한 입장. 채택 근거는 `MEMORY.md` 2026-05-14 결정 로그 참조.

PRD v1.1은 학생·교사·학부모를 **3개의 별도 앱**으로 나눌 것을 제안하나, WhyMath는 이를 **반려한다**. L7의 교사·학부모 기능은 다음 형태로 전달한다:

- **Flutter 단일 학생앱 + 별도 교사 웹**: 학부모 보고서는 학생앱 내 *역할별 UI·권한 레이어*(L6 모드 분기와 같은 메커니즘, `06_application_modes.md` 참조). **교사 대시보드는 별도 웹(React/Next)으로 Phase 3+** (시험지 빌더·SEO·검색유입·공유는 PC 웹 작업, 슬라이스 89). 어느 쪽이든 수학 로직은 독립 코어(L1-L4) API로 소비.
- **대시보드는 Phase 3+**: 교사 대시보드·학부모 보고서 모두 Phase 3 이후 도입 — 아래 "Phase별 진입"과 일치. Phase 1~2는 학생 경험에 집중.

**반려 근거**:

- 코어 상태(BKT·오개념·`MasteryState`)는 학생·교사·학부모가 *같은 데이터의 다른 뷰*를 보는 구조 — L7의 선순환("데이터 누적 → 모델 개선 → 콘텐츠 풍부")이 단일 코드베이스에서 자연스럽다. 앱을 나누면 동기화 비용만 늘어난다.
- 4~5명 팀이 3개 앱을 동시 개발·유지하는 것은 범위 폭발 — `MEMORY.md` 폐기 패턴 "처음부터 풀 K-12"와 같은 리스크.
- L7 자체가 "느리지만 결정적 자산"으로 Phase 3+에 무게가 실린다 — 앱 분리는 그 시점에도 불필요하다.
