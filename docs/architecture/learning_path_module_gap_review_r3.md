## §0. 재점검 사유 — 이 편이 v1·r2와 다른 지점

### ① 같은 기능 4종, 다른 말미

세 docx는 기능 54~57을 공유하지만 말미가 다르다:

| 편 | 말미 구성 | 대조 편 |
|---|---|---|
| 『1단계: 학습 경로(Path)』 | 기능 4종 + 아키텍처 다이어그램 | **v1**(2026-08-03) |
| 『08. 학습 경로(Path)』 | + **확장 제안 58~62** | **r2**(2026-08-11) |
| **『13. 학습 경로(Path)』** | + **「WhyMath에서의 핵심 차별화」5요소** + Physics Misconception DB 연계 | **이 문서** |

기능 4종은 v1이 전수 대조했으므로 **재대조하지 않는다**. 이 문서가 다루는 것은 ⑴ 아키텍처
다이어그램의 **fan-in 종단**(v1이 한 줄로 넘긴 곳)과 ⑵ **핵심 차별화 5요소**다.

### ② v1이 종단을 넘긴 방식과, 그 뒤에 일어난 일

v1 §1 (횡단)은 이렇게 적었다:

> **5단(학생 대시보드)은 클라 소비 0**이라 파이프라인 끝단이 열려 있다(`REC-01` 소관).
> 즉 아키텍처는 어긋나지 않았고 **끝에서 두 마디가 아직 연결되지 않았을 뿐**이다.

그 뒤 세 가지가 일어났다:

| 사건 | 결과 |
|---|---|
| `REC-01` done | 입력 루프 미도달을 **관측·정직 표기**했다. 배선은 아니다 |
| `S4-18` done | 복습·목표 두 엔드포인트를 **서버에 착지**시켰다(끝에서 두 번째 마디) |
| `PATH-05` done | 대시보드 좌석(Me 탭)을 만들고 **경로·진단 2갈래를 배선**했다(끝 마디의 절반) |

**"끝에서 두 마디"가 이제 "끝 마디의 절반"으로 줄었는데, 남은 절반의 소유자가 없다.**
`REC-01`은 done이고(관측만 소유), `S4-18`은 backend 레이어로 done이고, `PATH-05`는 범위가
경로·진단으로 못박혀 있다. **v1이 소관을 지정한 태스크가 전부 닫혔는데 일은 남았다.**

이것이 v1을 고치지 않고 r3를 쓰는 이유다 — 어느 판정이 **언제 무엇 때문에** 바뀌었는지가
그 자체로 기록 가치이기 때문이다(r2 §8이 확립한 규율).

## §1. 다이어그램 fan-in 종단 전수 대조 ← **이 문서의 새 축**

틀의 다이어그램:

```
진단평가 → 학습 수준 분석 → Knowledge Graph 분석
                                  │
              ┌───────────────────┼───────────────────┐
              ▼                   ▼                   ▼
        선수학습 추천        학습 경로 생성        복습 일정 생성
              └───────────────────┼───────────────────┘
                                  ▼
                        목표 기반 학습 플랜
                                  ▼
                       **학생 대시보드 제공**
```

판정 글리프: `✅` 충족·초과 / `△` 부분(부품은 있는데 배선·데이터·기본값 없음) /
`⚠️` 진짜 갭 → D / `🚫` 의도적 미채택 → §5

| 갈래 | 서버 좌석 | 학생 도달 (Flutter 실측) | 판정 |
|---|---|---|---|
| 선수학습 추천 | `GET /v1/me/weak-concepts/{id}/prerequisites`(재귀 CTE) | **미호출** — 단, 경로 응답이 같은 정보를 포함해 **기능상 도달** | ✅(v1 승계) |
| 학습 경로 생성 | `GET /v1/me/weak-concepts/{id}/learning-path` | **호출** — `me_screen.dart:100` `_LearningPathSection` | ✅ `PATH-05` |
| (진단·수준분석) | `GET /v1/me/diagnosis/concepts` | **호출** — `me_screen.dart:180` `_DiagnosisSection` | ✅ `PATH-05` |
| **복습 일정 생성** | `GET /v1/me/review-queue`(`S4-18`·라이브) | **0건** | ⚠️ → **D7** |
| **목표 기반 학습 플랜** | `GET /v1/me/target-progress`(`S4-18`·라이브) | **0건** | ⚠️ → **D8** |
| 학생 대시보드(종단) | Me 탭(`me_screen.dart`) | **좌석 실재 · 4갈래 중 2갈래만 도달** | ⚠️ 위 둘의 합 |

**Flutter가 부르는 `/v1/me` 라우트는 정확히 3종이다** — `next-problem` · `diagnosis/concepts` ·
`weak-concepts/{id}/learning-path`(`problems_api.dart:30,54,72`). 그게 전부다(부록 A).

### §1 종합 — 파이프라인은 어긋나지 않았고, **끝 마디의 절반이 비어 있다**

v1의 판정("아키텍처는 어긋나지 않았다")은 **전건 유효**하다. 이 문서는 그것을 뒤집지 않는다.
바뀐 것은 **비어 있는 자리의 크기와 소유 상태**다: v1 시점엔 "두 마디 · `REC-01` 소관"이었고,
지금은 **"반 마디 · 무소유"**다.

**무소유임을 실측으로 확정한 근거** — mobile 레이어 `todo` 전수는 `MATH-05`(표기 역방향) ·
`MOB-11`(복귀 지원) · `PATH-10`(정렬 근거 렌더) · `S3-25`(섀도 회수) **4건뿐**이며,
어느 것도 복습·목표 축이 아니다(부록 B).

## §2. 「WhyMath에서의 핵심 차별화」5요소 대조

틀은 말미에 "네 기능이 독립이 아니라 **하나의 적응형 학습 엔진으로 통합될 때** 효과가 크다"며
5요소 아키텍처를 제안한다. **결론: 신규 태스크 0건.** 4요소는 승계·충족이고, 1요소만 정정이 있다.

| # | 요소 | WhyMath 현행 (실측) | 판정 |
|---|---|---|---|
| 1 | **진단 및 실시간 평가 엔진** — 실력·오개념·학습 속도 지속 분석 | `compute_concept_diagnoses`(BKT×IRT 교차검증) + IRT CAT(θ 매 요청 재추정). 다만 **학습 속도**의 원천인 `ProblemAttempt.duration_seconds`는 **0행**(입력 루프 미도달) | ✅ + ⚠️ **`REC-01` 소관**(중복 등재 금지) |
| 2 | **지식 그래프** — 선수·후속 관계로 최적 순서 계산 | 원자 백본 2,683노드·2,210 prerequisite 엣지 · Kahn 위상정렬 · DAG hard error 보장 | ✅ v1 승계 |
| 3 | **학습 경로 최적화 엔진** — 목표·남은 기간·가능 시간 반영 | 목표·기간은 `target-progress`가 보유(단 §5-⑪). **가능 시간은 v1 §2-② 영구 미채택**(생산자 없는 신호) | ✅ 부분 + 🚫 승계 |

## §3. 잔여 갭 설계 (D7~D9)

번호는 v1의 D1~D3 · r2의 D4~D6을 잇는다.

### D7 — 복습 큐가 학생에게 도달하지 않는다 (`PATH-12`)

**문제**: `S4-18`(done, 2026-08-10)이 `GET /v1/me/review-queue`를 라이브로 착지시켰다.
`ReviewQueueItem`은 `decayed_mastery`·`days_since_practice`·`due_rank`를 갖고, 응답은
`decay_model='bkt_p_forget'`·`calibrated=false` 정직 표기까지 동반한다. **좌석은 완성이다.**

그런데 `src/mobile/lib/` 전수에서 `review-queue` 참조가 **0건**이다. 이 응답을 볼 수 있는
사람은 **아무도 없다** — 학생 앱이 부르지 않고, 웹 대시보드는 Phase 3+이며, 관리자 콘솔의
표면도 아니다. 유일한 호출자는 `tests/backend/api/test_me_review_queue.py`다.

**왜 지금까지 안 드러났는가** (세 겹의 무증상):
1. **`S4-18`은 backend 레이어 태스크**였고 acceptance 3항 전부가 서버 산출물(파생 계산·
   컬럼 0·정직 표기)이다. 클라 배선은 **애초에 범위가 아니었고**, 후속 태스크도 열리지 않았다.
2. **`PATH-05`는 범위가 경로·진단으로 못박혀 있었다.** 대시보드 좌석을 만든 태스크가
   복습 갈래를 모르는 채 닫혔다.
3. **어떤 게이트도 이것을 red로 만들지 않는다** — D9의 주제다. 테스트가 라우트를 관통하므로
   `OPS-22` 감사기는 `reached`로 판정한다.

**정합 설계 (신규 백엔드 엔드포인트 0 · `src/backend` 0줄 · 신규 API 0)**:
Me 탭에 복습 섹션을 하나 더 둔다. `_LearningPathSection`의 구조를 그대로 답습하고
`_MessageRow(dense: true)`·`MeTabState.SectionStatus`(401/그 외 실패 분리)를 재사용한다.

**서버 순서를 그대로 렌더한다** — `decayed_mastery` 오름차순은 서버가 이미 정했고, 클라는
View Layer다(전역 UI 불변식 1 "표현 ≠ 의미" · `ARCH-10` 클라 수학로직 금지 게이트).
클라에서 재정렬·재계산하지 않는다.

**정직 표기 동반 이동** — `calibrated=false`·`decay_model`을 삼키지 않고 표기한다.

### D8 — 목표축 노출이 **결정되지 않은 채 방치** (`PATH-13`)

**문제**: D7과 표면적으로는 같다 — `GET /v1/me/target-progress`도 클라 소비 **0건**이다.
그러나 **막는 것이 다르다.** D7은 그냥 안 이었을 뿐이지만, D8에는 **불변식 충돌**이 있다.

`TargetProgress`의 필드는 6개다:

| 필드 | 성격 | 학생 노출 가능성 |
|---|---|---|
| `days_until_exam` | 목표일까지 **남은 일수** | **카운트다운 그 자체** |
| `target_grade` | 목표 수능 등급 1~9(echo) | 등급 = 서열 표면 |
| `target_score` | 목표 표준점수(echo) | 점수 = 서열 표면 |
| `target_exam_date` | 목표 시험일(echo) | 날짜 자체는 중립 |
| `standard_coverage_percent`/`observed`/`scope` | **성취기준 커버리지** | 성장 서술 |

그리고 전역 UI 불변식 2는 이렇게 못박는다(`docs/design/ui/00_index.md:43`):

> **반(反)게임화** — 정답률 랭킹·스트릭·**카운트다운**·보상 연출 금지. 학습 경로 시각화는 허용.

이 불변식은 **산문이 아니라 집행되는 계약**이다 — `src/mobile/test/governance/
anti_gamification_governance_test.dart`(ARCH-26)가 `lib/**` 소스를 전수 스캔하고,
`me_screen.dart:13`은 **화면 자신이 "카운트다운을 두지 않는다"고 선언**하고 있다.

**즉 `days_until_exam`을 Me 탭에 그대로 렌더하면 그 화면은 자기 주석을 위반한다.**

**그런데 이 충돌이 어디에도 적혀 있지 않다.** `S4-18`의 acceptance에도, `target_progress.py`
docstring(점수 예측 금지는 명시하되 D-day는 언급 없음)에도, `OPS-22` 대장의 by-design
사유에도 없다. 지금 미노출인 것은 **결정의 결과가 아니라 아무도 판단하지 않은 결과**다.
CLAUDE.md **"만료 없는 유예·제외 금지"**(2026-08-03)가 겨냥하는 상태다.

**판정 (Kiki 확정 2026-08-11) — 커버리지만 노출한다.**

| 필드 | 판정 | 근거 |
|---|---|---|
| `standard_coverage_percent`/`observed`/`scope` | **노출** | 카운트다운도 서열도 아니다. "목표 대비 어디까지 왔나"에 답하는 유일한 축 |
| `days_until_exam` | **미노출·구조적 배제** | 카운트다운 금지 불변식 정면 위반 |
| `target_grade`·`target_score` | **미노출** | 등급·점수는 서열 표면(v1 §2-⑤ 계열) |
| `target_exam_date` | **미노출**(이번 범위) | 단독으로는 중립이나, 옆에 커버리지가 있으면 학생이 잔여일을 **암산**한다 — 카운트다운을 클라 밖으로 밀어낸 것과 같다 |

**이것은 틀에 대한 의도적 거절이다.** 틀의 기능 57은 "남은 기간 45일 · 필요 학습량 112개 개념 ·
340문제 · 복습 9회"를 계산해 보여주라고 요구한다. WhyMath는 **그 요구를 받지 않으면서
"목표 대비 어디까지 왔나"에는 답한다.** 거절과 응답이 같은 화면에서 일어난다.

**정합 설계 (신규 백엔드 엔드포인트 0 · `src/backend` 0줄)**:
- Me 탭에 커버리지만 렌더한다.
- `school_type`이 `None`이면 세 커버리지 필드가 **전부 `None`**이다(서버가 0%로 위장하지 않고
  정직하게 비운 상태 — `target_progress.py` docstring). 클라도 **0%로 렌더하지 않는다** —
  "아직 범위를 정할 수 없어요"에 해당하는 별도 상태로 구분한다.
- 미노출 3필드가 **위젯 트리에 부재**함을 테스트로 동결한다. 값을 렌더하면 red가 나야 한다.

**어조 제약**: 커버리지는 **부족분 고발이 아니라 성장 서술**이다. "아직 X% 남았어요"가 아니라
"지금까지 관측된 범위"를 말한다. 말하는 대상은 **데이터의 관측 범위**이지 학생이 아니다.

**표면 구분 (중복 방지)**: 이 노출은 `PED-08`이 만든 `GET /v1/me/growth-evidence`와 **다른
표면**이다 — 후자는 WH-1 튜터링 **대리 지표 9종**(힌트 깊이·교정 등)을 노출 계약
(`classify_metric_exposure`) 경유로 내보내고, 이쪽은 **성취기준 커버리지**다. 지표군이
겹치지 않으므로 노출 계약 우회 표면을 새로 여는 것이 아니다. (`PED-06`이 정본화하고 `PED-08`이
집행 지점을 만든 계약을 **침범하지 않음**을 리뷰 게이트로 확인한다.)

**하지 말 것**:
- 점수·등급 **예측** — `ASM-07` 봉인 소관이고 `TargetProgress.model_fields` 집합 동등
  assert가 이미 예측 필드의 자리 자체를 막는다.
- 학교 일정·모의고사 일정 — 데이터 적재 0(v1 §2-② 계열, 생산자 없음).
- 하루 학습 가능 시간·요일별 학습량 — v1 §2-②③ **영구 미채택**.
- 잔여일을 클라에서 **계산** — 서버가 안 주는 것을 클라가 만들면 불변식 1·2를 동시에 어긴다.

**의존**: 없음. D7과 **독립**이다(다른 엔드포인트·다른 판정 근거).
**태스크**: 신설 — `PATH-13`(S4 · priority 4 · **layer=mobile**).

### D9 — 「학생 도달」축이 없어 이 갭이 **구조적으로 안 보였다** (`OPS-34`)

**문제**: D7·D8이 **하루가 아니라 며칠간 아무 게이트도 울리지 않고** 지나간 이유는 우연이
아니다. `OPS-22`(done)가 만든 `declared_unwired_audit`의 HTTP 축은 `reached`를 이렇게 정의한다
(`ops/declared_unwired_audit.py:892-897`, **감사기 자신의 주석**):

> **정직한 잔여**(유예 문구가 실제로 말하던 것): 이 축의 `reached`는 "dart 클라 호출 ∪
> 백엔드 테스트 호출"이므로, 위 7건이 reached라는 사실은 *테스트가 관통한다*는 뜻이지
> *학생 앱이 쓴다*는 뜻이 아니다. […] **이 축은 그 구분을 표현하지 못한다** — 클라 소비
> 공백을 보려면 **dart 호출만 따로 세는 별도 축이 필요**하고, **그것은 이 태스크 범위 밖**이다
> (`OPS-25` 리포트에 잔여로 기록).

**그 별도 축의 소유 태스크는 0건이다.** `OPS-29`(CI 집행 선언) · `OPS-30`(알림) ·
`OPS-31`(백업) · `OPS-32`(의존성 선언) 어느 것도 이 축이 아니다(부록 C).

`review-queue`·`target-progress`는 `_MANIFEST`에 **등재조차 되지 않았다** — 테스트가 있으니
자동으로 `reached`이고, 미분류가 아니므로 exit 1이 나지 않는다. **정직 표기를 요구하는 게이트
자신이, 자기 테스트로 만족된다.**

**이미 이 정의가 태스크를 닫은 실사례가 있다.** `PED-15`는 제목이
"성장 증거 서빙 엔드포인트 **클라 도달 0** — `GET /v1/me/growth-evidence`를 부르는 곳이 없다"이고
`layer: mobile`인데, **`acceptance: []`이고 산출물은 backend 테스트 1건**이다. artifacts 필드가
스스로 이렇게 적는다:

> 정직한 잔여: 이 엔드포인트를 소비하는 **모바일 클라이언트는 여전히 0건**(성장 증거 화면 없음)
> — **도달 증명이지 학생 화면 배선이 아니다.**

기록은 완벽히 정직하다. **그런데 태스크는 `done`이고, 남은 일의 소유자는 사라졌다**
(실측: `grep -rin "growth" src/mobile/lib/` → **0건**). D7·D8이 방치될 뻔한 것과 **같은
메커니즘**이며, 이 메커니즘에 소유자를 붙이지 않으면 다음 엔드포인트에서 또 일어난다.

**정합 설계 (`OPS-22` 대체 0 · 신규 대장 파일 0 · 기존 4축 정의 변경 0)**:
`AXIS_HTTP`에 **dart 호출만 세는 파생 축**을 하나 더 둔다. 판정 3분류
(`client-reached` / `by-design:<사유>` / `pending-task:<id>`)는 `OPS-22`의 기존 계약을
**그대로 재사용**하고, 라우트 추출은 `route_paths()`를 재호출한다(재구현 0 — `OPS-22`
acceptance ③이 확립한 규율).

**그랜드파더 만료 계약을 승계한다** — `pending-task:<id>`는 해당 태스크가 실재하고

**변별력 (양방향)**: 학생 대면 라우트의 dart 호출을 떼면 **exit 1**, 배선하면 **exit 0**,

**의존**: 없음.

|---|---|---|

## §6. 반복 실수 — **10회차 (새로운 축)** 등재

v1 §6은 8회차까지, r2 §9는 9회차를 등재했다:

| 회차 | 형태 |
|---|---|
| 1~8 | 만들고 **배선 안 함** / **적재 안 함** / **배포에 넣지 않음** / **입력을 잇지 않음** / **켜지 않음** / **공급원을 잇지 않음** / **분해하지 않음** / **기본값으로 껐음** |
| 9(r2) | 만들고 켰는데, **경계를 넘을 때 흘림** |
| **10(신규)** | **측정 정의가 느슨해, 미완이 완료로 읽혔다** |

**10회차가 새로운 축인 이유**: 1~8은 *아무도 재지 않아서* 안 보였고, 9는 *값이 경계에서
떨어져서* 안 보였다. 이번 것은 **재는 장치가 있고, 정상 작동하며, 통과 판정을 낸다.**
`OPS-22` 감사기는 버그가 없다 — `reached`의 **정의가 두 가지를 한 칸에 담을 뿐**이다:

| 도달의 종류 | 감사기 판정 | 실제 의미 |
|---|---|---|
| 백엔드 테스트가 라우트를 호출 | `reached` | **코드가 죽지 않았다** |
| dart 클라가 라우트를 호출 | `reached` | **학생이 볼 수 있다** |

**이 둘은 다른 사실인데 같은 초록불을 켠다.** 그리고 그 초록불 위에서 태스크가 닫혔다 —
`PED-15`가 `layer: mobile`인 채 backend 테스트만 남기고 done이 된 것이 실사례다. 기록은
정직했지만(artifacts가 "도달 증명이지 학생 화면 배선이 아니다"라고 명시), **정직한 기록은
소유자를 만들지 않는다.**

**재발방지 형태로 남길 원칙**:

> **"도달"은 누가 도달했는지를 말해야 한다.**
> 학생 대면 표면의 도달 측정에 **테스트 호출을 학생 도달과 같은 칸에 담지 않는다.**
> 그리고 태스크의 `layer`가 `mobile`인데 산출물이 backend뿐이면, 그것은 완료가 아니라
> **레이어 불일치**다 — 남은 일의 소유자가 사라지는 지점이 정확히 거기다.

이 원칙의 **1차 집행은 산문이 아니라 코드**다(`OPS-34` = D9). CLAUDE.md는 이미 두 번
"규칙 산문 2회 실패 후 코드 착지"를 겪었으므로(PB-02 그랜드파더 만료 계약 선례), 이번엔
처음부터 코드로 간다. **이 커밋에서 CLAUDE.md를 고치지 않는다** — 헌법 개정은 별도 판단이며,
`OPS-34`가 착지한 뒤 그 게이트를 근거로 등재하는 편이 순서가 맞다.

**부수 관찰(태스크 신설 없음)**: §4의 판정 기준 미끄러짐(같은 표 안에서 "존재하는가"와
"입력되는가"가 섞임)은 문서 작성 규율 축의 문제이고, 이 문서 범위에서 확인된 사례는 **1건뿐**이다.
**패턴이 아니라 단발**이므로 "판정 기준 감사" 같은 태스크를 열지 않는다 — §4의 기록으로 족하다.
