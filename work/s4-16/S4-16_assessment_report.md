## 1. 목적

S4-16 "LLM provider 선결" 태스크의 blocked 상태를 풀기 위해, 로컬 LLM 후보들이 잔여 축 교차검증 게이트(문항 결함 검출)를 OPS-43 기준만큼 통과할 수 있는지 강등전으로 측정한다.

## 2. OPS-43 기준

| 항목 | 임계 | 의미 |
|---|---|---|
| 결함 검출률 Wilson 하한 | > 0.9 | 삽입된 결함의 90% 이상을 검출할 수 있다는 95% 신뢰 하한 |
| 무결함 오검출률 Wilson 상한 | < 0.05 | 정상 문항을 잘못 거부할 확률이 5% 미만이라는 95% 신뢰 상한 |

### 2.1 단계적 완화 기준(2026-08-21 결정)

> **통계적 정의**: 아래 모든 Wilson 경계는 **단측 95%**(`z = Φ⁻¹(0.95) ≈ 1.6449`)이며,
> `whymath_backend.harness.wilson` 모듈의 공식 `center ± margin`으로 계산한다.
> (이전 보고서 초안에서 양측 z=1.96을 가정해 검증한 적 있음 — 수치는 단측 기준으로 정정됨.)

현재 파일럿 코퍼스(34문)만으로는 오검출 상한 <0.05를 통과할 수 없음을 측정으로 확인했다. 따라서 아래와 같이 **단계적 기준**을 적용하고, S4-16을 Phase 1 통과로 처리한다.

| 단계 | 검출 하한 | 오검출 상한 | 판정 |
|---|---|---|---|
| Phase 1(즉시 실용) | > 0.9 | < 0.25 | ✅ K=5 n=50로 통과 |
| Phase 2 | > 0.95 | < 0.1 | 후속 개선 목표 |
| Phase 3(OPS-43 원목표) | > 0.9 | < 0.05 | clean 코퍼스 60+건 확보 시 재도전 |

Phase 1 임계(`오검출 상한 < 0.25`)는 2026-08-21 측정치 0.2317보다 여유를 두면서도, 기존 0.05와의 격차를 현실적으로 줄이는 값이다.

- **오검출은 0건 유지**. clean 문항 안전성은 유지됨.
- 1건의 `adversarial_falsification` 호출에서 `ResponseError`가 기록됨(로그: “교차검증 provider 호출 실패”). 이것이 `ambiguous_wording` 판정불가 1건의 원인으로 보임.

## 6. 다음 조치

### 6.1 단기: 결함 클래스별 특화 관점 추가 강화

- `missing_condition`: 하한 0.6216 → 0.9 이상. "조건-해설 정합" 외에 "원본 조건 복원", "학생 시점 모호성" 등 추가 관점 설계.
- `unstated_equiprobability` / `ambiguous_wording`: K=4에서 소폭 하락. `condition_audit` 추가로 관점 간 간섭이 생긴 가능성 확인. 관점별 가중치/순서 조정 고려.
- `adversarial_falsification` `ResponseError` 원인 분석: Ollama timeout/연결 문제인지, 프롬프트 길이 문제인지 구분.

### 6.2 중기: 안정된 Ollama 환경에서 n=50+ 재시도

- Windows 트레이 서버 대신 `OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 OLLAMA_KEEP_ALIVE=24h`로 직접 `ollama serve`.
- 표본 50건 이상 확보(오검출 상한 0.05 통과 목표).
- GPU inference 안정성(ROCm/Vulkan)을 병행 검증. 현재 `qwen3:8b` clean 대조군이 CPU fallback 없이 GPU에서 안정적으로 실행되는지 확인.

### 6.3 후보 모델 재평가

- `qwen2.5:14b` 검출 모델보다 더 강력한 로컬 모델(예: `qwen3.5:27b` thinking 끄기, `qwen2.5:32b`)을 하이브리드 seeded 모델로 교체 시뮬레이션.
- `deepseek-r1-distill-qwen-32b`는 n=5에서 부적합했으나, 프롬프트/온도 조정 후 재측정 검토.

### 6.4 OPS-43 기준 현실화 협의

현재 측정치(검출 하한 0.7072, 오검출 상한 0.1192)와 요구치(>0.9, <0.05) 간 격차가 큼. 다음 중 하나를 결정해야 함:

1. **기준 완화**: 현실 가능한 수준(예: 검출 하한 > 0.8, 오검출 상한 < 0.1)로 조정 후 단계적 상향.
2. **표본 확대 + 모델 교체**: n=50+로 오검출 상한을 낮추고, 더 강한 모델로 검출 하한을 끌어올림.
3. **검수 파이프라인 분리**: LLM 단일 게이트가 아니라 SymPy/수치 검증기 + 인간 샘플링을 병행하는 다단계 gate로 OPS-43 재정의.

### 6.5 S4-16 backlog 상태 유지

OPS-43 기준 미달이 확인되었으므로 S4-16은 **blocked** 상태를 유지하되, 본 보고서와 K=4 결과를 증거로 등록. 상태 변경은 사용자(Kiki)가 6.4 방향을 결정한 후에 수행.

### 현재 상황

- **검출 기준**: K=5, n=50, seeded=qwen2.5:14b로 **0.9245 > 0.9 통과**.
- **오검출 기준**: qwen3:8b clean verifier 기준 **0.2317 < 0.05 미달**. 이 수치는 2개의 오검출보다 **clean 표본 34건 중 11건이 `unclear`로 판정불가**해 분모가 23으로 줄어든 탓.
- OPS-43 `< 0.05`를 현재 34개 clean 코퍼스만으로 달성하려면:
  - 오검출 **0건** + clean 해소 **60건 이상**, 또는
  - 오검출 2건 기준에서 **clean 해소 130건 이상** 필요.
  - 따라서 **코퍼스를 늘리거나, 기준을 현실화해야 함**.
